## 1. 내 오답 패턴 4가지

### 패턴 ① 생성자 인자 순서 — 9문항

[06-03] [06-17] [07-17] [07-18] [07-20] [08-15] [08-16] [09-20] [10-03]

**Form마다 첫 번째 인자가 다르다.** 이 표 하나로 정리된다.

| Form | 종류 | 첫 번째 인자 | POST 처리 코드 | save() |
|---|---|---|---|---|
| `ArticleForm` | ModelForm | `data` | `ArticleForm(request.POST, request.FILES, instance=article)` | ✅ |
| `UserCreationForm` | ModelForm | `data` | `CustomUserCreationForm(request.POST)` | ✅ (새 User) |
| `UserChangeForm` | ModelForm | `data` | `CustomUserChangeForm(request.POST, instance=request.user)` | ✅ (기존 User 수정) |
| `AuthenticationForm` | **Form** | **`request`** | `AuthenticationForm(request, request.POST)` | ❌ 없음 |
| `PasswordChangeForm` | **Form** | **`user`** | `PasswordChangeForm(request.user, request.POST)` | ✅ (비밀번호 변경) |

- ModelForm 생성자: `__init__(self, data=None, files=None, ..., instance=None)` → 위치 인자 순서는 **data → files**, `instance`는 **키워드**로 넘긴다.
- `AuthenticationForm`만 `request`가 맨 앞이다. 헷갈리면 `AuthenticationForm(request, data=request.POST)`처럼 키워드로 쓴다.

### 패턴 ② "save()가 빠지면?" — 6문항

[04-12] [05-18] [06-14] [06-15] [06-17] [09-11]

| 상황 | 결과 |
|---|---|
| `article.title = 'x'` 만 하고 save() 없음 | 메모리 속 객체만 바뀜, **DB는 그대로** |
| `form.save(commit=False)` | DB에 **저장 안 한** 인스턴스 반환 → 값 채우고 `article.save()` |
| `ArticleForm(request.POST)`로 수정 (instance 빠짐) | 기존 글 그대로, **새 글이 생김** (INSERT) |
| 회원가입 `form.save()` | User를 만들 뿐, **로그인은 안 됨** → `auth_login(request, user)` 따로 |

> 📌 save()는 **pk(또는 instance)가 있으면 UPDATE, 없으면 INSERT**. 저장은 언제나 명시적으로 해야 일어난다.

### 패턴 ③ 이름이 비슷한 가짜 보기에 낚였다 — 12문항

| 문항 | ✅ 진짜 | ❌ 내가 고른 가짜 |
|---|---|---|
| [02-04] | `TEMPLATES`의 `'DIRS'` | `TEMPLATE_PATH` (없는 설정) |
| [02-08] | `name` 속성 | `id` 속성 |
| [02-12] | `<int:num>` | `<num:int>` (순서 반대) |
| [04-12] | `article.save()` | `Article.objects.save(article)` (없는 메서드) |
| [04-15] | `title__icontains` | `title=` (정확히 일치) |
| [06-02] | `widget=forms.Textarea` | `field=forms.TextField` (TextField는 **models**에 있음) |
| [07-05] | `{% load static %}` | `{% import static %}` |
| [07-13] | `static(settings.MEDIA_URL, ...)` | `static(settings.STATIC_URL, ...)` |
| [09-04] | `@require_POST` | `@login_required` |
| [10-09] | `update_session_auth_hash` | `update_session_auth_user` (없는 함수) |
| [10-15] | Salt | Key Stretching |
| [10-20] | `EMAIL_BACKEND` | `EMAIL_HOST` |

### 패턴 ④ 보안 기능이 막는 범위를 넓게 잡았다 — 9문항

[05-04] [05-10] [08-04] [10-12] [10-13] [10-15] [10-16] [10-18] [10-19]

| 기능 | 하는 일 | **하지 않는 일** |
|---|---|---|
| POST | 데이터를 Body에 담아 주소창에 안 보이게 | 암호화 ❌ (HTTPS 몫) |

| HttpOnly | JavaScript의 쿠키 읽기 차단 | 요청에 쿠키가 실리는 것 차단 ❌ |
| Salt | 레인보우 테이블 무력화 | 무차별 대입 방어 ❌ (Key Stretching 몫) |
| Base64 | 인코딩 (규칙만 알면 복원) | 비밀번호 보호 ❌ |

## 2. 단원별 개념 정리

### 01 · Intro & Design Pattern (오답 3)

#### 앱 등록 — 생성 → 등록 `[01-16]`

- `startapp`은 앱 폴더와 파일을 **만들기만** 한다. Django가 앱을 인식하게 하려면 `settings.py`의 `INSTALLED_APPS`에 직접 추가한다.
- 순서는 **생성 → 등록**. 등록을 먼저 하면 아직 없는 앱이라 에러가 난다.
- ❌ urls.py에 `import articles` → 앱 인식은 URL이 아니라 **settings**가 맡는다.

#### render()와 템플릿 경로 `[01-19]`

```python
def index(request):
    return render(request, 'articles/index.html')
```

- Django는 **`app폴더/templates/`까지**를 기본 탐색 경로로 보고, 그 뒤 경로만 적는다 → 실제 파일은 `articles/templates/articles/index.html`.
- `render()`는 **HttpResponse 객체**를 반환한다 (❌ HTML 문자열이 아님).
- view 함수의 첫 인자 `request`는 생략할 수 없다.

#### 후행 쉼표 권장 패턴 `[01-20]`

```python
INSTALLED_APPS = [
    'articles',
    'django.contrib.admin',   # ← 마지막 요소에도 쉼표
]                             # ← 닫는 괄호는 다음 줄
```

- 권장하는 것은 **값마다 줄을 나누는 것**. `['a', 'b',]`처럼 한 줄에 몰아 쓰는 건 권장하지 않는다.
- `(1,)`처럼 요소가 하나인 튜플엔 쉼표가 필수라는 말은 **맞다**.

### 02 · Template & URLs (오답 7)

#### 추가 템플릿 경로는 `TEMPLATES` → `DIRS` `[02-04]`

```python
TEMPLATES = [
    {
        ...
        'DIRS': [BASE_DIR / 'templates'],
        ...
    },
]
```

- `STATICFILES_DIRS` = **정적 파일** 추가 경로 (7단원), `TEMPLATE_PATH` = 없는 설정.

#### 서버가 값을 찾는 key는 `name` `[02-08]`

```html
<input type="text" name="message" id="message">
```

- 서버: `request.GET.get('message')` ← **name** 값으로 꺼낸다.
- `id`는 `<label for="...">` 연결·CSS·JS용 HTML 식별자일 뿐, 서버로 가지 않는다.

#### `.get()` vs `['key']` — 키가 없을 때 `[02-11]`

| 코드 | 키가 없으면 |
|---|---|
| `request.GET.get('message')` | `None` (기본값) |
| `request.GET['message']` | **MultiValueDictKeyError** (예외) |

- 파이썬 딕셔너리와 똑같다. ❌ 반대로 기억했다.

#### path converter — `<변환기:변수명>` `[02-12]` `[02-14]`

```python
path('articles/<int:num>/', views.detail)   # 변환기가 앞, 변수명이 뒤
```

- 기본 제공 5가지: **str, int, slug, uuid, path**. ❌ **float는 없다.**
- `{num}`, `:num` 같은 다른 프레임워크 문법은 Django에서 쓰지 않는다.

#### include는 앞부분을 잘라서 넘긴다 `[02-16]`

```python
# 프로젝트 urls.py
path('articles/', include('articles.urls'))
# articles/urls.py
path('', views.index)   # → /articles/
```

- include가 `articles/`를 잘라 낸 뒤 남은 빈 문자열이 `''`와 매칭 → `''`는 **`/articles/` 그 자체**. ❌ `/articles/articles/` 아님.

#### `{% url %}` 태그 문법 `[02-19]`

```django
{% url 'detail' 1 %}
{% url 'articles:detail' article.pk %}   {# app_name 사용 시 #}
```

- url은 **태그** → `{% %}` (❌ `{{ }}`).
- URL 이름 다음 인자는 **띄어쓰기**로 구분, 쉼표 ❌. URL 이름을 빼면 안 된다.

### 04 · ORM (오답 6)

#### 저장 전 인스턴스의 pk는 `None` `[04-07]`

```python
article = Article()
article.pk        # None
article           # <Article: Article object (None)>
article.save()
article.pk        # 1
```

- pk 속성 자체는 있다 → ❌ AttributeError 아님. **값이 None**일 뿐이고 save() 후에 배정된다.

#### 수정 = 조회 → 변경 → save() `[04-12]`

```python
article = Article.objects.get(pk=1)
article.title = 'byebye'
article.save()
```

- save()는 **인스턴스 메서드**. `Article.objects.save()`나 `article.update()`는 없다 (`QuerySet.update()`는 별개).

#### delete()의 반환값 `[04-13]`

```python
article.delete()   # (1, {'articles.Article': 1})
```

- **(삭제된 총 개수, 모델별 삭제 개수 딕셔너리)** 튜플.

#### Field lookup — `필드명__조건` (언더스코어 **2개**) `[04-15]` `[04-17]`

| lookup | 의미 |
|---|---|
| `title__contains='django'` | 포함 (대소문자 **구분**) |
| `title__icontains='django'` | 포함 (대소문자 **무시**, i = case-insensitive) |
| `pk__gt=10` / `pk__gte=10` | > 10 / **>= 10** (e = equal) |
| `pk__lt=10` / `pk__lte=10` | < 10 / <= 10 |

- `title_icontains`(언더스코어 1개)는 잘못된 문법, `title='django'`는 정확히 일치.

#### Django shell은 실제 DB에 반영된다 `[04-19]`

- shell은 Django 환경에서 실행 → 만든 데이터는 **종료해도 남는다**.
- `shell -v 2` = 자동 import된 모델 목록 출력 (SQL 출력 아님).
- IPython은 편의 도구일 뿐 필수가 아니다.

### 05 · ORM with View (오답 6)

#### CRUD view 짝 `[05-03]`

| 기능 | 페이지 보여주기 (GET) | 처리 (POST) |
|---|---|---|
| Create | `new` — 입력 페이지 | `create` — DB 저장 |
| Update | `edit` — 수정 페이지 | `update` — DB 수정 |

- ❌ new/create 역할을 반대로 골랐다. **new = 페이지, create = 저장.**

#### GET vs POST — POST는 암호화가 아니다 `[05-04]`

| | GET | POST |
|---|---|---|
| 용도 | 조회 | 생성·수정·삭제 |
| 데이터 위치 | URL 쿼리 스트링 | HTTP Body |
| 암호화 | ❌ | ❌ (주소창에 안 보일 뿐) |

- 전송 중 보호는 **HTTPS**의 역할.

#### CSRF 토큰 `[05-10]`

```html
<form action="..." method="POST">
  {% csrf_token %}   <!-- → <input type="hidden" name="csrfmiddlewaretoken" value="..."> -->
</form>
```

- 역할: 요청이 **Django가 제공한 페이지에서 왔는지 확인**. 데이터 **암호화 기능은 없다.**

#### 글 작성 후 Network 탭: 302 → 200 `[05-14]`

```text
[POST] /articles/create/   → 302 (redirect)
[GET]  /articles/3/        → 200 (새 글 상세)
```

- create는 저장 후 render가 아니라 **redirect** → 새로고침해도 POST가 재전송되지 않는다.

#### textarea는 태그 사이에 값 `[05-17]`

```html
<input type="text" name="title" value="{{ article.title }}">
<textarea name="content">{{ article.content }}</textarea>
```

- textarea에는 `value` 속성이 없다. `placeholder`는 회색 안내문일 뿐 제출되지 않는다.

#### save() 빠진 update view `[05-18]`

- 대입만 하고 redirect → DB의 제목은 **기존 그대로** (패턴 ②).

### 06 · Django Form (오답 14) ★ 최우선

#### Form vs ModelForm `[06-01]`

| | `forms.Form` | `forms.ModelForm` |
|---|---|---|
| 모델 연결 | ❌ | `class Meta: model = Article` |
| input 렌더링 | ✅ | ✅ |
| 유효성 검사·에러 메시지 | ✅ | ✅ |
| **save() (DB 저장)** | **❌ 없음** | ✅ |

#### widget = 겉모습만 바꾼다 `[06-02]`

```python
class ArticleForm(forms.Form):
    title = forms.CharField(max_length=10)
    content = forms.CharField(widget=forms.Textarea)
```

- `widget`은 HTML에서 어떤 입력 요소로 그릴지 정한다. **검증 규칙은 그대로.**
- `forms.TextField`는 없다 → `TextField`는 **models** 쪽 필드.
- HTML 속성은 위젯의 `attrs`로: `forms.TextInput(attrs={'class': 'my-title', 'placeholder': '제목'})`

#### unbound form vs bound form `[06-03]`

| 코드 | 상태 | 언제 |
|---|---|---|
| `ArticleForm()` | **unbound** (데이터 없음) | GET — 빈 입력 양식 보여줄 때 |
| `ArticleForm(request.POST)` | **bound** (데이터 있음) | POST — 검증·저장할 때 |

- new view는 GET 요청이라 보낼 데이터가 없다 → 빈 폼을 context로 넘긴다.

#### `{{ form }}`이 그려 주는 것 / 직접 써야 하는 것 `[06-04]`

```html
<form action="{% url 'articles:create' %}" method="POST">   <!-- 직접 -->
  {% csrf_token %}                                            <!-- 직접 -->
  {{ form }}                    <!-- label, input(name·id·required·maxlength), 에러, help text -->
  <input type="submit">                                       <!-- 직접 -->
</form>
```

- **form 태그, csrf_token, 제출 버튼**은 Form이 만들어 주지 않는다.

#### Form만 적용했는데 create가 동작한 이유 `[06-05]`

- Form이 만든 input의 `name`이 **필드 이름**(title, content) = 기존 view가 `request.POST.get('title')`로 꺼내던 키와 같다.
- 이 단계의 Form은 "HTML을 대신 써 주는 것"뿐. 서버 검증은 `is_valid()`를 써야 시작된다.

#### ModelForm이 렌더링하는 필드 `[06-09]`

```python
class ArticleForm(forms.ModelForm):
    class Meta:
        model = Article
        exclude = ('title',)   # 또는 fields = ('title', 'content')
```

- `auto_now`, `auto_now_add`, `id`는 **editable=False** → 처음부터 폼 대상이 아니다.
- title 제외 → **content만** 남는다.

#### is_valid()와 실패 처리 `[06-11]` `[06-12]`

- `is_valid()` → True/False 반환. 통과 → `form.cleaned_data`, 실패 → `form.errors`에 필드별 에러.
- **실패하면 저장하지 않는다.**
- 실패 시 에러가 담긴 **기존 form 객체를 그대로 render**. ❌ `ArticleForm()`을 새로 만들면 입력값과 에러가 모두 사라진다.

#### 공백만 입력하면? — 2단 검사 `[06-13]`

| 입력 | 브라우저 `required` | Django |
|---|---|---|
| 아예 빈칸 | **막음** (제출 안 됨) | — |
| 스페이스만 | 통과 (빈 값이 아니라서) | 앞뒤 공백 제거(`strip=True` 기본) → 빈 값 → **"필수 항목" 에러** |

- 브라우저 검사는 편의 기능이고, 진짜 방어는 서버 검증이다.

#### `save(commit=False)` `[06-14]` `[06-15]`

```python
if form.is_valid():
    article = form.save(commit=False)   # DB 저장 X, 인스턴스만 반환
    article.user = request.user         # 폼에 없는 필드를 코드로 채움
    article.save()                      # 이제 저장
```

- 반환값은 **저장 안 된 모델 인스턴스** (❌ None 아님).
- 유효성 검사를 건너뛰는 기능이 아니다 → is_valid() **통과 후**에 쓴다.

#### instance = 수정 대상 지정 `[06-17]`

```python
form = ArticleForm(instance=article)                 # GET: 기존 값 채운 폼
form = ArticleForm(request.POST, instance=article)   # POST: 기존 글 UPDATE
```

- POST에서 `instance`를 빠뜨리면 → **새 글이 생긴다** (INSERT). ❌ 기존 글 삭제·IntegrityError 아님.

#### 통합 create view의 3가지 경로 `[06-19]`

```python
def create(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST)
        if form.is_valid():
            article = form.save()
            return redirect('articles:detail', article.pk)   # ① POST 성공 → 여기서 끝
    else:
        form = ArticleForm()                                  # ② GET → 빈 폼
    context = {'form': form}                                  # ②와 ③이 함께 도착
    return render(request, 'articles/create.html', context)
```

| 요청 | 흐름 | 결과 |
|---|---|---|
| GET | else → 빈 폼 | render |
| POST 성공 | save → redirect | 상세 페이지 |
| POST 실패 | if 통과 못 함 → 아래로 | **에러 담긴 폼 render** |

- 마지막 context·render는 if/else **바깥** → **GET + 검증 실패한 POST** 공용. ❌ "GET일 때만"이 틀린 말.

#### Form 렌더링 옵션 `[06-20]`

| 코드 | 출력 |
|---|---|
| `{{ form.as_p }}` | 각 필드를 `<p>`로 감쌈 |
| `{{ form.as_ul }}` | `<li>`만 (`<ul>`은 직접) |
| `{{ form.as_table }}` | `<tr>`만 (`<table>`은 직접) |
| `{{ form.title }}` | title 필드의 input |
| `{{ form.title.errors }}` | title 필드의 **에러 메시지** |

#### 정적 파일 기본 경로 = `app폴더/static/` `[07-04]`

- 템플릿(`app/templates/`)과 같은 구조 → static 태그에는 **그 뒤 경로만** 적는다.
- 추가 경로는 `STATICFILES_DIRS`. `staticfiles/`는 배포 때 `collectstatic`으로 모으는 폴더(STATIC_ROOT)에 흔히 쓰는 이름이지 기본 탐색 경로가 아니다.

#### `{% load static %}` `[07-05]`

- static은 built-in 태그가 아니다 → 쓰기 전에 **load**로 불러온다. ❌ `import`, `include`, `extends`가 아니다.

#### static 태그는 "웹 주소"를 만든다 `[07-07]`

```django
{% load static %}
<img src="{% static 'images/sample-1.png' %}">
{# → /static/images/sample-1.png  (STATIC_URL + 경로) #}
```

- ❌ `C:/project/...` 같은 실제 파일 경로가 나오지 않는다.

#### URL(웹 주소) vs 실제 폴더 경로 `[07-13]` `[07-14]`

| | 웹 주소 | 실제 폴더 |
|---|---|---|
| Static | `STATIC_URL` | `STATICFILES_DIRS` |
| Media | `MEDIA_URL` | `MEDIA_ROOT` |

```python
# 프로젝트 urls.py
urlpatterns = [
    ...
] + static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
#          ↑ 웹 주소                       ↑ 실제 폴더
```

- 이 설정은 **DEBUG=True(개발 서버)에서만** 동작한다. 운영에서는 웹 서버나 S3가 미디어 파일을 제공한다 → "운영에서도 권장"이 틀린 말.

#### 이미지 업로드 3종 세트 `[07-16]` `[07-17]` `[07-18]` `[07-20]`

```python
# models.py
image = models.ImageField(blank=True)   # Pillow 설치 필요
```

```html
<!-- create.html / update.html 둘 다 -->
<form action="..." method="POST" enctype="multipart/form-data">
```

```python
# views.py
form = ArticleForm(request.POST, request.FILES)                    # 생성
form = ArticleForm(request.POST, request.FILES, instance=article)  # 수정
```

- `enctype="multipart/form-data"` 없으면 파일이 전송되지 않는다. ❌ `application/json`.
- 일반 입력값은 `request.POST`, 업로드 파일은 **`request.FILES`**.
- 두 번째 위치 인자인 이유: ModelForm 생성자가 `__init__(self, data=None, files=None, ...)` → **2번째 자리가 files**. `instance`는 키워드로 넘긴다.
- 수정할 때도 `request.FILES`와 `instance` **둘 다** 필요하다.

### 08 · Auth 01 · 쿠키·세션·로그인 (오답 9)

#### 쿠키 보안 속성 `[08-04]`

|---|---|
| Secure | HTTPS 연결에서만 전송 |

#### Custom User는 "나중에 확장하려고" 처음에 만든다 `[08-09]`

- 기본 User는 필드가 정해져 있어 확장이 어렵다 → 프로젝트 **초기(첫 migrate 전)**에 내 User로 갈아 끼운다 (`AUTH_USER_MODEL = 'accounts.User'`).
- ❌ 비밀번호 해싱이나 migrate가 필요 없어지는 것이 아니다.

#### 세션·User 관점의 CRUD `[08-13]` `[09-01]`

| 기능 | 관점 |
|---|---|
| 로그인 | **세션 Create** |
| 로그아웃 | **세션 Delete** |
| 회원가입 | User Create |
| 회원정보 수정 / 비밀번호 변경 | User Update |
| 회원 탈퇴 | User Delete |

#### AuthenticationForm `[08-14]` `[08-15]` `[08-16]`

- **Form**이다 (ModelForm ❌) → 이미 있는 유저를 확인할 뿐이라 **save()가 없다.** 세션은 `auth_login()`이 만든다.
- 생성자: `__init__(self, request=None, *args, **kwargs)` → **첫 인자 request, 그다음 data.**

```python
form = AuthenticationForm(request, request.POST)        # ✅
form = AuthenticationForm(request, data=request.POST)   # ✅ 가장 안전
form = AuthenticationForm(request.POST)                 # ❌ 조용히 실패
```

- 잘못 쓰면 `request.POST`가 request 자리로 들어가고 data는 비어 **unbound form** → `is_valid()`가 항상 False. **에러 메시지도 500 에러도 없이** 로그인만 안 돼서 찾기 어렵다.

#### 로그인 view `[08-17]`

```python
if form.is_valid():
    auth_login(request, form.get_user())
    return redirect('articles:index')
```

- `form.get_user()` = 검증을 통과한 유저 객체. ❌ `request.user`는 아직 로그인 전이라 AnonymousUser다.

#### 템플릿의 `{{ user }}`는 context processor가 넣는다 `[08-19]`

- `settings.py` → `TEMPLATES` → `context_processors`에 `django.contrib.auth.context_processors.auth`가 기본 포함 → **모든 템플릿**에 `user`가 들어간다.
- ❌ `AUTH_USER_MODEL`은 어떤 모델을 User로 쓸지 정하는 설정이다.

#### 비로그인 `request.user` = AnonymousUser `[08-20]`

- ❌ None이 아니다. `is_authenticated`는 False, `username`은 빈 값 → `Hello, {{ user.username }}`이 `Hello,`로만 보인다.

### 09 · Auth 02 · 로그아웃·회원가입·접근 제한 (오답 7)

#### 로그아웃 = 세션 Delete `[09-01]`

- 위 [세션·User 관점의 CRUD](#세션user-관점의-crud-08-13-09-01) 표 참고. User 객체 Delete는 **회원 탈퇴**다.

#### 데코레이터 구분 `[09-04]`

| 데코레이터 | import | 하는 일 |
|---|---|---|
| `@require_POST` | `django.views.decorators.http` | POST만 허용, GET이면 **405** |
| `@login_required` | `django.contrib.auth.decorators` | 비로그인 사용자를 **로그인 페이지로** redirect |

- logout view를 POST로만 받게 하는 건 **require_POST**. `@post_only`는 없는 데코레이터.

#### `class Meta(UserCreationForm.Meta)` `[09-10]`

```python
class CustomUserCreationForm(UserCreationForm):
    class Meta(UserCreationForm.Meta):   # 부모 Meta 상속
        model = get_user_model()         # model만 교체
```

- 부모의 **fields 설정은 그대로 두고 model만** 바꾸기 위해서. `class Meta:`로만 쓰면 부모 설정이 사라진다.

#### 회원가입 후 자동 로그인 `[09-11]`

```python
if form.is_valid():
    user = form.save()          # User 생성만
    auth_login(request, user)   # 로그인은 따로
    return redirect('articles:index')
```

#### 회원 탈퇴 `[09-12]`

```python
@require_POST
def delete(request):
    request.user.delete()   # 1. 탈퇴
    auth_logout(request)    # 2. 세션 정리
    return redirect('articles:index')
```

- `request.user` = 지금 요청한 로그인 사용자 → 대상이 항상 "나"라서 URL에 pk가 필요 없다.
- 로그아웃을 먼저 하면 `request.user`가 AnonymousUser가 되어 지울 대상을 잃는다.

#### `is_authenticated`는 속성 `[09-15]`

```python
request.user.is_authenticated     # ✅ 괄호 없음
request.user.is_authenticated()   # ❌
```

- User → True, AnonymousUser → False. 데코레이터는 `login_required`.

#### AuthenticationForm vs UserCreationForm `[09-20]`

- [1. 내 오답 패턴](#1-내-오답-패턴-4가지)의 패턴 ① 생성자 표 참고. **AuthenticationForm에는 save()가 없다** → "두 폼 모두 save()로 저장"이 틀린 말.

### 10 · Auth 03 · 회원정보·비밀번호·해시 (오답 12)

#### CustomUserChangeForm은 fields를 제한한다 `[10-02]`

```python
class CustomUserChangeForm(UserChangeForm):
    class Meta(UserChangeForm.Meta):
        model = get_user_model()
        fields = ('first_name', 'last_name', 'email')
```

- 제한하지 않으면 **is_superuser 같은 관리자용 필드까지** 사용자에게 노출된다.

#### 회원정보 수정 폼 생성 `[10-03]` `[10-04]`

```python
form = CustomUserChangeForm(instance=request.user)                 # GET
form = CustomUserChangeForm(request.POST, instance=request.user)   # POST
```

- ModelForm이라 첫 인자는 **data**. ❌ `(request, request.POST)`는 AuthenticationForm 방식이다.
- `instance=request.user`의 역할: GET에서 기존 정보 채우기 / POST에서 기존 User 수정 / 대상을 현재 사용자로 고정.
- ❌ 유효성 검사를 생략시키지 않는다 → is_valid()와 save()는 그대로 거친다.

#### PasswordChangeForm `[10-06]`

```python
form = PasswordChangeForm(request.user, request.POST)   # 첫 인자 user
```

- SetPasswordForm을 상속하고 **기존 비밀번호 확인(old_password)**을 추가한 **Form** (ModelForm ❌).
- 기존 비밀번호를 모르면 바꿀 수 없다.

#### update_session_auth_hash — 비밀번호 변경 후 로그인 유지 `[10-09]`

```python
if form.is_valid():
    user = form.save()
    update_session_auth_hash(request, user)
    return redirect('articles:index')
```

- 비밀번호가 바뀌면 세션의 인증 해시가 맞지 않아 **로그아웃된다** → 새 비밀번호 기준으로 갱신.
- 이름은 **session · auth · hash**. ❌ `update_session_auth_user`는 없다.

#### 인코딩 · 암호화 · 해싱 `[10-12]`

| | 예시 | 키 | 원래대로 복원 |
|---|---|---|---|
| 인코딩 | UTF-8, **Base64** | ❌ | 규칙만 알면 누구나 |
| 암호화 | AES | ✅ | 올바른 키로 복호화 |
| 해싱 | SHA-256 | ❌ | **원칙적으로 불가** (일방향) |

#### 암호학적 해시 함수의 성질 `[10-13]`

1. **결정성** — 같은 입력 → 항상 같은 출력
2. **일방향성** — 해시값으로 원래 입력을 알아내기 어렵다
3. **눈사태 효과** — 입력이 조금만 달라도 출력이 크게 달라진다
4. **고정 길이** — 입력 길이와 상관없이 출력 길이가 같다

#### Salt vs Key Stretching `[10-15]` `[10-16]`

| | Salt | Key Stretching |
|---|---|---|
| 막는 공격 | **레인보우 테이블** (미리 계산한 해시표) | **무차별 대입** |
| 방법 | 사용자마다 다른 랜덤 값을 붙여 해시 | 해시 연산을 수천~수십만 번 반복 |
| 효과 | 같은 비밀번호도 해시가 달라진다 | 후보 하나 검사하는 비용 증가 |
| 비밀인가? | ❌ 해시와 함께 DB에 저장 | — |

#### Django 기본 해셔 PBKDF2와 저장 형식 `[10-18]` `[10-19]`

```text
pbkdf2_sha256 $ <iterations> $ <salt> $ <hash>
   알고리즘    $   반복 횟수   $  솔트   $ 해시값
```

- PBKDF2 + SHA-256 → **Salt + Key Stretching을 모두** 적용한다.
- 구성 요소 4개: algorithm, iterations, salt, hash. **username은 없다.**
- ❌ Base64는 인코딩이라 비밀번호 보호와 무관하다.

#### 비밀번호 초기화 메일을 콘솔로 `[10-20]`

```python
EMAIL_BACKEND = 'django.core.mail.backends.console.EmailBackend'
```

- 메일 내용이 runserver 터미널에 출력된다.
- `EMAIL_HOST` = 실제 SMTP 서버 주소, `AUTH_PASSWORD_VALIDATORS` = 비밀번호 품질 검사 설정.

| 14 | 공백만 입력하면 브라우저 required가 막는다. | X — Django가 막음 |

| 28 | `is_authenticated`는 메서드라 괄호를 붙인다. | X — 속성 |

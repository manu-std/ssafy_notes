## 1. 워드 임베딩

### 1-1. 원-핫 인코딩 (One-hot Encoding)

- 규칙 기반 혹은 통계적 자연어 처리 연구의 대다수는 **단어를 원자적 기호(atomic symbol)**로 취급
- 벡터 공간 관점: 한 원소만 1이고 나머지는 모두 0인 벡터로 단어의 의미를 표현
- 벡터의 차원 수 = 전체 단어 수
- 이렇게 만든 표현을 **원-핫 표현(one-hot representation)**, 단어를 원-핫 표현으로 바꾸는 과정을 **원-핫 인코딩**이라고 부름

**근본적인 문제점**

- 예: 웹 검색 시 "삼성 노트북 배터리 사이즈"와 "삼성 랩탑 배터리 용량"은 사실상 같은 의미이지만, 원-핫 인코딩에서는 단어 벡터들이 서로 **직교(orthogonal)**하게 되어 유사도를 전혀 측정할 수 없음

**공식적인 문제 두 가지**

1. **차원의 저주(Curse of Dimensionality)**
   - 고차원 희소벡터(sparse vector)를 다루려면 많은 메모리가 필요
   - 차원이 커질수록 데이터가 점점 희소해져서(대부분이 0) 활용하기 어려움
   - 심지어 유클리디안 거리가 (거의) 모두 동일해짐

2. **의미적 정보 부족**
   - 비슷한 단어라도 유사한 벡터로 표현되지 않음
   - 비슷한 단어가 서로 무관한 벡터로 표현됨

### 1-2. 워드 임베딩 (Word Embedding)

- 단어를 **주변 단어들**로 표현하면, 훨씬 많은 의미를 담을 수 있음
- 현대 통계적 자연어 처리에서 **가장 성공적인 아이디어** 중 하나
- 핵심 직관: **"주변 단어들로 그 단어의 의미를 나타낼 수 있다"**
- 정의: 단어를, 단어들 사이의 **의미적 관계를 포착할 수 있는, 밀집되고(dense) 연속적인(continuous) 분산 벡터 표현(distributed vector representation)**으로 나타내는 방법

**원-핫 인코딩 vs 워드 임베딩**

| 구분 | 원-핫 인코딩 | 워드 임베딩 |
|------|--------------|--------------|
| "은행"과 "금융" | 완전히 독립적인(직교하는) 벡터 | 공간상 서로 가깝고, 비슷한 방향을 가리키는 벡터 → **의미적 유사성을 반영** |
| 벡터 형태 | 희소(sparse), 고차원 | 밀집(dense), 저차원 |

### 1-3. Word2Vec — Skip-gram과 CBOW

- **구글에서 개발한** 대표적인 워드 임베딩 기법
- 핵심 아이디어: **각 단어와 주변 단어들 사이의 관계를 예측**하도록 학습시킴

| 방식 | 설명 |
|------|------|
| **Skip-gram (SG)** | **중심 단어**를 통해 **주변 단어**를 예측 |
| **CBOW (Continuous Bag of Words)** | **주변 단어들**을 통해 **중심 단어**를 예측 — 문맥 단어들의 집합으로 중심 단어를 맞춤 |

#### Skip-gram: 중심 단어로 주변 단어 예측하기

- **윈도우 크기(window size)**: 중심 단어 주변 몇 개의 단어를 문맥으로 볼 것인가

**예시 (윈도우 크기 = 2)**
- 문장: "… problems turning into **banking** crises as …"
- 중심 단어: "banking" (위치 t)
- 주변 단어: {"turning", "into", "crises", "as"}

Skip-gram은 중심 단어 wₜ가 주어졌을 때, 각 주변 위치의 단어가 등장할 확률 P(wₜ₋₂|wₜ), P(wₜ₋₁|wₜ), P(wₜ₊₁|wₜ), P(wₜ₊₂|wₜ) 를 각각 예측하도록 학습한다. 즉, "banking이라는 단어를 봤을 때, 그 주변에 turning/into/crises/as 같은 단어들이 나올 확률이 높아지도록" 모델을 학습시키는 것.

#### CBOW: 주변 단어로 중심 단어 예측하기

- 목표: 주변 단어들의 집합이 주어졌을 때, 그 문맥과 함께 등장할 수 있는 단일 단어(중심 단어)를 예측

**예시**
- 문장: "The quick **brown** fox runs away."
- 입력(주변 단어): "The", "quick", "fox", "runs"
- 출력(중심 단어): "brown"

- 4개의 주변 단어가 입력으로 들어갔을 때, "brown"이 출력되도록 손실(loss)을 줄여가며 학습시키면, 이후에는 중심 단어를 매우 잘 예측하는 모델이 됨
- 비유: 글을 외우는 유치원생에게 문장에서 빈칸을 하나 뚫어놓고 "여기 들어갈 단어가 뭐게?"라고 묻는 것과 비슷함

#### Skip-gram vs CBOW 비교

| 항목 | Skip-gram | CBOW |
|------|-----------|------|
| 적은 데이터에서 | 잘 동작함 | — |
| 희귀 단어/구 표현 | 강함 | 약함 |
| 학습 속도 | 느림 | 빠름 |
| 자주 나오는 단어 | — | 강함 |

## 2. 순차적 데이터와 RNN

### 2-1. 순차적 데이터(Sequential Data)란?

- 예: 오디오, 텍스트, 비디오 등

**특징**
- **순서가 중요함**
- **장기 의존성(long-term dependency)**: 멀리 떨어진 정보가 현재/미래에 영향을 줌
  - 예: "여러 문 중 파란 문을 열고 안으로 들어가면, 너는 (?)를 찾게 될 거야" — 앞쪽의 "파란 문"이라는 정보가 뒤쪽 빈칸 예측에 영향을 줌
- **가변 길이(variable length)**: 순차 데이터는 길이가 일정하지 않고, 단어 수도 제각각임

### 2-2. RNN(Recurrent Neural Network)이 필요한 이유

- 전통적인 인공신경망(MLP 등)은 **고정된 길이의 입력**만 받을 수 있어서, 가변 길이의 데이터를 처리하기에 적합하지 않음
- 또한 순서 정보가 고려되지 않음(입력 순서를 바꿔도 결과가 같음)
- **RNN**은 가변 길이의 입력을 받을 수 있고, **이전 입력을 기억**할 수 있기 때문에 시퀀셜 데이터를 처리하기에 적합한 아키텍처
- 여러 입력 → 여러 출력(Many-to-Many)처럼 다양한 입출력 형태를 다룰 수 있음

### RNN 아키텍처, 아주 자세히 설명

> 강의를 따라가기 어려웠던 부분을 반영해, RNN의 구조와 수식을 처음부터 차근차근 풀어서 정리한다.

**핵심 아이디어**: RNN은 "이전 시점까지의 정보를 요약해서 기억하는 저장 공간"을 하나 가지고 있고, 매 시점(time step)마다 그 저장 공간을 업데이트하면서 시퀀스를 하나씩 읽어나간다. 이 저장 공간을 **히든 스테이트(hidden state, h)**라고 부른다.

**표기법 정리**

| 기호 | 의미 |
|------|------|
| xₜ | 시점 t에서의 입력 (예: t번째 단어의 벡터) |
| hₜ | 시점 t에서의 히든 스테이트 (그때까지의 정보를 요약한 벡터) |
| h₀ | 초기 히든 스테이트 (보통 0벡터로 시작) |
| yₜ | 시점 t에서의 출력 |
| Lₜ | 시점 t에서의 손실(정답과 yₜ의 차이) |
| Whh, Wxh, Why | 학습되는 가중치 행렬들 |

**핵심 수식 — 히든 스테이트 업데이트**

```
hₜ = tanh( Whh · hₜ₋₁ + Wxh · xₜ )
```

이 수식을 하나씩 뜯어서 이해해보면:

1. **Whh · hₜ₋₁**: "바로 이전 시점까지 기억하고 있던 정보(hₜ₋₁)"를, 가중치 행렬 Whh로 변환한 것. 즉 "과거의 기억을 이번 시점에 어떻게 반영할지"를 결정하는 부분.
2. **Wxh · xₜ**: "지금 새로 들어온 입력(xₜ)"을, 가중치 행렬 Wxh로 변환한 것. 즉 "새로운 정보를 어떻게 받아들일지"를 결정하는 부분.
3. 이 두 값을 **더한다**: "과거의 기억"과 "새로운 입력"을 합쳐서, 새로운 종합 정보를 만든다.
4. **tanh(...)**: 이 합산 값을 −1~1 사이로 압축해주는 활성화 함수. 값이 너무 커지거나 작아지는 것을 막고, 비선형성도 추가한다.
5. 그 결과가 바로 **새로운 히든 스테이트 hₜ** — "지금 시점까지의 모든 정보를 요약한, 갱신된 기억"이다.

이 과정을 시점 t=1, 2, 3, ..., T까지 **똑같은 가중치(Whh, Wxh)를 재사용**하면서 반복한다. 즉 파라미터는 "하나의 세트"만 있고, 그 파라미터가 매 시점마다 같은 방식으로 적용된다 (파라미터 공유, parameter sharing).

**출력 수식**

```
yₜ = Why · hₜ
```

- 각 시점의 히든 스테이트 hₜ를 다시 한번 가중치 Why로 변환해서, 그 시점의 출력 yₜ를 만들어낸다 (예: 다음 단어에 대한 예측 확률 분포 등)
- 각 시점의 출력 yₜ와 정답을 비교해서 손실 Lₜ를 계산하고, 전체 손실 L은 모든 시점의 손실을 합친 것

**"펼쳐서(unroll)" 보면 이해가 쉬워진다**

RNN을 그림으로 그릴 때 "한 개의 박스가 화살표로 자기 자신에게 돌아가는" 형태로 그리기도 하는데, 이걸 시간 축으로 **펼쳐서(unrolled)** 보면, 마치 "각 층이 하나의 시점을 나타내는, 아주 깊은 신경망"처럼 보인다. 다만 일반적인 깊은 신경망과 다른 점은, **모든 층(시점)이 완전히 동일한 가중치 W를 공유**한다는 것이다.

**RNN이 일반 신경망(피드포워드)과 다른 점**

- 일반적인 피드포워드 신경망은 입력 → 출력이 한 방향으로만 흐르고, 각 입력이 서로 독립적으로 처리됨
- RNN은 히든 스테이트를 통해 **과거 입력에 계속 영향을 받는다**는 점이 결정적으로 다름 — "기억"이 있는 신경망이라고 볼 수 있음

### 2-3. RNN의 기울기 소실 문제

- 역전파 과정에서, 시점 T에서 시점 1까지 거슬러 올라가며 tanh의 미분값 같은 **작은 값들이 계속 곱해짐**
- 그래서 **과거 시점에서 온 오차 신호는, 갈수록 더 작은 기울기**를 갖게 됨 (앞서 배운 시그모이드의 기울기 소실과 같은 원리 — 1보다 작은 값을 계속 곱하면 0에 수렴)
- 결과적으로, 파라미터들이 **장기 의존성(long-term dependency)은 학습하지 못하고, 단기 의존성만 포착**하게 됨 — RNN은 "방금 전 몇 단어"는 잘 기억하지만, "훨씬 이전의 문맥"은 거의 잊어버리는 경향이 있음

## 3. LSTM (Long Short-Term Memory)

- **1997년**, RNN의 기울기 소실 문제를 해결하기 위해 등장한 **RNN의 한 종류**

### LSTM 아키텍처, 아주 자세히 설명

**핵심 아이디어**: 일반 RNN은 "기억(히든 스테이트)"을 매 시점마다 통째로 새로 계산해서 덮어쓰다시피 하기 때문에, 오래된 정보가 쉽게 씻겨나간다(기울기 소실). LSTM은 이 문제를 해결하기 위해, **"오래 기억해야 할 정보"를 저장하는 별도의 통로(셀 스테이트)**를 추가로 만들고, 이 통로에 대해 **"무엇을 지우고, 무엇을 새로 쓰고, 무엇을 꺼내 쓸지"를 정교하게 조절하는 게이트(gate)**들을 둔다.

**두 가지 상태(state)**

| 상태 | 기호 | 역할 |
|------|------|------|
| **셀 스테이트 (Cell State)** | Cₜ | **장기(long-term) 정보**를 저장하는 "컨베이어 벨트" — 거의 그대로 다음 시점까지 흘러감 |
| **히든 스테이트 (Hidden State)** | hₜ | **단기(short-term) 정보** — 그 시점에서의 출력이자, 다음 시점으로 넘어가는 "현재 상태 요약" |

셀 스테이트 Cₜ는 마치 컨베이어 벨트처럼, 필요한 정보만 게이트를 통해 조금씩 더하거나 지우면서 시간축을 따라 쭉 흘러간다. 그래서 정보가 여러 시점을 거쳐도 잘 보존될 수 있다 (기울기 소실 완화).

**3가지 게이트**

LSTM은 매 시점마다 3개의 "게이트"를 계산해서, 셀 스테이트를 어떻게 업데이트할지 결정한다. 각 게이트는 0~1 사이의 값을 출력하는 **시그모이드 함수**로 계산되며, 이 값은 "얼마나 통과시킬지(비율)"를 의미한다 (0 = 완전히 막음, 1 = 전부 통과).

| 게이트 | 역할 |
|--------|------|
| **포겟 게이트 (Forget Gate)** | 이전 셀 스테이트(Cₜ₋₁)에서 **무엇을 버리고, 무엇을 유지할지** 결정 |
| **인풋 게이트 (Input Gate)** | 새로운 정보 중 **얼마나 셀 스테이트에 쓸지** 결정 |
| **아웃풋 게이트 (Output Gate)** | 셀 스테이트 중 **얼마나 히든 스테이트로 내보낼지** 결정 |

- 게이트의 출력값은 0, 1 혹은 그 사이의 값으로 설정됨
- 게이트는 **동적으로 계산**되며, 현재 입력(xₜ)과 이전 히든 스테이트(hₜ₋₁) 등 **문맥에 따라 값이 정해짐** (고정된 값이 아니라, 매 시점 상황에 맞게 새로 계산됨)

**포겟 게이트 수식 (예시)**

```
fₜ = σ( Wf · [hₜ₋₁, xₜ] + bf )
```

이 수식을 하나씩 뜯어보면:

1. **[hₜ₋₁, xₜ]**: 이전 히든 스테이트와 현재 입력을 이어붙인(concatenate) 벡터. "지금까지의 단기 기억"과 "지금 새로 들어온 정보"를 한 번에 살펴보겠다는 뜻.
2. **Wf · [hₜ₋₁, xₜ] + bf**: 이 이어붙인 벡터를 가중치 Wf와 편향 bf로 선형변환. 즉 "지금 상황을 보고, 이전 기억을 얼마나 버릴지 말지를 판단하기 위한 점수"를 계산하는 것.
3. **σ(...)** (시그모이드): 이 점수를 0~1 사이의 값으로 눌러줌. 이 값이 바로 "이전 셀 스테이트를 얼마나 유지할지"를 나타내는 **비율**이 된다.
   - fₜ가 1에 가까우면 → "이전 정보를 거의 그대로 유지해라"
   - fₜ가 0에 가까우면 → "이전 정보를 거의 다 잊어버려라"

이렇게 계산된 fₜ는 이후 셀 스테이트 업데이트 단계에서 **Cₜ₋₁과 곱해져서(fₜ × Cₜ₋₁)**, "이전 기억 중 살아남는 비율만큼만" 다음 셀 스테이트로 전달되는 데 사용된다. (인풋 게이트·아웃풋 게이트도 각각 비슷한 형태의 시그모이드 수식으로 계산되며, 이렇게 계산된 세 게이트가 함께 작동해 셀 스테이트와 히든 스테이트를 갱신한다.)

## 4. 언어모델 (Language Model)

### 언어모델이란?

- 인간의 두뇌가 자연어를 생성하는 능력을 모방한 모델
- **단어 시퀀스 전체에 확률을 부여**하여, 문장이 얼마나 자연스러운지를 측정함

### N-gram 언어모델

- **N-gram**: 연속된 N개 단어의 묶음
- 다양한 N-gram이 (말뭉치, corpus 안에서) 얼마나 등장했는지 통계를 수집하고, 이를 활용해 다음 단어를 예측함

**예시 (4-gram 언어모델)**

- 문장: "as the proctor started the clock, the **students opened their** ___"
- **직전 3개 단어("students opened their")**만 문맥으로 사용 (그 앞의 "as the proctor started the clock, the"는 반영되지 않음 — N-gram의 한계)

**코퍼스(말뭉치) 정보 예시**
- "students opened their" — 1000번 등장
- "students opened their **books**" — 400번 등장 → P(books | students opened their) = 400/1000 = **0.4**
- "students opened their **exams**" — 100번 등장 → P(exams | students opened their) = 100/1000 = **0.1**

> N-gram 모델의 한계: 정확히 N-1개까지의 직전 단어만 보기 때문에, 그보다 더 멀리 있는 문맥(장기 의존성)은 전혀 반영하지 못함

**옛날 기계번역 방식**: 번역 문제를 두 부분으로 쪼개서 사용
- **번역 모델**: 단어와 구가 어떻게 번역되어야 하는지를 모델링
- **언어 모델**: 유창한 (예: 영어) 문장을 쓰는 방법을 모델링 (영어 데이터로만 학습)
- 두 모델을 베이즈 룰(Bayes' rule)로 결합해서, 두 확률을 곱해 사용

## 5. Seq2Seq (Sequence-to-Sequence)

### 5-1. Seq2Seq 아키텍처

- **인코더(Encoder)**와 **디코더(Decoder)**로 이루어짐
- **인코더**: 입력 문장에 담긴 정보를 인코딩(요약)함
- **디코더**: 인코딩된 정보를 조건으로 하여, 타겟(목표) 문장을 생성함

**번역이 어려운 이유**

- 번역 문제는 **입력과 출력의 길이가 다를 수 있음**
- 신경망 기계번역(NMT)에서는 **길이가 다른 시퀀스 간의 매핑**을 처리할 수 있어야 함

**Seq2Seq의 아이디어 — 2개의 LSTM 사용**

- 한 LSTM(인코더)은 입력 시퀀스를 한 타임스텝씩 읽어서, **고정된 차원의 큰 벡터 표현(context vector)**을 얻음
- 다른 LSTM(디코더)은 인코더에게서 얻은 이 벡터로부터, **출력 시퀀스를 생성**함

**Seq2Seq 구조의 다양한 활용**

Seq2Seq 구조는 기계번역 외에도 다양한 태스크에 적용 가능:
- **요약(Summarization)**: 긴 문서를 읽고, 짧은 문장으로 요약된 텍스트를 출력
- **대화(Dialogue)**: 사용자의 발화를 기반으로, 맥락에 맞는 대답을 생성
- **코드 생성(Code Generation)**: 자연어로 작성된 설명/명령어를 입력받아, 그에 대응하는 프로그래밍 코드나 쿼리를 출력

### 5-2. 학습 — 티처 포싱 (Teacher Forcing)

- 인코더와 디코더는 하나의 통합 네트워크로 연결되어 학습됨
- 예: 출력 어휘 사전(vocabulary)이 50만 개라면, 각 단어는 50만 차원의 원-핫 인코딩 벡터로 표현됨
- **학습 초반에는 모델의 예측 능력이 형편없어서**, 학습이 불안정해질 수 있음

**티처 포싱이란?**

- 디코더가 다음 단어를 생성할 때, **모델이 스스로 예측한(틀렸을 수도 있는) 단어 대신, 정답 단어를 디코더의 입력으로 강제로 넣어주는** 방법
- 이렇게 하면 **훨씬 빠르고 안정적으로 학습**을 수행할 수 있음
- 시퀀스로 순차 진행되는 구조이기 때문에, 학습 중에는 (자기 자신이 틀린) 앞쪽 출력을 뒤쪽 입력에 그대로 넣지 않고, **앞쪽에는 항상 정답을 넣어주면서** 한 단어씩 손실(loss)을 계산함
- **적응형 훈련(스케줄드 샘플링)**: 학습 초반에는 티처 포싱을 많이 하다가, 학습이 진행되면서 후반으로 갈수록 티처 포싱 비율을 점점 줄여나가는 방식도 사용할 수 있음

### 5-3. 추론 (Inference) — 실사용 시

- **실제로 사용할 때(추론, inference)**는 정답을 알 수 없으므로, 매 단계에서 모델이 스스로 예측한 단어를 사용해야 함
- 문제는, 추론 중에는 **각 단계에서 한번 틀리면 되돌릴(undo) 수가 없다**는 것 — 한번 잘못된 단어가 나오면, 그 잘못된 단어를 기반으로 다음 단어를 또 예측하게 되어 **에러가 걷잡을 수 없이 누적**될 수 있음

**빔서치 (Beam Search)**

- 이 문제를 완화하기 위한 방법. 절차:
  1. 매 단계마다, 가장 가능성 있는(유망한) **k개의 후보** 시퀀스를 동시에 유지 (k = 빔 크기, beam size)
  2. 어떤 후보가 문장 종료 토큰(EOS)에 도달하면, **완성된 문장으로 리스트에 추가**
  3. 완성된 문장이 충분히 모이면 **탐색 종료**
  4. 각 후보들의 점수를 **로그 확률의 합(sum of log probabilities)**으로 계산해서, 그중 **최종 후보를 선택**

## 6. Attention

### 어텐션이 필요한 이유 — 병목 현상(Bottleneck Problem)

- 앞서 배운 기본 Seq2Seq 구조의 문제: 인코더는 **입력 문장 전체를, 마지막 시점의 히든 스테이트 단 하나(고정 길이 벡터)에 요약**해서 담아야 함
- 문장이 길어질수록, 이 하나의 고정 길이 벡터에 문장 전체의 의미 정보를 다 압축해 넣다 보니 **정보 손실**이 생길 수 있음 — 이를 **병목 현상(Bottleneck Problem)**이라고 부름
- 직관적으로, 문장이 길어질수록 맥락 정보가 마지막 히든 스테이트 안에서 점점 희석되어 있을 확률이 높음

**어텐션의 핵심 아이디어**: "인코더의 마지막 히든 스테이트 하나에만 의존하지 말고, 디코더가 각 단어를 생성할 때마다, 인코더가 갖고 있는 모든 시점의 히든 스테이트들을 다시 들여다보면서, 지금 필요한 정보를 그때그때 검색해서 가져다 쓰자"는 것 — **"내가 필요한 정보를 검색해서 보고 싶다"**는 아이디어

### 어텐션 개념, 아주 자세히 설명

**Query와 Values 관점으로 이해하기**

Seq2Seq에서 Attention을 사용할 때, **디코더의 (현재 시점) 히든 스테이트**와 **인코더의 모든 시점 히든 스테이트들** 사이의 관계를, 마치 "검색(search)"하는 관계처럼 볼 수 있다.

| 역할 | 무엇에 해당하는가 | 비유 |
|------|---------------------|------|
| **Query (질의)** | 디코더의 현재 히든 스테이트 | "내가 지금 찾고 싶은 정보는 이런 거야" (검색창에 입력하는 검색어) |
| **Values (값)** | 인코더의 모든 시점 히든 스테이트들 | "검색 대상이 되는 자료들" (검색 엔진이 갖고 있는 모든 문서) |

Attention의 전체 과정은 다음 3단계로 정리할 수 있다.

**1단계 — Query와 Values 사이의 유사도 점수(score) 계산**

- 디코더의 현재 Query(질의)가, 인코더의 각 시점 히든 스테이트(Value)와 **얼마나 관련이 있는지**를 점수로 계산
- 계산 방법은 여러 가지가 있음: **내적(dot-product)**, **곱셈식(multiplicative)**, **덧셈식(additive)** 등
- 직관: "지금 내가 궁금한 것(Query)과, 원문의 이 단어(Value)가 서로 얼마나 관련 있어 보이는가?"를 숫자 하나로 매기는 것

**2단계 — Softmax를 통해 확률 분포(attention distribution) 얻기**

- 1단계에서 계산한 여러 점수들을 **Softmax** 함수에 통과시켜서, 합이 1이 되는 **확률 분포**로 변환
- 이 분포가 바로 **Attention Distribution(어텐션 가중치)** — "원문의 각 단어에, 지금 이 순간 얼마만큼씩 주목(attend)해야 하는가"를 나타내는 비율

**3단계 — 분포를 이용해 Values를 가중합 → context vector(attention output)**

- 2단계에서 구한 확률 분포(가중치)를 이용해서, 인코더의 모든 히든 스테이트(Values)를 **가중합(weighted sum)**함
- 그 결과로 얻어지는 벡터가 **컨텍스트 벡터(context vector, attention output)** — "지금 이 순간, 원문에서 필요한 정보만 선택적으로 요약해서 가져온 벡터"

### 어텐션의 효능

**1. 해석 가능성 (Interpretability)**

- 어텐션 분포(attention distribution)를 시각화해서 보면, 디코더가 특정 단어를 생성할 때 **입력 문장의 어느 부분에 집중했는지**를 확인할 수 있음
- 모델이 내부적으로 어떤 근거를 참고해서 그 단어를 선택했는지, **사람이 파악할 수 있게** 해줌
- 즉 어텐션 분포는 모델의 **의사결정 과정을 해석할 수 있는 단서**가 됨

**2. 정렬 (Alignment)**

- 기존(어텐션 이전) 기계번역에서는, 원문 단어와 번역문 단어 사이의 대응 관계(정렬, alignment)를 파악하기 위해 **별도의 단어 정렬(word alignment) 모델을 따로 학습**해야 했음
- 어텐션을 사용하면, 디코더가 필요한 입력 단어에 **자동으로 집중**하기 때문에, 단어와 단어 간의 매핑 관계(정렬)를 **별도 모델 없이도 자연스럽게 학습**하게 됨

**정리하면**

- 기존 Seq2Seq: 인코더의 마지막 히든 스테이트 **하나**만 보고 전체 문장을 번역/생성해야 했음 (병목)
- Attention 적용: 디코더가 **매 단어를 생성할 때마다**, 인코더의 모든 히든 스테이트를 다시 살펴보고, **그 순간 가장 관련 있는 부분에 집중(attention)**해서 정보를 가져다 씀
- 이 덕분에, 문장이 아무리 길어도 정보 손실 없이 필요한 부분을 정확히 참조할 수 있게 됨 — 이것이 바로 이후 **트랜스포머(Transformer)** 아키텍처의 핵심 아이디어로 이어짐

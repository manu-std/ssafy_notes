## 1. 왜 온디바이스 AI인가

### 모든 지능이 클라우드에 있으면 위험하다

- **인터넷이 멈추면 공장도 멈춘다** — 프롬프트를 입력해도 응답을 받지 못함
- 단순히 효율성이 떨어지는 수준이 아니라, **모든 플로우가 멈추는 문제**가 발생

### 피지컬 AI (Physical AI) 예시

**쿠키 공장의 불량 검출 시스템**

```
컨베이어 벨트에 쿠키가 지나감
   → 최대 생산 속도를 따라잡는 실시간 추론
   → 불량 쿠키 검출
   → 로봇팔로 옮기는 액션
```

- 이 추론이 클라우드에 있다면 **응답 속도 때문에 불가능**하다 — **실시간성이 없다**
- 게다가 **프라이버시 문제**도 있다

> **결론: 엣지 디바이스에 지능을 직접 구동해야 한다.**

## 2. 온디바이스 AI 하드웨어

### 왜 전용 하드웨어가 필요한가

- 일반 목적 하드웨어인 **CPU·GPU는 AI 구동에서 속도와 전력 소모에 한계**가 있음
- **범용성을 포기하고 AI 도메인 특화 가속기로 진화**하면서 온디바이스 AI가 가능해짐

**핵심은 전력 효율과 메모리 접근 속도**

> 📌 **비유**: 메모가 **책상 위에 붙어 있으면 바로 참조**할 수 있지만, **책장에 꽂혀 있으면 바로 참조할 수 없다.**

- **DRAM 접근을 최소화**하고
- **온칩 SRAM**과 **DMA 엔진 구조**를 적극 활용
- → **효율과 성능이 크게 상승**

- ⚠️ **PyTorch는 파워풀한 하드웨어에서만 돌아간다** → 배포는 별도의 **런타임**이 필요

|---|---|

### 문제 — 런타임이 너무 많다

**이걸 다 배워야 하나?**

| 문제 | 내용 |
|---|---|
| **프레임워크 종속성 문제** | PyTorch와 TensorFlow가 서로 호환되지 않음 |

**ONNX(오닉스)**는 **호환성에 방점**을 두고, 자동 변환이 되도록 만들어둔 개방형 포맷.

> **요즘은 PyTorch에서 ONNX까지만 보내면, 나머지는 ONNX가 다 해준다.**

## 4. 100% 정수 연산 양자화의 필요성

### AI 가속기의 구동 특성

**가속기는 정수 연산만 지원하거나, 정수 연산에서 훨씬 효율적이다.**

| 가속기 | 특성 |
|---|---|
| **Google Coral Edge TPU** | **8비트 정수 모델만 실행** — 미지원 연산은 CPU로 보냄 |
| **ARM Ethos NPU 시리즈** | 8비트·16비트 정수 모델 실행 — 나머지는 CPU로 넘김 |

> **왜 정수 연산만 되나?** → **정수 연산이 훨씬 간단하기 때문.** 범용성은 포기하겠다는 설계 철학이다.
>
> (23번 노트에서 봤듯, 부동소수점 연산은 지수 정렬·사후 정규화 때문에 레이턴시와 회로 면적을 지수 스케일로 지불해야 한다.)

⚠️ 여기서 문제가 생긴다 — **미지원 연산이 CPU로 넘어가면(fallback), 가속기를 쓰는 의미 자체가 사라진다.** 그래서 **모델의 모든 연산이 100% 정수로 돌아가야** 한다.

## 5. 일반 양자화 — 스케일과 제로포인트

### 기본 발상

실수 r을 정수 q로 표현하고 싶다. 그런데 **무한한 실수를 8비트(256개)로 표현할 수 있을까?**

- 실수를 유심히 관찰해보니 "아, 이 값들은 100~200 사이에서 나오는구나"
- → **유한한 관심 범위(range)를 지정한다** — "여기는 내가 확실히 정수화하겠다"
- 실수는 무한하지만, **적절하게 구간을 나눠서 매핑**한다

```
r (실수)   ├──┼──┼──┼─ … ─┼──┼──┤
          rmin                  rmax
            ↓   ↓   ↓        ↓   ↓
q (8비트)   0   1   2  …    254  255
```

### 필요한 두 가지 파라미터

| 파라미터 | 이름 | 역할 |
|---|---|---|
| **S** | 스케일링 파라미터 (**실수**) | **한 칸의 크기** — 정수 눈금 하나가 실수로 얼마인지 |
| **Z** | 오프셋/제로포인트 파라미터 (정수) | **영점 조절** — 실수 0이 정수 몇 번에 해당하는지 |

**변환 공식**

```
r = S · (q − Z)

S = (r_max − r_min) / (2^8 − 1)
Z = ⌊ −r_min / S ⌋
```

- 관심 범위를 벗어난 값은 **클리핑(clipping)**, 눈금 사이의 값은 **반올림** 등으로 처리

> 📌 구현체에 따라 Z를 구할 때 내림 대신 반올림을 쓰기도 하고, 결과를 [0, 255] 범위로 클리핑하기도 한다. 핵심은 **"실수 0이 반드시 정수 격자 위의 한 점에 정확히 대응되어야 한다"**는 것이다 — 패딩이나 ReLU 때문에 0이 정확히 표현되지 않으면 오차가 크게 번지기 때문이다.

### ⚠️ 그런데 문제가 있다 — S가 실수다

양자화를 했으니 **q만 가지고 연산할 것 같지만, 실제로는 S가 실수라서 무조건 실수 연산을 해야 한다.**

> **→ 가속기 구동 불가.** 이게 바로 4장에서 말한 "CPU로 넘어가버리는" 상황이다.

## 6. 행렬 곱 연산의 양자화

**목표**: 스케일링 파라미터를 정수화하여, q₃를 **정수 연산만으로** 유도하기

### 주어진 상황

실수 행렬 `r₃ = r₁ · r₂` (r_α ∈ R^(N×N))이고, **r₁, r₂, r₃가 각자 자신의 양자화 스킴을 가진다.**

| 행렬 | 양자화 스킴 | 양자화 결과 |
|---|---|---|
| r₁ | (S₁, Z₁) | q₁^(i,j) |
| r₂ | (S₂, Z₂) | q₂^(j,k) |
| r₃ | (S₃, Z₃) | q₃^(i,k) |

### 식 전개

각 원소를 `r = S(q − Z)`로 바꿔서 대입하면:

```
S₃ ( q₃^(i,k) − Z₃ ) = Σ(j=1 to N) S₁( q₁^(i,j) − Z₁ ) · S₂( q₂^(j,k) − Z₂ )
```

### 호재 — 실수를 한 덩어리로 묶을 수 있다

우변에서 S₁, S₂는 시그마 밖으로 빼낼 수 있고, 좌변의 S₃는 이항할 수 있다.

```
q₃^(i,k) = Z₃ + M · Σ(j=1 to N) ( q₁^(i,j) − Z₁ )( q₂^(j,k) − Z₂ )

여기서   M := S₁ · S₂ / S₃      ← 스케일링 파라미터(실수)를 변수 한 개로 묶음
```

> 💡 **이것이 오늘의 핵심 기법 ① "실수 파트만 모으기"다.**
>
> 시그마 안쪽(`(q₁ − Z₁)(q₂ − Z₂)`)은 **전부 정수 연산**이다. 실수는 오직 **M 하나**로 응축되었다.
>
> **→ M을 별도로 미리 양자화시켜버리면, 실수 연산이 전멸한다.**

### 남은 문제

⚠️ **M은 실제로 0과 1 사이의 값**이라, 그냥 정수로 나타내기가 어렵다.

## 7. 비트 시프팅

**해결책: 비트 시프팅** (파이썬의 `<<`, `>>` 연산자와 같은 그것)

**비트 시프팅 과정**: **임시로 스케일 업 → 양자화 및 연산 → 스케일 다운**

```
q₃^(i,k) = Z₃ + M · Σ(q₁ − Z₁)(q₂ − Z₂)

        ↓

q₃^(i,k) = Z₃ + 2^(−n) · { (2^n · M) · Σ(q₁^(i,j) − Z₁)(q₂^(j,k) − Z₂) }
                  ↑          ↑
           스케일 다운    스케일 업
          (비트 시프트)    (정수화)
```

**작동 원리**

1. **스케일 업**: M이 0.003 같은 작은 실수라면, 2^n을 곱해서 (예: n=30) `2^n · M`을 충분히 큰 값으로 만든다 → **반올림하면 의미 있는 정수**가 된다
2. **연산**: 이제 모든 항이 정수이므로 **정수 곱셈과 덧셈만으로** 계산
3. **스케일 다운**: 결과를 `2^(−n)`배 한다 = **오른쪽으로 n비트 시프트**

> 📌 **핵심 포인트**: 2의 거듭제곱으로 나누는 것은 **나눗셈이 아니라 비트 시프트**다. 23번 노트에서 봤듯 나눗셈은 압도적으로 비싼 연산이지만, **비트 시프트는 사실상 공짜**다.
>
> 이것이 23번에서 배운 **고정소수점의 스케일링 팩터** 개념 그 자체다 — 하드웨어는 정수로만 다루고, 소수점 위치(= n)는 우리가 관리한다.

## 8. 배치 정규화 계층 폴딩 (BN Folding)

### 배치 정규화란

**학습 중 정규화를 통해 입력 분포의 변화를 줄여 안정적인 학습을 돕는 기법.**

```
BN(x) = γ · (x − μ_batch) / √(σ²_batch + ε) + β
```

- ⚠️ **BN 계층에서도 실수 연산이 필요하다**
- 그러나 **BN 계층에서 별도로 양자화를 진행하면 비효율적**이다
- → 그래서 **폴딩(folding) 기법**을 사용한다

### BN 폴딩이란

**BN 연산을 바로 앞의 Conv 계층 연산에 통합해서 함께 양자화하는 것.**

**폴딩 전**
```
Input X_q
   ↓
Conv W_q
   ↓ s_q
BN σ, μ        ← 여기서 실수 연산 발생
   ↓ s_q,B
  ( + ) ← Bias b_q
   ↓ a_q
ReLU6
```

**폴딩 후**
```
Input X_q
   ↓
Conv W_fold,q     (W_fold = W / σ)
   ↓
  ( + ) ← Bias b_fold,q     (b_fold = b − μ/σ)
   ↓ a_q
ReLU6

a = X·W_fold + b_fold = (X·W − μ)/σ + b = s_B + b
```

### 왜 이게 되는가 — 상세 설명

Conv와 BN이 **연달아 붙어 있을 때** 성립하는 이야기다. 하나씩 뜯어보자.

**① 두 연산 모두 "곱하고 더하기"에 불과하다**

Conv 계층이 하는 일은 입력에 가중치를 곱하고 편향을 더하는 것이다.

```
Conv:  y = X·W + b
```

BN이 하는 일도, **추론 시점에는** 결국 같은 형태다.

```
BN:  z = γ · (y − μ)/σ + β
       = (γ/σ)·y + (β − γμ/σ)
        ↑ 곱하는 상수    ↑ 더하는 상수
```

> ⚠️ **중요**: 학습 중에는 μ와 σ가 **매 배치마다 달라지는 값**이라 이렇게 못 한다. 하지만 **학습이 끝나면 μ와 σ는 전체 데이터의 이동평균으로 고정된 상수**가 된다. γ, β도 학습이 끝난 고정값이다. **그래서 추론 시점의 BN은 그냥 "상수를 곱하고 상수를 더하는" 선형 변환일 뿐이다.**

**② 선형 변환 두 개를 이어 붙이면 선형 변환 하나가 된다**

이제 Conv 결과를 BN에 넣어보자.

```
z = (γ/σ)·(X·W + b) + (β − γμ/σ)
  = X · (γW/σ) + { γ(b − μ)/σ + β }
        ↑              ↑
    새로운 가중치      새로운 편향
```

**즉 "Conv 하고 BN 하기" = "새 가중치로 Conv 하기 한 번"이다.** BN 계층이 통째로 사라졌다.

> 📌 **슬라이드의 식은 γ=1, β=0인 단순화된 형태다.** 슬라이드에서는 `W_fold = W/σ`, `b_fold = b − μ/σ`로 쓰는데, γ와 β까지 포함한 일반형은 위와 같이 `W_fold = γW/σ`, `b_fold = γ(b−μ)/σ + β`가 된다. 개념은 완전히 동일하다 — γ도 결국 상수이므로 그냥 σ와 함께 나눗셈에 흡수될 뿐이다.

**③ 그래서 양자화 관점에서 무엇이 좋아지는가**

이게 핵심이다.

- **폴딩 전**: Conv를 정수로 계산해서 결과를 뱉으면, 그 결과를 다시 실수로 되돌려서(디퀀타이즈) BN의 실수 연산(나눗셈, 제곱근)을 하고, 다시 정수로 양자화해야 한다. **정수 ↔ 실수 왕복이 매 계층마다 발생한다**
- **폴딩 후**: `W_fold`는 **학습이 끝난 시점에 미리 계산해둘 수 있는 고정된 가중치**다. 그러니 **평소처럼 한 번 양자화해서 저장해두면 끝**이다
- 추론 시에는 **Conv 하나만 정수로 돌리면 되고, BN 계층은 아예 존재하지 않는다**

**④ 결국 이렇게 정리된다**

> "W에 σ를 합쳐버려서 새로운 가중치를 만든다" = **W를 미리 σ로 나눠둔 뒤 양자화**한다
> "μ는 바이어스로 넘긴다" = **μ/σ를 b에서 빼둔 뒤 양자화**한다

**⑤ 덤으로 얻는 것**

BN 폴딩은 양자화를 안 하더라도 **그 자체로 추론 최적화 기법**이다. 계층 하나가 통째로 사라지므로 메모리 접근과 연산이 줄어든다. 그래서 TensorRT 같은 추론 엔진은 양자화 여부와 무관하게 **기본적으로 BN 폴딩을 수행**한다.

> 이 테크닉까지 적용하면 **CNN은 완전히 양자화된다.**

## 9. 트랜스포머의 양자화

CNN은 위 방법으로 해결됐는데, **트랜스포머는 어떻게 양자화하나?**

### 새로운 연산들이 등장한다

| 연산 | 비고 |
|---|---|
| **Softmax** | 사실 CNN에도 들어간다 |
| **GELU** | — |
| **LayerNorm** | — |

> **전부 실수 투성이다.**

### 해결 전략 — 다 묶어서 처리하기

기본 아이디어는 앞서 본 것과 동일하다. **실수 파트를 한데 묶고, 비트 시프팅으로 정수화**하는 방식이 각 연산마다 모두 적용된다. (자세한 유도 과정은 강의에서 생략)

**연산별 접근법**

| 연산 | 정수화 방법 |
|---|---|
| **Softmax** | **정수 파트와 소수 파트를 분리**하려는 노력을 하고, **소수 파트를 묶어서 근사** |
| **GELU** | **1.702**라는 계수를 뽑아내서 비트 시프팅으로 근사하고, 내부의 시그모이드 함수는 **Softmax 양자화 방식을 차용** |
| **LayerNorm** | **비트 시프팅과 반복적 탐색(iterative search)**을 통해 근사값을 도출 |

> 📌 GELU의 1.702는 `GELU(x) ≈ x · σ(1.702x)`라는 잘 알려진 근사식에서 나온 값이다. 시그모이드로 환원되므로, 시그모이드만 정수로 처리할 수 있으면 GELU도 해결된다는 논리다.
>
> LayerNorm에서 "반복적 탐색"이 필요한 이유는 **제곱근** 때문이다. 제곱근은 나눗셈보다도 비싼 연산이라 닫힌 형태로 처리할 수 없고, 정수 뉴턴법 같은 반복 알고리즘으로 근사한다.

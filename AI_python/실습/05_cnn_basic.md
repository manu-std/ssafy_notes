## 1. 왜 MLP가 아니라 CNN인가

MLP로도 되긴 되는데, 왜 굳이 CNN을 써야 할까?

### 이미지 데이터의 특징

- 우리에게는 "고양이 사진"이지만, 컴퓨터에게는 **2차원 공간 구조를 가진 데이터**
- 컴퓨터 입장에서는 숫자로 이루어진 **2D 격자(표) 3장이 겹친 것** (R, G, B 채널)

### MLP의 한계 1 — 위치 정보 소실

- MLP는 입력을 **플래튼(flatten, 한 줄로 펼침)**해서 넣어야 하기 때문에, **픽셀의 위치 정보가 사라짐**
- 이미지의 의미는 **이웃한 픽셀들의 위치 관계** 속에서 나오는데, MLP는 이 "이웃 관계"를 입력 구조상으로는 알 수 없음

> `[개인 메모 · 시험범위 아님]` 개인적 소견: 픽셀의 위치정보는 (완전연결이니까) 사라지지만, 의미는 그래도 학습하는 거 아닌가? 어차피 어디에 입력하든 완전연결이면 모든 픽셀이 연결되긴 하잖아. 인접 위치라는 것도 어쨌든 픽셀 위치에 규칙이 있으니까 — 어디에 입력해도 다 똑같이 연결되면, 모델 입장에서는 오히려 "규칙이 없게" 느껴지는 걸까? 어쨌든 시누소이달 위치 인코딩 같은 아이디어로도 (MLP에) 해결할 수 있는 거 아닌가?
>
> **답변**
>
> 정말 예리한 질문이고, 절반은 정확히 맞는 지적이다.
>
> **① "위치 정보가 사라진다"는 표현은 사실 살짝 부정확한 축약이다.** 정확히 말하면, 완전연결(FC) 구조에서 입력을 한 줄로 펼치는 과정은 **되돌릴 수 있는(bijective) 순서 재배열**일 뿐이다 — 즉 각 입력 인덱스(예: 782번째 값)는 항상 원본 이미지의 정해진 한 픽셀(예: (24,30) 위치)에 고정되어 매핑된다. 그리고 첫 번째 레이어의 가중치는 "782번째 입력에 대한 가중치"처럼 **그 고정된 위치 전용으로** 학습된다. 그러니 정보 이론적으로는, 위치 정보가 "사라진다"기보다는 **"명시적인 2차원 구조가 아니라, 고정된 인덱스라는 형태로 암묵적으로 남아있다"**고 보는 게 더 정확하다. 이 부분에서의 직관은 맞다.
>
> **② 그런데 진짜 문제는 "위치 정보의 손실"이 아니라, "가중치 공유(weight sharing)의 부재"다.**
>
> - CNN의 필터는 이미지 전체에 걸쳐 **똑같은 가중치를 재사용**한다. 그래서 "세로선을 찾는 필터"를 왼쪽 위 모서리에서 한 번 배우면, 그 필터가 오른쪽 아래 모서리에 나타나는 세로선도 (같은 가중치로) 자동으로 찾아낸다 — 이게 **이동 불변성(translation invariance)**이다.
> - 반면 MLP는 782번째 입력(즉 특정 픽셀 위치)에 대한 가중치와, 1500번째 입력(다른 픽셀 위치)에 대한 가중치가 **완전히 독립적**이다. 그래서 "왼쪽 위에 세로선이 있다"는 패턴을 학습해도, 그 지식이 "오른쪽 아래에 세로선이 있다"는 패턴에 **자동으로 전이되지 않는다.** 이미지의 모든 가능한 위치마다, 같은 패턴을 **처음부터 다시, 독립적으로** 배워야 한다.
> - 이것이 정확히 강의에서 말한 **"파라미터 폭발"**과 같은 문제의 다른 얼굴이다 — 위치마다 별도로 학습해야 하니, 그만큼 파라미터도 늘어나고, 그 모든 파라미터를 제대로 학습시키려면 데이터도 훨씬 더 많이 필요하다.
>
> **③ 그래서 "시누소이달 위치 인코딩으로 해결할 수 있지 않나?"라는 질문에 대한 답:**
>
> 트랜스포머(ViT)의 위치 인코딩과 MLP의 상황은 **풀어야 할 문제 자체가 다르다.**
> - **셀프 어텐션**은 원래 입력을 **순서 없는 집합(set)**처럼 취급한다 — 그래서 "이게 몇 번째 토큰인지"를 알려주는 위치 인코딩이 반드시 필요하다.
> - **MLP는 이미 (①에서 설명했듯) 각 입력 인덱스가 고정된 위치에 대응**되어 있으므로, 굳이 위치 인코딩을 더할 필요가 없다 — MLP의 첫 레이어 가중치 자체가 이미 "이건 782번째 위치의 정보"라는 것을 암묵적으로 알고 학습되기 때문이다. 그러니 위치 인코딩을 추가해도 **가중치 공유가 없다는 근본적인 문제는 전혀 해결되지 않는다.**
>
> 정리하면: MLP가 "위치를 모른다"는 말은 엄밀히는 부정확하고, 진짜 한계는 **"위치마다 같은 패턴을 재사용하지 못하고, 매번 독립적으로 새로 배워야 한다"**는 것 — 이 문제는 위치 정보를 추가한다고 풀리는 게 아니라, **가중치를 공유하는 구조(CNN의 합성곱)**로만 풀린다.

### MLP의 한계 2 — 파라미터 폭발

- MLP는 **이전 층의 모든 뉴런이 다음 층의 모든 뉴런과 연결**되는 완전연결 구조
- 고해상도 이미지를 입력하면, 가중치 수가 폭발적으로 늘어남

## 2. CNN의 등장

- 이미지를 2차원 그대로 입력받아서, **필터라는 "도장"**으로 이미지의 각 부분을 찍어보며 특징을 추출

**CNN이 좋은 이유 3가지**
1. **공간 정보를 유지**
2. **파라미터 폭발 해결**
3. **위치 변화에 강건**

- 똑같은 필터를 이미지 전체에 **재사용**함 (파라미터 공유)
- 예: 필터 하나의 크기가 5×5(×채널)라면, 파라미터는 채널 수에 따라 75개(5×5×3) 정도로 매우 적음

### 이미지를 학습한다는 것 = 특징을 추출하는 것

- 데이터를 요약해서, 대상을 설명하는 **특징을 추출**하는 것이 목표
- **저수준 특징**: 선, 점, 색상
- **고수준 특징**: 눈, 코, 바퀴, 창문
- **최종 특징**: 고양이 얼굴, 자동차 등 오브젝트 수준

> 우리의 목표는, 특징을 가장 잘 뽑아내는 필터를 찾는 것 — **"최적의 도장을 찾아라!"**

### 이미지 데이터를 FCN으로 구현할 경우의 문제

- 이미지의 **2차원 행렬 성질이 전혀 반영되지 못함** (위에서 다룬 한계와 동일)

### 주요 개념 정리

| 개념 | 설명 |
|------|------|
| **입력 데이터** | 2차원 숫자 격자 3장 (R, G, B) |
| **필터(커널)** | 특징을 찾아내는 정방형 행렬. 학습 대상. 예: 수직선을 감지하는 필터는, 수직 방향의 값은 높게, 수평 방향의 값은 낮게 하는 가중치를 가짐 |
| **특징 맵(Feature Map)** | 필터가 이미지를 훑고 지나간 결과물. 커널이 찾으려는 특징이 이미지의 특정 위치에 강하게 나타날수록, 해당 위치의 값이 커짐 |

**전체 흐름**: 합성곱 → 활성화 → 풀링 (반복) → 평탄화 → 완전연결층 → 출력

- **특징 추출부**: "무엇이 보이는가"
- **분류부**: "그래서 무엇인가"

**오늘 실습 파이프라인**

2. **모델 설계**: 합성곱(Convolution)과 풀링(Pooling) 레이어를 포함한 CNN 모델의 설계도를 직접 코드로 작성
3. **손실 함수 & 옵티마이저 정의**: 모델의 '오답 노트' 역할을 할 손실 함수와, '똑똑한 수정 도구'인 옵티마이저를 설정
4. **모델 학습**: 준비된 데이터를 모델에 반복적으로 보여주며 가중치를 업데이트
5. **모델 평가**: 학습이 끝난 모델이 처음 보는 테스트 데이터에 대해 얼마나 정확하게 분류하는지 성능을 확인

## 4. CNN 모델 구현 — 코드로 보기

### 모델 구조

```python
import torch.nn as nn
import torch.nn.functional as F

class Net(nn.Module):
    def __init__(self):
        super(Net, self).__init__()
        self.conv1 = nn.Conv2d(3, 6, 5)     # 3채널 입력 -> 6채널 출력, 5x5 필터
        self.pool = nn.MaxPool2d(2, 2)      # 2x2 영역에서 최댓값만 남김
        self.conv2 = nn.Conv2d(6, 16, 5)    # 6채널 입력 -> 16채널 출력
        self.fc1 = nn.Linear(16 * 5 * 5, 120)
        self.fc2 = nn.Linear(120, 84)
        self.fc3 = nn.Linear(84, 10)        # 최종 10개 클래스

    def forward(self, x):
        x = self.pool(F.relu(self.conv1(x)))   # Conv1 -> ReLU -> Pool
        x = self.pool(F.relu(self.conv2(x)))   # Conv2 -> ReLU -> Pool
        x = torch.flatten(x, 1)                # 평탄화 (배치 차원은 유지)
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        x = self.fc3(x)
        return x

net = Net()
```

### 출력 크기 계산 — `16 * 5 * 5`는 어디서 왔나

**공식** (패딩 없음, stride 1 기준): `출력 크기 = 입력 크기 − 커널 크기 + 1`

| 단계 | 연산 | 크기 변화 | 계산 |
|------|------|-----------|------|
| 입력 | — | 3×32×32 | 원본 |
| conv1 | Conv2d(3,6,5) | 6×28×28 | 32−5+1=28 |
| pool | MaxPool2d(2,2) | 6×14×14 | 28÷2=14 |
| conv2 | Conv2d(6,16,5) | 16×10×10 | 14−5+1=10 |
| pool | MaxPool2d(2,2) | 16×5×5 | 10÷2=5 |
| flatten | — | 400 | 16×5×5=400 |

→ 그래서 `nn.Linear(400, 120)` (즉 16×5×5)

> ⚠️ **초보자가 가장 많이 만나는 에러**: `RuntimeError: mat1 and mat2 shapes cannot be multiplied` — Flatten 후의 크기와 `nn.Linear`의 입력 크기가 안 맞을 때 발생. 표처럼 단계별로 직접 계산하거나, `forward` 안에 `print(x.shape)`를 넣어서 실제 크기를 확인하면 해결할 수 있음
>
> 📌 `padding`을 쓰면 크기가 줄지 않음 (`nn.Conv2d(3,6,5,padding=2)`: 32→32 유지). 요즘 모델들은 대부분 Conv 층에서는 padding으로 크기를 유지하고, **풀링에서만** 크기를 줄이는 방식을 씀

## 5. 풀링 (Pooling)

- 합성곱 연산을 통해 얻은 특징맵의 크기를 줄이는 **다운샘플링** 과정

**목적**
- 다음 계층에서 처리해야 할 **파라미터 수를 감소**
- **과적합 방지**: 중요한 특징만 남기고, 사소한 변화는 무시 — 모델이 이미지의 미세한 노이즈나 위치 변화에 과도하게 민감해지는 것을 방지

**맥스 풀링(Max Pooling)**
- 모든 격자를 2×2로 나눠서, **하나(최댓값)만 남기고 나머지 3개를 버림**

**애버리지 풀링(Average Pooling)**
- 쓰이긴 하지만, 평균을 내는 과정에서 **신호가 희석됨**

### 계층적 특징 추출

- 단순한 패턴에서 복잡한 패턴으로 — 이미지 인식에 강력함
- 특징을 추출하고 분류하기 위해, 마지막에 **플래튼**한 뒤 10개의 클래스로 변환

## 6. 학습 및 평가

### 손실 함수와 옵티마이저

```python
criterion = nn.CrossEntropyLoss()
optimizer = optim.SGD(net.parameters(), lr=0.001, momentum=0.9)
```

- 분류 문제이므로 **교차 엔트로피 손실**
- **모멘텀(momentum)을 가진 SGD** 옵티마이저 사용

### 학습 루프 (5줄 — MLP와 동일)

```python
optimizer.zero_grad()              #    기울기 초기화
outputs = net(inputs)              # ① 순전파
loss = criterion(outputs, labels)  # ② 손실 계산
loss.backward()                    # ③ 역전파
optimizer.step()                   # ④ 가중치 업데이트
```

> CNN이든 MLP든 트랜스포머든, 이 학습 루프는 동일함 — 오늘 바뀐 것은 `net`의 **내부 구조**뿐

### 실제 학습 결과 (CIFAR-10, 2 에포크, batch_size=4)

- 초기 손실값은 약 2.3 근처에서 시작 (10개 클래스에 균등하게 0.1씩 확률을 줬을 때: −ln(0.1) ≈ 2.303)
- 2 에포크 학습 후 손실이 꾸준히 감소 (2.21 → 1.28 부근)
- **테스트 정확도: 약 55%** (참고: 순수 무작위 찍기는 10%)

**클래스별 정확도 (일부 발췌)**

| 클래스 | 정확도 |
|--------|--------|
| plane | 43.5% |
| car | 78.4% |
| bird | 35.4% |
| cat | 38.3% |
| ship | 80.3% |

> 자동차·배·트럭처럼 **형태가 뚜렷하고 배경이 단순한 클래스**는 정확도가 높고, 고양이·개·사슴처럼 **서로 비슷하게 생기고 자세가 다양한 클래스**는 정확도가 낮은 경향

## 7. 전이 학습 (Transfer Learning)

**질문들**
- 남이 만든 모델을 가져다 쓰는 게 왜 "반칙"이 아닌가?
- 무엇을 가져오고, 무엇을 새로 만드는가?
- 미세조정(fine-tuning)은 왜 학습률을 낮춰야 하는가?

### 왜 처음부터 학습하지 않는가

- 완벽하게 고양이를 구분하는 모델을 처음부터 만들려면: 방대한 데이터(수백만 장), 많은 컴퓨터 자원, 오랜 시간이 필요 — 게다가 **느린 수렴 시간, 과적합 위험**(데이터를 암기해버림), **로컬 미니마**에 빠질 위험도 있음
- 바닥부터 시작하면 오래 걸림!

**해결책**: 대규모 데이터셋으로 **이미 학습된 모델의 가중치**를, 새로운 모델에 가져다 활용하자
- **이미지넷(ImageNet)**: 세계에서 가장 크고 유명한 이미지 데이터베이스

**이미 학습된 지식을 빌려와도 문제가 없나?**

- CNN이 학습하는 **저수준 특징(선, 모서리, 질감, 색 변화를 찾아내는 능력)**은, 무엇을 하든(어떤 대상을 분류하든) **똑같이 필요한 매우 범용적인 공통 지식**
- 그래서 **학습된 지식(특징 추출부)은 건드리지 않고, 출력하는 부분(분류부)만** 용도에 맞게 고쳐서 활용할 수 있음

> **비유**: A는 이탈리아어를 유창하게 하는 상태에서 스페인어를 배우기 vs B는 (모국어 없이) 스페인어를 처음부터 배우기 — 문법 구조, 어휘의 뿌리, 발음 감각을 이미 갖춘 A가 훨씬 빠르게 배움. 전이학습이 바로 이것.

### 전이학습의 두 가지 방식

**① 특징 추출 (Feature Extraction / 리니어 프로빙, Linear Probing)**

- 합성곱과 풀링(특징 추출부)은 **그대로 빌려오고**, 마지막 **선형 분류기(Linear classifier)만 새로 닮**
- 새로 만드는 분류층만 학습하므로, 학습할 양이 매우 적어 **압도적으로 빠름**
- **적은 데이터**로도 가능, 성능의 **베이스라인**으로 활용
- 위쪽(특징 추출부) 컨브층은 얼리고(freeze), 마지막 층만 (예: 512 → 10) 교체

**언제 쓰나**: 학습 데이터가 아주 적어서, 잘못 건드리면 빌려온 모델을 망가뜨릴 것 같을 때

**② 미세조정 (Fine-tuning)**

- **고정했던 특징 추출부까지 포함**해서, 모델 전체를 다시 학습
- 내 데이터에 최적화되므로 **최고의 학습 성능**을 낼 수 있음
- 다만, 기존 지식을 잃어버리면 안 되므로 **조심해서** 진행해야 함
- 특징 추출부까지 학습하되, **학습률을 매우 낮게** 설정해야 함
  - 학습률이 높으면, 기존 가중치를 순식간에 파괴해버려서 성능이 급락할 수 있음 (**파괴적 망각**)
- 기존 성능이 이미 좋은데도 왜 파인튜닝을 할까? → **우리 데이터만의 특수한 질감·형태**에 더 예민하게 반응하도록 만들기 위해서

### 언제 어떤 방식을 쓸까

| 상황 | 방식 |
|------|------|
| 데이터 적음 + 원본과 비슷 | 리니어 프로빙 |
| 데이터 많음 + 원본과 다름 | 파인튜닝 |
| 데이터 적음 + 원본과 다름 | 리니어 프로빙으로 시작해서, 조금씩 풀어보기 (LP → FT) |

> 실무에서 흔한 순서: **LP(Linear Probing) → FT(Fine-Tuning)**

## 8. 전이학습 실습 — 코드와 결과

### 데이터를 사전학습 모델(ImageNet)에 맞추기

- **이미지 크기**: ImageNet 모델은 224×224 기준 → CIFAR-10(32×32)은 **Resize 필요**
- **정규화 값**: 우리가 쓰던 0.5/0.5가 아니라, **ImageNet의 평균/표준편차**로 맞춰야 함

```python
transforms.Normalize(mean=[0.485, 0.456, 0.406],   # ImageNet 표준 평균
                     std=[0.229, 0.224, 0.225])    # ImageNet 표준 표준편차
```

### 모델 준비 코드 (ResNet18 기반)

```python
def build_resnet18(freeze):
    # 1. 사전학습된 ResNet18 불러오기 (ImageNet 가중치 포함)
    model = models.resnet18(weights='IMAGENET1K_V1')

    # 2. 특징 추출부를 얼린다 (freeze=True일 때만)
    if freeze:
        for param in model.parameters():
            param.requires_grad = False

    # 3. 마지막 분류층을 우리 문제(10개 클래스)에 맞게 교체
    num_features = model.fc.in_features      # ResNet18은 512
    model.fc = nn.Linear(num_features, 10)   # 1000종 -> 10종

    return model.to(device)
```

> `requires_grad = False`로 설정하면, 그 층의 기울기를 계산하지 않음 → 옵티마이저가 업데이트할 것도 없으므로 값이 그대로 유지됨. 사전학습 모델이 애써 배운 "선과 모서리를 찾는 능력"을 건드리지 않고 보존하는 방법

### 실습 결과 비교 (CIFAR-10 5,000장, 128×128, 1 에포크)

| 방식 | 학습 가능 파라미터 | 학습률 | 테스트 정확도 |
|------|----------------------|--------|------------------|
| **특징 추출(Linear Probing)** | 5,130개 (전체 1,100만 개 중 극히 일부) | 0.01 | **74.6%** |
| **미세조정(Fine-tuning)** | 11,181,642개 (전체) | 0.001 (10배 낮춤) | **80.6%** |

> 참고: 직접 처음부터(맨바닥) 만든 작은 CNN은 (더 오래 학습해도) 50~60% 수준이었음 — 전이학습을 쓰니 단 1 에포크만으로도 훨씬 좋은 성능이 나옴

## 9. 전이학습에서 반드시 지켜야 할 3가지

**① 입력 전처리를 사전학습 모델에 맞춘다**

```python
transforms.Resize(IMG_SIZE)
transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
```

- 앞 실습의 `Normalize((0.5,0.5,0.5),(0.5,0.5,0.5))`를 그대로 쓰면 성능이 크게 떨어짐 — 모델이 학습된 방식과 같은 방식으로 데이터를 넣어야 함

**② 마지막 층은 반드시 교체한다**

```python
model.fc = nn.Linear(model.fc.in_features, 10)   # 1000종 -> 10종
```

- 교체하지 않으면 출력이 1,000개로 나와서 `CrossEntropyLoss`에서 오류가 남

**③ 옵티마이저는 모델 수정 후에 만든다**

```python
model.fc = nn.Linear(512, 10)                     # 먼저 층을 교체하고
optimizer = optim.SGD(model.parameters(), ...)    # 그다음 옵티마이저 생성
```

> 순서가 바뀌면, 옵티마이저가 **옛날 층**을 붙잡고 있어서 새 층이 학습되지 않음 (모델을 새로 만들거나 수정하면, 옵티마이저도 반드시 다시 만들어야 하는 것과 같은 이유)

## 10. 모델 성능 향상 기법

### 데이터 증강 (Data Augmentation)

- 회전 / 자르기 / 뒤집기 등의 변환을 줘서, 데이터의 다양성을 **인위적으로 높이는** 기법
- 모델은 매번 조금씩 다른 이미지를 보게 되므로, **사물의 본질적인 특징**을 학습하게 됨

| 증강 없음 | 증강 있음 |
|-----------|-----------|
| 100번 거의 똑같은 고양이 사진을 봄 → 데이터를 "외워버림" | 매번 조금씩 다른 모습을 봄 → 데이터의 "본질"을 배움 |

**효과**
- 일반화 성능 향상
- 과적합 방지
- 부족한 데이터 보강

**단점**
1. **데이터의 본질을 훼손**할 수 있음 — 예: 숫자 "6"을 상하로 뒤집으면 "9"가 되어버림
2. 학습 난이도와 시간이 늘어남

> ⚠️ **의미를 훼손하는 증강은 사용하지 말 것** — 예: 글자·숫자 데이터에는 좌우 반전을 쓰면 안 됨
>
> ⚠️ **증강은 학습(train) 데이터에만 적용** — 테스트(평가) 데이터는 원본 그대로 사용해야 공정한 평가가 됨

**코드 예시**
```python
train_transform = transforms.Compose([
    transforms.RandomHorizontalFlip(),      # 좌우 반전
    transforms.RandomCrop(32, padding=4),   # 살짝 잘라내기
    transforms.ToTensor(),
    transforms.Normalize((0.5, 0.5, 0.5), (0.5, 0.5, 0.5)),
])
```

## 11. 학습률 스케줄러

- 학습 초반엔 학습률을 **크게**, 에포크가 지나면서 **동적으로 조정**해서 후반에는 **작게**
- 비유: **멀 때는 뛰어가고, 가까워지면 기어간다**

**대표적인 방식**
- **스텝LR(StepLR)**: 에포크마다 고정된 비율로 감소 — 구현이 쉽고 직관적
- **코사인 애닐링LR(Cosine Annealing LR)** 등

**효과**
- 세밀한 손실 감소
- 성능 극대화와 안정적인 학습

**주의점 — 또 다른 "파라미터 지옥"**
- 스케줄러 자체가 **또 다른 하이퍼파라미터**를 추가하는 셈
- 설정이 조금만 어긋나도, 모델이 충분히 학습되지 않거나 너무 느리게 수렴할 수 있음
- **성급한 학습 종료**, **범용성 부족**(일반적으로 통하는 정답 조합이 없어서, 엔지니어의 경험과 감각이 많이 필요함) 등의 어려움이 있음

**옵티마이저 vs LR 스케줄러의 역할 차이**
- **옵티마이저**: "어느 방향으로, 어떻게 움직일까?"
- **LR 스케줄러**: "지금이 속도를 줄여야 할 때인가?"

> `[개인 메모 · 시험범위 아님]` (실무적인 개인 의견) 대충 학습을 돌리다가, 손실이 횡보(정체)할 때 강제 종료하고, 학습률을 낮춰서 체크포인트(ckpt)에서 다시 이어가는 방식이 낫지 않을까 — 하이퍼파라미터가 폭발해버리면 머리 아프니까.

## 12. 전이학습의 한계

- **원본과 완전히 다른 도메인**(예: 의료 영상, 위성 사진 등)이면, 전이학습의 효과가 제한적일 수 있음
- 사전학습 모델의 **편향(bias)까지 함께 가져옴** (원본 데이터의 편향이 그대로 전이될 수 있음)
- **라이선스 확인 필수** — 모델마다 **상업적 이용 조건**이 다름

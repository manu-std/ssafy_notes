## 1. 학습 전략의 중요성

**모델 구조만으로는 부족하다**

- 좋은 구조(architecture)만으로는 성능을 보장할 수 없음
- **동일한 구조, 동일한 데이터셋**을 사용해도, 학습 과정에 따라 **성능 차이가 크게 날 수 있음**
- 학습 과정에서 발생하는 **불안정성, 과적합, 수렴 속도** 문제 때문

**학습에서 자주 겪는 문제들**

| 문제 | 설명 |
|------|------|
| **학습 불안정** | 손실 폭발, 학습 멈춤, 수렴 실패 |
| **과적합** | 훈련 데이터에는 잘 맞지만, 검증·실전 성능이 저하됨 |
| **느린 수렴** | 최적점에 도달하기까지 불필요하게 많은 에폭을 소모 → 학습 효율 저하 |

**학습 전략에 포함되는 요소들**

- 초기화 방법, 학습률 스케줄링, 정규화, 데이터 전처리 등

> **좋은 구조만으로는 충분하지 않다 — 좋은 훈련 전략이 반드시 필요하다.**

## 2. 모델 구성 — "악마는 디테일에" (활성화 함수 선택)

### 활성화 함수가 필요한 이유

- 신경망에 **비선형성(non-linearity)**을 부여해서, 복잡한 패턴을 학습할 수 있게 함
- 복잡한 패턴은 (활성화 함수 없이는) 선형 분류만으로는 표현이 불가능함

**대표적인 활성화 함수**: ReLU, Sigmoid, Tanh, Leaky ReLU 등

### Sigmoid

- 출력을 **0~1 사이의 값**으로 제어 → **확률처럼 해석 가능**
- 이진 분류 문제에서, "이 클래스일 확률"로 활용 가능

**Sigmoid의 문제점**

- 입력이 매우 크거나 매우 작으면, 출력이 거의 **0 또는 1로 고정(포화, saturate)**됨 → 그 지점에서는 더 이상 역전파 신호가 전달되지 않음 (기울기 ≈ 0)
  - (역전파: 정답과 예측의 차이를 모델에 전달하며 가중치를 수정하는 과정)
- 출력 범위가 **항상 양수(0~1)** → 편향된(bias 방향으로 치우친) 업데이트가 발생할 수 있음
- 연산에 **지수(exp) 함수**가 들어감 — 초월함수 연산은 상대적으로 계산 비용이 비쌈

> `[개인 메모 · 시험범위 아님]` 질문: "선을 꺾는다, 면을 꺾어 쌓는다"는 컨셉을 잘 생각해보면, 오히려 내가 원하는 부분만 제어할 수 있는(나머지 구간은 기울기가 0인) 함수가, "제어"라는 측면에서는 ReLU보다 컨셉상 유리하지 않은지?
>
> **답변**
>
> 좋은 질문이고, 절반은 맞는 직관이다. 실제로 시그모이드처럼 **양쪽 끝이 모두 평평(포화)한 함수**는, "이 뉴런은 특정 구간에서만 반응하고, 그 바깥에서는 값이 거의 고정된다"는 의미에서 확실히 더 "국소적으로 제어된(localized, bounded)" 반응을 만들어낼 수 있다. 실제로 이런 성질이 **정확히 필요한 곳**도 있다 — 예를 들어 지난 시간에 배운 **LSTM의 게이트**들이 시그모이드를 쓰는 이유가 바로 이것이다. 게이트는 "0(완전히 막음)부터 1(완전히 통과)까지의 제한된 범위 안에서, 정보를 얼마나 통과시킬지"를 결정해야 하므로, 값이 반드시 0~1 사이로 **엄격히 제한(bounded)**되어야 하는 용도에는 시그모이드가 딱 맞는다.
>
> 하지만 **깊은 신경망의 은닉층 활성화 함수**로 반복해서 쌓아 쓸 때는 얘기가 달라진다. 핵심은 "값을 제어(bound)하는 것" 자체보다, **"역전파로 기울기가 여러 층을 무사히 통과해서 전달되는가"**가 훨씬 더 중요하다는 점이다.
>
> - 시그모이드는 **양쪽(매우 작을 때 + 매우 클 때) 모두** 포화되어 기울기가 0에 가까워진다. 즉 기울기가 죽는(사라지는) "위험 구간"이 **두 군데**나 있는 셈이다.
> - 반면 ReLU는 입력이 양수인 구간에서는 기울기가 항상 정확히 **1**로 유지되고, 포화되지 않는다 — "위험 구간"이 음수 쪽 **한 군데**뿐이다.
> - 신경망이 깊어질수록, 각 층에서 기울기가 살아있어야 전체 사슬(chain)을 통해 맨 앞 층까지 학습 신호가 전달될 수 있는데, 시그모이드처럼 포화 구간이 넓고 양쪽에 있는 함수를 계속 쌓으면, 층을 거칠 때마다 기울기가 0에 가까워질 확률(위험)이 누적되어 급격히 커진다 — 이것이 앞서 배운 기울기 소실 문제의 근본 원인이다.
> - ReLU가 "원하는 부분만 제어하지 못하고, 양수 쪽은 무한정 그대로 흘려보낸다"는 점이 오히려 장점으로 작용한다 — 그 구간에서는 기울기가 절대 줄어들지 않기 때문에, 아무리 층을 깊게 쌓아도 기울기가 안정적으로 전달된다.
>
> 정리하면: **"내가 원하는 범위만 제어하고 싶다"는 목적 자체에는 시그모이드가 개념적으로 더 적합한 것이 맞다** (그래서 게이트에 쓰인다). 하지만 **"수십~수백 층을 깊게 쌓아 학습시켜야 하는 은닉층 활성화 함수"라는 목적에는, 그 "양쪽 제어(이중 포화)"가 오히려 기울기 전달을 방해하는 치명적인 단점이 되기 때문에 ReLU가 선호되는 것**이다. 즉 두 함수 모두 "맞는 자리"가 다를 뿐, 어느 하나가 절대적으로 우월한 게 아니다.

### Tanh (하이퍼볼릭 탄젠트)

- 시그모이드와 비슷하지만, **음수 값도 출력**할 수 있음 (범위: −1~1)
- 하지만 여전히 양쪽 끝에서 포화됨 → **기울기 소실 문제가 여전히 존재**

### ReLU

- **양의 영역에서는 포화되지 않음** — 시그모이드·Tanh처럼 기울기 소실 문제가 크게 줄어듦
- 계산 효율성이 높고, 학습 속도가 빠름
- 단점: 입력이 음수이면 항상 0만 출력 → **"죽은 뉴런(Dead ReLU)"** 문제 발생 가능

### Leaky ReLU

- ReLU의 모든 장점을 그대로 수용
- **"죽지 않는 뉴런"**: 음수 입력에도 아주 작은 기울기를 부여해서, 뉴런이 완전히 죽어버리지 않게 함
- 다만 음수 영역의 기울기 값(예: 0.01)을 **어떤 기준으로 정할지가 다소 임의적**임
- 실제로는 일반 ReLU보다 **항상 우세하지는 않음** — 성능 차이가 거의 없는 경우가 많음

### ELU (Exponential Linear Unit)

- 평균 출력이 **0 근처**에 가까워짐
- 음수 영역에서 **포화 구간(값이 서서히 특정 값에 수렴)**을 제공

> `[개인 메모 · 시험범위 아님]` ELU는 (ReLU의 x=0 지점에서의 뾰족한 꺾임과 달리) 도함수의 미분 불가능성 문제도 함께 없앴다는 특징이 있음

- 다만 `exp`(지수) 연산을 사용하기 때문에, 계산이 더 복잡해짐

### 결론 — 실무에서는 어떻게 선택할까?

- **크게 고민하지 말고 ReLU를 쓰면 됨** — ReLU가 기본적으로 좋은 선택
- 아주 미세한 성능 차이가 필요하다면, ReLU의 개선판들(Leaky ReLU, SELU, ELU, GELU 등)을 시도해볼 수 있음
- **시그모이드나 Tanh**는 (은닉층 활성화 함수로는) 이제 "전문가의 영역" — 게이트처럼 **특수한 아키텍처**에는 여전히 잘 맞음 (고수들이 의도적으로 쓰는 경우)

## 3. 데이터 전처리

### 형식 통일

- 이미지 데이터의 조건을 **일치**시켜야 함 (학습/검증/테스트 데이터 모두에 **동일하게** 적용)
- 일반적인 정규화 방식: **평균 0, 표준편차 1**로 맞추는 것
- 이 전처리가 성능에 미치는 영향이 상당히 큼

**이미지 조건 일치의 예시**
- 색상 채널 통일 (예: 3채널로 통일)
- 모델 입력 크기 고정

**모델별로 전처리 방식이 달랐던 사례**
- **AlexNet**: 이미지에서 (데이터셋) 평균 이미지를 빼는 방식을 사용
- **VGGNet**: 채널별 평균을 빼고, 채널별 표준편차로도 나눠주는 방식을 사용

## 4. 모델 상수(파라미터) 초기화

### 아이디어 1 — 모든 가중치를 0으로 초기화하면?

- 모든 가중치와 편향을 **동일한 값(0)으로 초기화**하면 → **학습이 전혀 일어나지 않음** (지난 시간에 배운 대칭성 붕괴 문제와 동일한 이유)

### 아이디어 2 — 랜덤 초기화

- 아주 작은 값들로, **가우시안(정규) 분포**를 따르도록(0을 중심으로) 랜덤 초기화
- **문제**: 모델이 깊어지면?
  - 초반 레이어에서는 괜찮아 보이지만, 레이어를 거칠수록 **기울기가 0으로 수렴**함
  - 만약 초기 상수(값)를 좀 더 크게 잡으면, 이번엔 반대로 **기울기가 폭발**함

### 자비에르(Xavier) 초기화

- 가중치 초기 분포의 **분산을, 입력 차원(뉴런 수)에 맞춰서** 설정: **std = 1/√dim**
- 분산을 입력 차원 증가를 고려해서 설계함
- 모델 상수의 분산이 입력 차원과 관련되도록 설계하면, **선형 연산 이후 출력의 분산 = 입력의 분산**임을 수학적으로 보일 수 있음

**실험 결과 (레이어를 거치며 분산이 어떻게 유지되는지)**

| 레이어 | 평균(mean) | 표준편차(std) |
|--------|------------|-----------------|
| Layer 1 | ≈ 0.00 | 0.63 |
| Layer 2 | ≈ 0.00 | 0.49 |
| Layer 3 | ≈ 0.00 | 0.41 |
| Layer 4 | ≈ 0.00 | 0.36 |
| Layer 5 | ≈ 0.00 | 0.32 |
| Layer 6 | ≈ 0.00 | 0.30 |

> 자비에르 초기화 없이 단순 랜덤 초기화만 쓰면, 레이어를 거칠수록 값들의 분포가 왜곡되며 표준편차가 무너지는 경향을 보이는데, 자비에르 초기화를 적용하면 레이어를 거듭해도 분산이 비교적 완만하게(붕괴하지 않고) 유지되는 경향을 보임

### 자비에르 초기화 + ReLU — 궁합 문제

- **ReLU를 쓰면 자비에르 초기화가 잘 안 맞음**
- 이유: 입출력 분산을 맞추는 자비에르 초기화 전략은, **입출력이 대칭적인 분포**를 보인다는 가정 하에 설계된 것
- 그런데 **ReLU는 음수를 전부 0으로 만들어버려서, 양의 값만 남기는 비대칭적인 함수**임 → 자비에르의 가정이 깨짐

### 허(He) 초기화

- 가중치 초기 분포의 분산을 **2 × 입력 차원**에 맞춰서 설정: **std = √(2/dim)**
- **비대칭적인 분포에서도 분산이 유지**되도록 설계됨
- **결론: ReLU를 쓴다면 He 초기화를 쓰자**

### ResNet에서의 초기화 전략

- ResNet은 **잔차 연결(residual connection)**을 사용해서, 매우 깊은 신경망도 학습이 잘 되도록 설계됨
- **ResNet의 철학**: "전(全) 층에 기울기를 전달하자"
- 스킵 커넥션(skip connection)을 통해, 입력이 그대로 더해지기 때문에, **깊은 층에서도 기울기가 끊기지 않고 전달**됨
- **초반에 초기화가 잘못되면**, 후반 층으로 갈수록 출력 분포 값이 계속 증폭될 수 있음

**ResNet의 실제 초기화 방식**
- ResNet은 ReLU를 사용하는 구조이므로, 기본적으로 **He 초기화**를 사용
- 잔차 블록 안에서, **첫 번째 컨볼루션**은 He 초기화를 사용
- **두 번째 컨볼루션은 0으로 초기화**

> 이렇게 하면, 학습 초반에는 (두 번째 컨볼루션이 0이라서) **사실상 스킵 커넥션(입력을 그대로 통과시키는 경로)에만 의존**하게 되어, 안정적인 학습을 유도할 수 있음
>
> 즉 학습 초기에는 "입력 = 출력" 형태로 분포가 안정적으로 시작되기 때문에, **학습이 안전하게 출발**할 수 있게 됨

## 5. 모델 정규화(규제, Regularization)

### 정규화가 필요한 신호

- 학습이 진행되는 동안, **훈련(train) 오차는 계속 줄어드는데, 검증(validation) 오차는 오히려 늘어난다면** → 이것이 바로 **정규화가 필요하다는 신호**

### 정규화의 목적

- 학습 과정에서 **특정 가중치가 지나치게 커지는 현상을 방지**
- 가중치가 너무 크면, 특정 입력에 과도하게 반응하게 됨 → 결국 **훈련 데이터를 "외워버리는"** 상태(과적합)가 됨
- **방법**: 가중치 크기에 비례한 **패널티(penalty)**를 손실함수에 추가
- 직관: **"큰 가중치는 과적합을 부른다 — 그러니 줄여주자"**

**만약 가중치 감소(패널티)를 극단적으로/완벽하게 만족시킨다면?**

- 모든 가중치가 0인 모델은, 사실상 **"아무것도 하지 않는 모델"**
- 규제(패널티) 항목 그 자체만 단독으로 쓰이면 의미가 없고, **원본(본래) 모델의 학습 목표(정확도를 높이는 것)와 함께 작동**할 때에만 의미가 있음
- 즉 목표는: **훈련 오차를 줄이면서, 동시에 가중치도 적당히 작게 유지**하는 것 (두 목표의 균형)

### L2 정규화 (릿지, Ridge / Weight Decay)

- 큰 가중치에 대해 **제곱(²)으로 패널티**를 부여 → 극단적으로 큰 값을 강하게 억제

### L1 정규화 (라쏘, Lasso)

- 가중치 크기에 상관없이 **절댓값으로 동일하게** 패널티를 부여
- **중요하지 않은 가중치는 완전히 0**으로 만들어버림 (희소성, sparsity)
- 자동으로 **중요한 특성만 선택**하게 되어, 더 단순한 모델을 만들 수 있음
- 상수(파라미터)의 희소성이 가능하다면, **더 작은 모델을 선호**한다는 철학
- → 실무에서 **L1 정규화가 많이 사용됨**

### 엘라스틱 넷 (Elastic Net)

- L1과 L2 정규화를 **섞어서 함께 사용**하는 방식

## 6. 드롭아웃 (Dropout) — 복습

- 학습 과정에서 **일부 뉴런을 확률적으로 꺼버림**
- 매 학습 스텝마다, **다른(부분) 네트워크 구조가 샘플링되는 효과**
- "너는 이 뉴런 없이도 좋은 결과를 내야 해!"라는 식으로 강제함으로써, **과적합을 방지**함
- 여러 개의 작은 모델을 합친 **앙상블(ensemble) 방식**과 유사한 효과

**드롭아웃 사용처**
- **CNN에는 잘 안 쓰고, FCN(완전연결층)에 주로 사용**됨
- **배치 정규화(Batch Normalization)가 이미 적용된 모델에서는 비선호**됨 — 배치 정규화 자체가 이미 강력한 정규화 효과를 제공하기 때문

**드롭아웃 사용 시 주의점**

- **테스트(추론) 시에는 뉴런을 전부 사용**함 (드롭아웃 끄기)
- 학습과 테스트의 "프로토콜"이 다르기 때문에, 그냥 두면 테스트 시 출력 값의 스케일이 학습 때와 달라짐(대략 2배 차이가 날 수 있음)
- 해결책: **학습 시, 살아남은 뉴런들의 출력을 1/(1−p) 배로 스케일링**해서, 학습/테스트 간 기댓값이 일치하도록 보정함

## 7. 학습 안정성 — 학습률(Learning Rate) 설정

- **학습률(Learning Rate)은 가장 중요한 하이퍼파라미터**
- 같은 모델, 같은 전처리, 같은 모듈을 사용해도, **학습률에 따라 완전히 다른 결과**가 나올 수 있음
- 잘못된 학습률 선택으로 인해, **학습이 완전히 실패**할 수도 있음

**기본 전략**: 큰 값으로 시작해서, 에폭이 지날수록 점점 작은 값으로 조정 (학습률을 줄이는 다양한 전략이 존재)

> 좋은 학습률을 사용하면, 손실이 **안정적으로 줄어드는 양상**을 보임

### 학습률 스케줄링 방식들

**① 계단식 감소 (Step Decay)**
- 일정 에폭이 지날 때마다, 학습률을 **계단식으로 감소**시키는 방식
- 정체(plateau) 구간마다 학습률을 낮추는 전략
- 단점: **언제 변경할지(변경 지점) 결정이 불명확**하고, 학습 곡선이 불안정해질 수 있음
- 그럼에도 실무에서 **계단식이 많이 사용됨**

**② 코사인(Cosine) 스케줄링**
- 코사인 파형을 따라서, **천천히** 학습률을 변경
- 직관: 처음엔 크게, 나중엔 작게
- 실무에서 **빈번하게(많이) 사용**되는 방식
- (구체적인 적용은 사람/프로젝트마다 다름)

**③ 선형(Linear) 감소**
- 직선을 따라 학습률을 줄이는 방식
- 이건 (일반적인 처음부터 끝까지의 학습보다는) **사전학습이나 미세조정(fine-tuning)**에 주로 사용됨
- 미세조정은 애초에 (이미 사전학습된 모델을 다루므로) 작은 학습률로 시작해서 작은 학습률로 끝나는 경우가 많아서 선형 감소를 사용

**④ 기타 감소 방식**
- 다양한 형태의 감소 방식이 가능
- **역제곱(Inverse Square Root) 꼴**: 대규모 모델에는 잘 사용되지 않음
- **일정값 유지(Constant)**: 학습 내내 동일한 속도(학습률)로 학습

---

## 8. 학습 종료 — 얼리 스타핑 (복습)

- **얼리 스타핑(Early Stopping)** 기법: 모델을 학습하는 동안, **검증 데이터셋**을 통해 검증 손실을 지속적으로 모니터링
- 학습을 진행하면서, 검증 성능이 더 이상 좋아지지 않고 **오히려 나빠지기 시작**하면 → 학습을 **종료**

## 9. 하이퍼파라미터 선정

| 구분 | 정의 |
|------|------|
| **파라미터** | 모델이 (학습을 통해) 스스로 학습하는 값 |
| **하이퍼파라미터** | 학습을 시작하기 전에, **사람이 직접 정하는 값** |

**대표적인 하이퍼파라미터들**

| 범주 | 세부 항목 |
|------|-----------|
| **학습 관련** | 학습률(가장 중요), 학습률 감소(디케이) 방식, 배치 사이즈(작으면 정규화 효과, 크면 안정성↑), 에폭 수, 조기 종료 여부 |
| **최적화 도구** | SGD, Adam, AdamW, 모멘텀 계수, 가중치 감소(weight decay) |
| **모델 구조** | 네트워크 깊이, 채널 수, 드롭아웃 비율, 정규화 방식(BN, LN, GN 등) |

## 10. 좋은 하이퍼파라미터는 어떻게 찾을까?

### 그리드 서치 (Grid Search) vs 랜덤 탐색 (Random Search)

- **그리드 서치**: 모든 하이퍼파라미터 조합을 격자(grid) 형태로 촘촘히 실험
- **랜덤 탐색**: 하이퍼파라미터 공간에서 **무작위로** 조합을 뽑아서 실험
  - 성능에 크게 영향을 주지 않는 "불필요한 축(하이퍼파라미터)"이 있는 경우, 그 축의 모든 값을 다 실험하지 않아도 되므로, **시간을 낭비하지 않을 수 있음**
- 일반적으로 **랜덤 탐색을 좀 더 선호**함

**모든 조합을 다 실험할 수 없다면?**
- (빅테크 기업조차도) 모든 조합을 다 실험하지는 않음 — 모든 조합을 다 해보려는 건 사실상 비효율적인 접근
- 하이퍼파라미터는 매우 많기 때문에, 그리드 서치만으로 전부 커버하기 어려움
- 몇 가지 **직관과 규칙(경험적 노하우)**을 활용하면, GPU 자원이 많지 않아도 좋은 성능을 이끌어낼 수 있음

## 11. 실전 디버깅 체크리스트 (순서대로)

> 새로운 모델/코드를 학습시킬 때, 아래 순서를 따르면 문제를 효율적으로 진단할 수 있음

### 체크 1 — 데이터 입력에 문제는 없는가? (초기 손실값 확인)

- **초기 손실값**을 반드시 확인할 것
- 분류 문제 등에서 흔히 쓰는 **교차 엔트로피(CE) 손실**이라면, 초기 손실값은 **log(클래스 개수)**와 비슷해야 정상
- 예상치를 크게 벗어난다면 → **데이터 로딩, 라벨링에 문제**가 있을 가능성이 높으므로 확인 필요

### 체크 2 — 작은 샘플로 일부러 과적합시켜보기

- 작은 샘플(적은 데이터)을 활용해서, **일부러 과적합**까지 시켜봄 (정확도 100%까지 학습이 되는지 확인)
- **손실이 줄지 않는다면**, 다음 중 하나에 문제가 있을 가능성:
  - 학습률/초기화 문제
  - 모델 구조의 오류 가능성
  - 활성화 함수 이슈
  - 최적화 도구(옵티마이저) 이슈, 혹은 코드 버그
- 이 테스트를 해보지 않으면, 어디에 문제가 있는지 원인을 알 수 없음

### 체크 3 — 손실이 폭발한다면? (적절한 학습률 찾기)

- 손실이 폭발한다면 → **학습률을 줄이고, 초기화 방법을 변경**해볼 것 (가장 흔한 원인)
- 혹은 **네트워크 깊이가 너무 깊거나**, 구조적인 문제일 수도 있음
- 체크리스트 2에서 확정한 구조와 최적화 도구를 그대로 활용해서, **적절한 학습률**을 찾는 단계
- 모든 학습 데이터를 활용해서, **약 100 이터레이션만** 빠르게 학습시켜 경향을 파악
- 일반적인 탐색 범위: **로그 스케일**로 1e-1, 1e-2, ..., 1e-4 정도까지
- **손실이 실제로 감소하는 학습률**을 사용할 것

### 체크 4 — 후보 학습률/설정 조합 비교

- 체크리스트 3에서 얻은 후보 학습률들과, 가중치 감소(weight decay) 등 다른 설정 조합 중 **좋은 조합을 탐색**
- 위 조합들을 활용해서, **1~5 에폭 정도만** 짧게 학습시켜 성능을 비교
- 모든 조합을 끝까지(전체 에폭) 학습시키는 것은 **연산 자원 낭비**
- 좋은 조합은 보통 **초기 몇 에폭 내에 손실이 확 줄어드는** 경향을 보임
- 이때 확인할 지표는 **트레인 로스가 아니라, 검증(Validation) 로스**임

### 체크 5 — 후보를 좁혀서 10~20 에폭 추가 학습

- 앞 단계에서 좁힌 후보로, **10~20 에폭 정도 추가 학습**
- 이 단계에서는 **학습률 감소(스케줄링)는 적용하지 않음**
- **손실의 이동 평균(moving average)**을 관찰
- **학습 데이터와 검증 데이터를 모두** 확인

### 학습률에 따른 손실 곡선 해석 가이드

- 초반에 **손실값이 그대로 유지**되는 경우 → **초기화 값이 문제**일 가능성 → 학습률을 조정해볼 것
- **검증 정확도가 계속 증가**하는 경우 → 계속 학습을 진행할 것
- **검증 정확도가 떨어지기 시작**하는 경우 → **과적합**의 신호
- **학습/검증 성능 차이가 매우 작다면?** → 모델의 표현력(capacity)이 너무 약한 것일 수 있음 → **더 큰 모델을 도입해서 더 오래 학습**시켜야 함
  - 모델 용량(capacity)을 늘리면, 검증 정확도가 더 오를 여지가 있음을 시사

## 1. Self-Attention

### 1-1. RNN의 한계

**장기 의존성(Long-term Dependency) 문제**
- RNN은 왼쪽에서 오른쪽으로 순차적으로 전개되기 때문에, 멀리 떨어진 두 단어가 서로 상호작용하려면 **시퀀스 길이만큼의 단계를 거쳐야** 함
- 단계가 길어질수록 그만큼 **기울기 소실 또는 폭발(vanishing/exploding gradient)** 문제가 발생해서, 장기 의존성을 학습하기 어려웠음
- 또한 RNN은 입력의 (왼쪽→오른쪽) 선형적인 순서를 강하게 반영하는 구조라는 한계도 있음

**병렬화(Parallelization) 문제**
- RNN은 순전파(forward)와 역전파(backward) 모두 **시퀀스 길이만큼의 단계가 필요**함
- 각 시점의 계산이 이전 시점의 결과에 의존하는 **순차적인 연산**이기 때문에, **병렬화가 불가능**함
- 이는 병렬 연산에 강한 **GPU를 제대로 활용하기 어렵게 만들며**, 대규모 데이터를 학습하는 데 비효율적임

### 1-2. Self-Attention 기본 아이디어

- 이전에 배운 어텐션은 각 단어의 표현을 **쿼리(Query)**로 두고, **밸류(Value) 집합**으로부터 필요한 정보를 직접 불러와 결합하는 방식이었음
- 그렇다면 이 어텐션 메커니즘을, 인코더-디코더 사이가 아니라 **한 문장 내부에서** 적용하면 어떨까? → 이것이 바로 **셀프 어텐션(Self-Attention)**

**Seq2Seq의 Attention vs Self-Attention**

| 구분 | 연결 대상 |
|------|------------|
| **(Seq2Seq) Attention** | 입력 문장 내의 단어들 ↔ 출력 문장 내의 각 단어 |
| **Self-Attention** | (같은) 문장 내의 다른 단어들 ↔ 문장 내의 각 단어 |

**예시**

- "어제 카페 갔었어 거기 사람 많더라"라는 문장에서, "거기"라는 단어를 셀프 어텐션으로 표현할 때 → "카페", "갔었어" 같은 관련 단어들에 강하게 주목(어텐션)함
- 즉 문장 내부의 각 단어가, 문장 내부의 다른 단어들을 살펴보면서 자기 자신을 더 풍부하게(문맥을 반영해서) 표현하게 됨

**셀프 어텐션의 장점**

- 인코딩(혹은 디코딩)을 **모든 위치에 대해 동시에** 수행할 수 있음
- 순차적으로 처리해야 하는 연산 수가, **시퀀스 길이가 늘어나도 (RNN과 달리) 그만큼 증가하지 않음** → 병렬화에 유리

### 1-3. Query, Key, Value

이전 Attention에서는 각 단어를 표현하는 Query와 Value 벡터가 있었다면, Self-Attention에서는 각 단어 i를 표현하는 **Query, Key, Value** 세 종류의 벡터가 각각 존재한다. 이 세 벡터는 각각 학습되는 가중치 행렬 Wq, Wk, Wv를 단어 임베딩 벡터에 곱해서 만들어진다.

| 벡터 | 역할 |
|------|------|
| **쿼리(Query) 벡터** | 단어 i가 (다른 단어들로부터) **어떤 정보를 찾을지**를 표현 |
| **키(Key) 벡터** | 단어 i가 **자신이 가진 정보의 특성**을 표현하는 벡터 (다른 단어들의 쿼리에 "나는 이런 특성을 가진 단어야"라고 응답하는 용도) |
| **밸류(Value) 벡터** | 실제로 참조되는 **정보의 내용**을 담고 있는 벡터 |

> 정리: **Key 벡터**는 어텐션 스코어(유사도 점수)를 계산하기 위한 벡터이고, **Value 벡터**는 그 단어로부터 실제 결과물(출력)을 만들어내기 위한 벡터

**예시로 이해하기**

- "어제"라는 단어가 쿼리로 쓰이면, 문장 안의 (어제를 포함한) 모든 단어가 각자의 Key로 응답하고, 이 둘 사이의 **어텐션 스코어**가 계산됨
- "카페"가 쿼리로 쓰이면, 카페의 Query와 모든 단어의 Key를 곱해서 스코어를 계산하고, Softmax로 확률로 변환한 뒤, 그 확률(가중치)로 모든 단어의 Value를 가중합해서 **카페에 대한 새로운(문맥이 반영된) 벡터**를 만들어냄
  - 예: "어디 갔었어?"라는 맥락이라면, "카페"라는 단어에 높은 가중치가 실림

**수식으로 정리 (i번째 단어의 셀프 어텐션 출력 계산)**

```
1단계 — Query와 Key 사이의 유사도(내적) 계산:
    e(i,j) = qᵢᵀ · kⱼ

2단계 — Softmax로 확률 분포(어텐션 가중치) 계산:
    α(i,j) = exp(e(i,j)) / Σⱼ' exp(e(i,j'))

3단계 — 각 단어의 출력을 Values의 가중합으로 계산:
    oᵢ = Σⱼ α(i,j) · vⱼ
```

- qᵢ: i번째 단어의 Query 벡터
- kⱼ, vⱼ: j번째 단어의 Key, Value 벡터
- α(i,j): i번째 단어가 j번째 단어에 주는 어텐션 가중치 (모든 j에 대해 합이 1)
- oᵢ: i번째 단어의 셀프 어텐션 최종 출력 (문맥이 반영된 새 표현)

**단어 임베딩 벡터의 차원 — 그리고 워드 임베딩의 벡터 연산**

> `[개인 메모 · 시험범위 아님]` 질문: 모든 단어에 대해 512차원 임베딩 벡터가 있다고 하는데, 왜 하필 512차원인지는 설명 안 하심. 그리고 "여왕 − 왕 = 여자 − 남자" 같은 워드 임베딩의 벡터 연산 개념이 있었잖아, 그거 설명해줘.
>
> **답변**
>
> **① 왜 512차원인가?**
> 512라는 숫자 자체에 특별한 수학적 의미가 있는 건 아니다. 원조 트랜스포머 논문("Attention Is All You Need")에서 저자들이 실험적으로 **성능과 계산 비용(메모리·속도) 사이의 균형이 잘 맞는 값**으로 512를 선택했을 뿐이다. 차원이 너무 작으면(예: 64차원) 단어의 다양한 의미를 표현할 "공간"이 부족해서 표현력이 떨어지고, 반대로 너무 크면(예: 4096차원) 파라미터 수가 급격히 늘어나 계산 비용과 메모리 사용량이 커진다. 그래서 512는 여러 하이퍼파라미터 중 하나로, 모델 크기에 따라 다르게 설정되는 값이다 (예: BERT-base는 768차원, GPT-3는 모델 크기에 따라 훨씬 큰 차원도 사용).
>
> **② "여왕 − 왕 = 여자 − 남자" 개념 (워드 임베딩의 벡터 연산, Word Analogy)**
> 이건 워드 임베딩(Word2Vec 같은 기법으로 학습된 단어 벡터)이 갖는 놀라운 특성 중 하나로, 트랜스포머 자체의 개념이라기보다는 **애초에 워드 임베딩이라는 아이디어가 왜 강력한지**를 보여주는 유명한 예시다.
>
> 단어를 벡터 공간에 배치했을 때, 그 공간 안에서 "방향(벡터의 차이)"이 특정한 **의미적 관계**를 나타내는 경우가 있다는 것이 실험적으로 관찰되었다. 예를 들어:
> - vector("왕") − vector("남자") + vector("여자") ≈ vector("여왕")
> - 즉 "왕에서 '남성성'이라는 요소를 빼고, '여성성'을 더하면 여왕이 된다"는 관계가, 벡터의 **덧셈·뺄셈 연산만으로 근사적으로 성립**한다는 뜻
>
> 이게 가능한 이유는, 워드 임베딩이 (Word2Vec의 Skip-gram/CBOW처럼) "주변 문맥에 함께 등장하는 패턴"을 통해 학습되기 때문에, "왕-여왕", "남자-여자"처럼 **비슷한 문맥 패턴을 공유하는 단어 쌍들이, 벡터 공간에서 비슷한 방향과 거리(비슷한 '관계 벡터')를 갖도록 자연스럽게 학습**되기 때문이다. 즉 벡터 공간의 특정 방향이 "성별(gender)"이라는 의미적 축을 어느 정도 포착하게 되는 것이다.
>
> 이 성질을 발견한 것이 바로, 워드 임베딩이 단순한 "단어 → 숫자" 변환을 넘어서 **의미(semantics) 자체를 어느 정도 벡터 공간의 기하학적 구조로 담아낼 수 있다**는 것을 보여준 유명한 사례이며, 이후 워드 임베딩(그리고 그 발전형인 트랜스포머의 임베딩)이 널리 각광받게 된 배경이기도 하다.

### 1-4. Self-Attention의 한계와 해결책

셀프 어텐션은 단어 간 관계를 효율적으로 잡아내는 강력한 메커니즘이지만, 세 가지 한계가 존재한다.

| 한계 | 설명 |
|------|------|
| **1. 순서 정보 부재** | 단어의 유사도만 계산하기 때문에, 단어의 **순서(위치)를 전혀 고려하지 않음** |
| **2. 비선형성 부족** | 어텐션 계산은 본질적으로 **가중 평균(weighted average) 연산**이라는 선형 결합에 불과하기 때문에, 복잡한 패턴이나 깊은 표현력을 담기 어려움 |
| **3. 미래 참조 문제** | 언어 모델은 시퀀스를 왼쪽에서 오른쪽으로 순차 생성해야 하는데, 셀프 어텐션은 모든 단어를 동시에 보기 때문에, **아직 생성되지 않아야 할 미래 단어까지 참조**해버림 |

#### 해결책 1 — 순서 정보 부재 → 포지셔널 인코딩 (Positional Encoding)

- 각 단어의 위치 i를 나타내는 **위치 벡터(position vector)**를 정의해서, 단어 임베딩 값에 **더해준 것**을 입력으로 사용

**대표적인 방법 두 가지**
- **시누소이달 포지션 인코딩 (Sinusoidal Positional Encoding)**: 서로 다른 주기의 사인(sin)·코사인(cos) 함수를 합성해서 위치 벡터를 만드는 방법 (강의에서는 자세한 수식 유도 없이 "이런 방법이 있다" 정도로만 소개됨)
- **런드 앱솔루트 포지션 임베딩(Learned Absolute Position Embedding)**: 위치 벡터 자체를 모두 학습 파라미터로 설정해서, 학습 과정에서 데이터에 맞춰 최적화되도록 하는 방법

> 이보다 더 발전된 기법들도 계속 나오고 있음 — 여기서는 개념만 이해하고 넘어가면 됨

#### 해결책 2 — 비선형성 부족 → 피드포워드 네트워크(FFN) 추가

- 셀프 어텐션 연산 자체에는 비선형 변환이 없어서, 아무리 복잡하게 계산해봐도 결국 **선형 변환**에 불과함
- 그래서 셀프 어텐션 다음에 **피드포워드 네트워크(FFN, Feed-Forward Network)**를 두어, 더 깊고 비선형적인 표현으로 확장함
- FFN은 ReLU 같은 활성화 함수를 사용하며, **같은 모듈(레이어) 안에서는 모든 단어(위치)에 대해 동일한 FFN**을 적용함

> `[개인 메모 · 시험범위 아님]` 질문: FFN이 "모듈(레이어) 안에서는 모든 단어에 동일하게 적용되지만, 다른 모듈(레이어)끼리는 서로 다른 FFN을 쓴다"고 했는데, 그 이유가 뭔지 심도 있게 설명해줘.
>
> **답변**
>
> 이건 두 가지 서로 다른 질문이 섞여 있어서, 나눠서 답하는 게 명확하다.
>
> **① 왜 "같은 레이어 안에서는" 모든 단어(위치)에 똑같은 FFN을 적용하는가?**
>
> 이것을 **위치별 가중치 공유(position-wise weight sharing)**라고 부른다. 이렇게 하는 핵심 이유는 두 가지다.
> - **효율성**: 만약 문장의 각 단어 위치마다 서로 다른 FFN 파라미터를 따로 학습해야 한다면, 파라미터 수가 "문장 길이 × FFN 파라미터 수"만큼 폭발적으로 늘어난다. 게다가 문장 길이는 입력마다 다 다른데(가변 길이), 위치마다 다른 파라미터를 쓴다면 애초에 다른 길이의 문장에 모델을 적용할 수조차 없다.
> - **일관된 변환 로직**: "이 단어가 문장의 3번째에 있든 30번째에 있든, 셀프 어텐션을 거쳐 나온 벡터를 '똑같은 방식으로' 한 번 더 다듬어주고 싶다"는 것이 FFN의 역할이다. 즉 위치와 무관하게 "각 단어 벡터 하나하나에 적용하는 동일한 변환 함수"라는 개념이기 때문에, 같은 파라미터를 재사용하는 것이 자연스럽다. (CNN에서 하나의 필터(커널)를 이미지 전체 위치에 대해 재사용하는 것과 비슷한 아이디어 — "파라미터 공유"를 통해 위치에 무관하게 일관된 특징 추출 로직을 학습한다.)
>
> **② 왜 "다른 레이어(모듈)끼리는" 서로 다른 FFN 파라미터를 쓰는가?**
>
> 트랜스포머는 여러 개의 레이어(블록)를 쌓아서 만든다. 각 레이어를 통과할 때마다, 단어 벡터는 셀프 어텐션 + FFN을 거치며 점점 더 "추상적이고 고차원적인" 정보로 재구성된다. 이는 CNN의 여러 층이 각각 다른 필터를 갖는 것과 같은 이유다: **낮은 레이어는 비교적 단순하고 지역적인 패턴(예: 인접 단어 관계)을 학습**하고, **높은 레이어로 갈수록 더 복잡하고 추상적인 패턴(예: 문장 전체의 의미, 장거리 의존관계)을 학습**하는 경향이 있다. 만약 모든 레이어가 완전히 똑같은 FFN 파라미터를 공유한다면, 레이어를 아무리 많이 쌓아도 매번 "똑같은 변환"만 반복하게 되어, 레이어를 깊게 쌓는 의미(점점 더 추상적인 표현을 학습하는 것)가 사라져버린다. 그래서 각 레이어는 자신만의 독립적인 FFN(그리고 어텐션) 파라미터를 가지고, 레이어를 거칠 때마다 서로 다른 종류의 변환을 학습하도록 설계되어 있다.
>
> 정리하면: **"위치(단어)에 대해서는 공유"**하지만 **"레이어(깊이)에 대해서는 독립적"**이라는 것이 핵심이다 — 이 두 설계 선택이 각각 "효율성/일관성"과 "표현력의 계층적 확장"이라는 서로 다른 목적을 위해 존재한다.

#### 해결책 3 — 미래 참조 문제 → 마스크드 셀프 어텐션 (Masked Self-Attention)

- 단어를 생성할 때는 한 단어씩 순차적으로, 미래 단어를 예측해야 하는데, 셀프 어텐션은 기본적으로 **모든 단어를 동시에 참조**할 수 있음
- **인코딩(Encoder)**에서는 문제없이 모든 단어에 대해 어텐션할 수 있음
- **디코딩(Decoder)**에서는 **현재까지 나온 단어까지만** 어텐션할 수 있어야 함
  - 방법: 아직 나오지 않은(미래) 단어에 대한 어텐션 스코어에 **음의 무한대(−∞)를 입력**해서, Softmax를 취하면 그 값이 **0으로 수렴**하게 만듦 → 신호를 완전히 죽여서, 미래 단어에는 전혀 어텐션이 안 되도록 막는 방식

> 여기서도 이전 Seq2Seq와 마찬가지로 **티처 포싱(Teacher Forcing)**이 이루어짐 — 다만 여기서는 "다음 단어가 무엇인지"만 예측하는 방식으로 이루어짐

### Self-Attention 정리

| 한계 | 해결책 |
|------|--------|
| 순서 정보 부재 | 포지셔널 인코딩(Positional Encoding) |
| 비선형성 부족 | 피드포워드 네트워크(FFN) 추가 |
| 미래 참조 문제 | 마스크드 셀프 어텐션(Masked Self-Attention) |

## 2. Transformer 아키텍처

- **트랜스포머(Transformer)**는 "Attention Is All You Need"라는 논문에서 처음 제안된 아키텍처
- **인코더-디코더(Encoder-Decoder) 구조**로 설계됨
- 기존 Self-Attention과 다른 핵심 차이점: **멀티헤드(Multi-Head)** 어텐션을 사용함

### 2-1. 멀티헤드 어텐션 (Multi-Head Attention)

- 문장에서 같은 단어라도, **여러 이유로 다른 단어에 주목**할 수 있음 (예: 문법적 관계 때문에 주목하는 경우, 의미적 관계 때문에 주목하는 경우 등)
- **단일 셀프 어텐션 헤드**로는, 한 가지 관점에서의 단어 간 관계밖에 파악할 수 없음
- 따라서 **여러 개의 어텐션 헤드**를 두어서, 다양한 관점(다양성)을 동시에 포착함

**구체적인 구현 방식**
- 헤드를 8개 둔다면, 원래 512차원이었던 벡터를 **8개로 쪼개서** 각각 **64차원(512÷8=64)**짜리 벡터로 나눠서 씀
- 헤드마다 서로 다른 관점을 배우기 때문에, 사실상 더 많은 파라미터를 활용하는 효과가 있음
- 즉 512차원 벡터 하나를 8개의 64차원 벡터로 분리해서, **각각 독립적인(분리된) 어텐션 연산**을 수행하는 개념

### 2-2. Scaled Dot-Product Attention

**문제**: Query와 Key의 차원이 커질수록, 두 벡터의 **내적(dot product) 값도 자연스럽게 커짐**. 이 값이 너무 크면 Softmax 함수의 출력이 지나치게 뾰족해져서(하나의 값에 확률이 거의 몰려버려서), 미세한 입력 변화에도 큰 차이가 발생하고, **기울기 소실(gradient vanishing)** 문제가 생길 수 있음

**예시**
- 스케일링 없이: softmax([40, 50, 45]) ≈ [0.000045, 0.99326, 0.00669] — 하나의 값(0.993)에 극단적으로 쏠림
- 스케일링 후 (√(d/h) = 8로 나눔): softmax([5.00, 6.25, 5.625]) ≈ [0.1573, 0.5489, 0.2938] — 훨씬 더 완만한 분포

**해결책**: 내적 값을 그대로 쓰지 않고, **√(d/h)로 나눠서** 스케일을 조정

```
output_l = softmax( XQₗKₗᵀXᵀ / √(d/h) ) × XVₗ
```

- 이렇게 하면 값이 안정적으로 분포되어, 학습이 훨씬 더 빠르고 안정적으로 진행됨
- 목표: Softmax를 극단적으로 뾰족하게 만드는 것을 추구하지 않고, **적당히 뾰족하도록**(즉 적당히 여러 곳에 나눠서 어텐션하도록) 스케일링하는 것

### 2-3. 잔차 연결(Residual Connection)과 레이어 정규화(Layer Normalization)

**잔차 연결(Residual Connection)**
- 레이어(셀프 어텐션, FFN 등)를 통과하지 않은 **원래의 표현(입력)도 함께 더해서 사용**하는 방식

**흥미로운 점**: 단어 임베딩 xᵢ에 위치 임베딩 pᵢ를 더해서 x̂ᵢ = xᵢ + pᵢ 라는 입력을 만드는데, 이 위치 정보는 여러 블록(레이어)을 통과할수록 점점 **희석(약해짐)**되는 경향이 있음
- 잔차 연결을 통해, 매 레이어마다 원래의 (위치 정보를 포함한) 입력을 계속 다시 더해줌으로써, **위치 정보가 깊은 레이어까지 잘 유지되도록 하는 효과**를 냄
- (벡터를 더하면 새로운 벡터가 이전 벡터의 정보를 여전히 포함하는 형태가 되지만, 스칼라를 단순히 더하면 원래의 개별 정보가 사라져버리는 것과 대비되는 개념)

**레이어 정규화(Layer Normalization)**
- 각 레이어의 출력을 정규화해서, 학습을 안정적으로 만들어주는 기법 (잔차 연결과 함께 각 서브레이어 뒤에 적용됨)

### 2-4. 인코더/디코더 구조

**인코더(Encoder) 블록 구성**
- 멀티헤드 어텐션 → 피드포워드 네트워크

**디코더(Decoder) 블록 구성**
- **마스크드 멀티헤드 어텐션**(자기 자신의 이전 출력들에 대해서만 어텐션)
- 이어서, 인코더-디코더 어텐션: 여기서는 **디코더의 아래(이전) 층에서 넘어온 것이 Query**가 되고, **인코더에서 넘어온 것이 Key와 Value**가 됨
- 이어서, 피드포워드 네트워크

### 2-5. Transformer vs RNN — 정보가 흐르는 방식의 차이

- 이전 방법(RNN 등)보다 트랜스포머가 **성능도 좋고, 계산 효율도 좋음**
- 트랜스포머와 RNN을 같은 구조 상에서 비교해보면, 둘 다 결국 "주어진 토큰들 사이의 관계 정보를 본다"고 할 수 있는데:
  - **RNN**: 정보가 O → O → O → O 처럼, 한 방향으로 순서대로만 흐르는 구조
  - **트랜스포머**: 모든 위치의 정보가 서로 **다 연결**되어 있는 구조. 다만 어텐션을 통해, 그 연결의 **강도(가중치)를 상황에 맞게 동적으로 조절**하며 연결됨

**레이어를 쌓았을 때 나타나는 흥미로운 현상**

트랜스포머의 여러 레이어를 관찰해보면, 레이어마다 서로 다른 "성격"의 어텐션 패턴이 나타나는 경향이 있음:
- 어떤 레이어에서는, 단어들 간의 실제 관계와 무관하게 **인접한 단어끼리만** 어텐션하는 경향 → 자연스럽게 **RNN처럼** 동작
- 어떤 레이어에서는, **주변 단어들**에 대해 (관계와 무관하게) 어텐션하는 경향 → **CNN처럼** 동작
- 어떤 레이어에서는, 모든 단어에 대해 **동일하게(균등하게)** 어텐션하는 경향 → **MLP처럼** 동작

> 이런 현상 때문에, 트랜스포머는 일종의 **"뉴럴 아키텍처 서치(Neural Architecture Search)"**처럼 동작한다고 볼 수 있음 — 예전에는 "이 문제엔 CNN을 쓸까, RNN을 쓸까, MLP를 쓸까"를 사람이 직접 선택해야 했다면, 이제는 **트랜스포머가 어텐션을 통해, 그때그때 필요한 최적의 아키텍처(연결 방식)를 스스로(동적으로) 학습**한다고 볼 수 있다는 것. 즉 각 레이어에서 어떤 정보를 어텐션하느냐에 따라, 그 레이어가 CNN이 됐다가 RNN이 됐다가 하는 식으로 **동적으로 학습**된다.

## 3. 사전학습 기반 언어모델

- **사전학습(Pre-training)**: 대용량의 데이터로부터 먼저 **선행 학습**을 진행
- 이후 두 번째 단계로, 번역·요약 등 **특정 태스크(레이블)를 학습**시켜, 그 태스크에 맞는 분류기(레이블 classifier) 등으로 사용할 수 있음 — 이 두 번째 단계를 **파인튜닝(Fine-tuning)**이라고 부름

**어떤 구조를 쓸지 — 인코더냐, 디코더냐**

### 3-1. 인코더 모델 (BERT류)

- **인코더**는 (양방향으로) **모든 맥락이 주어져 있을 때** 사용하기 적합
- **마스크드 언어모델(Masked Language Model, MLM)**을 사용: 입력 단어의 일부를 [MASK] 토큰으로 치환하고, 이 마스크 자리에 원래 어떤 단어가 있었는지 맞히는 훈련을 진행 → **양방향(bidirectional) 문맥을 모두 활용**할 수 있음

**BERT의 학습 방법**

- 입력 토큰의 **15%를 무작위로 선택**해서 마스킹 등을 적용
- 다양한 문맥 표현을 학습시켜서, **강건한(robust) 모델**을 학습할 수 있도록 함

**MLM 손실(loss) 계산 방법**

- 마스크된 각 위치에서, 모델은 **전체 단어 사전(vocabulary) 크기만큼의 확률 분포**를 출력함 (Softmax를 전체 vocab에 대해 적용)
- 이 확률 분포와, 그 자리에 실제로 있었던 정답 단어(원-핫 벡터) 사이의 **교차 엔트로피(cross-entropy) 손실**을 계산
- 즉 "이 마스크 자리에 어떤 단어가 있었을지, vocab 전체를 대상으로 확률을 매겨보고, 정답 단어에 더 높은 확률을 주도록" 학습하는 것 — (분류 문제의 교차 엔트로피 손실과 원리가 동일하며, 다만 클래스(범주) 수가 "단어 사전 크기"만큼 매우 크다는 점이 다름)

**NSP (Next Sentence Prediction)**

- 두 개의 문장을 주고, 그 사이에 [SEP]이라는 특수 토큰을 넣음
- 어떤 샘플은 두 문장이 실제로 연속된 문장 쌍이고, 어떤 샘플은 연속되지 않는(무작위로 짝지어진) 문장 쌍
- 모델은 이 둘을 구분해서, **IsNext / NotNext**를 예측하도록 학습됨

**BERT의 다운스트림 태스크 예시 — 개체명 인식 (NER)**

- 예: "John Smith lives in New York" 문장에서
  - John → B-PER (사람 이름의 첫 단어)
  - Smith → I-PER (사람 이름에 속하는 나머지 단어)
  - lives → O (개체명이 아닌 단어)
  - In → O
  - New → B-LOC (장소 이름의 첫 단어)
  - York → I-LOC (장소 이름에 속하는 나머지 단어)

> 별도로 복잡한 아키텍처를 설계할 필요 없이, BERT 위에 태스크별 출력층만 얹어도 일반적으로 좋은 성능이 나옴

### 3-2. 인코더-디코더 모델 (T5류)

**T5의 학습 방법 — Span Corruption**

- 인코더-디코더 구조에서는, **인코더가 입력 문장을 모두 보고**, 그 정보를 바탕으로 **디코더가 출력을 생성**함
- 학습을 위해 **Span Corruption**이라는 과정을 수행:
  1. 입력 문장에서 **연속된 토큰(구간, span)**을 무작위로 선택해서 제거
  2. 제거된 부분을, 특수 placeholder 토큰(예: `<X>`, `<Y>`)으로 치환
  3. 디코더는 이 placeholder에 해당하는 **원래의 span(제거되었던 내용)을 복원**하도록 학습
- 이를 통해, 언어 모델링(다음 단어 예측)과 비슷한 방식으로 훈련을 수행할 수 있음
- 마치 게임(빈칸 채우기 퍼즐)을 풀듯이 문제를 학습시키는 방식이라고 볼 수 있음

**파인튜닝 — 프리픽스(Prefix)로 태스크 구분**

- 파인튜닝 시 풀고자 하는 문제(번역, 요약 등)가 다양한데, 이 문제들을 구분하기 위해 입력 앞에 **문제를 구분하는 프리픽스(prefix text)를 붙여서**, 지금 어떤 태스크를 훈련하는지 구분함
- 출력은 각 프리픽스에 맞는 형태로 생성됨

### 3-3. 디코더 모델 (GPT류)

- **전형적인 언어 모델 구조** — 문장 생성에 유용
- 디코더만으로도, 인코더 없이 (모델을) 구현할 수 있음
- 생성 태스크뿐 아니라, **분류(classification) 태스크에도 활용 가능**

**파인튜닝 시 활용 방법**

| 태스크 유형 | 방법 |
|--------------|------|
| **생성(Generation) 태스크** | 사전학습 때와 동일하게, **다음 단어 예측(Next Token Prediction)** 방식으로 파인튜닝. 대화나 요약처럼 **출력이 시퀀스인 태스크**에 자연스럽게 적합 |
| **분류(Classification) 태스크** | 마지막 히든 스테이트 위에 새로운 **선형층(linear layer)**을 연결해서 classifier로 사용. 이 linear layer는 처음부터 새로 학습해야 함 |

**GPT 시리즈의 발전**

- **GPT-1**: (기본적으로) 분류기(classifier)로서의 성격이 강했음
- **GPT-3**: 맥락(in-context)을 가지고 어떤 텍스트 문제를 풀어야 하는지 스스로 파악할 수 있는 능력을 보여줌

### 3-4. 러닝 vs 트레이닝, 그리고 인컨텍스트 러닝

- **러닝(Learning)** = 패턴 인식 (넓은 의미)
- **트레이닝(Training)** = 가중치(weight)를 실제로 학습(업데이트)시키는 과정

**인컨텍스트 러닝(In-Context Learning)**

- 가중치(파라미터)를 업데이트(트레이닝)하지 않고도, **입력(프롬프트)에 예시나 맥락을 함께 제공**하는 것만으로, 모델이 중간 생성 과정을 통해 추론하며 문제를 더 정밀하게 풀어낼 수 있는 능력

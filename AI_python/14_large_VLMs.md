## 1. 파운데이션 모델이란?

### AI 모델이란 무엇인가

**가장 단순한 관점**: 함수 또는 프로그램

**조금 더 상세한 관점**
- 입력과 출력을 연결하는 함수
- **데이터로부터 그 형태(파라미터)가 결정되는** 함수
- 학습 때 보지 못했던 데이터에 대해서도 **작동이 요구되는** 함수
- 뉴럴넷: 입력 → 뉴럴넷 → 출력

> `[개인 메모 · 시험범위 아님]` 이건 필기자 본인의 관점과 같음: 입력도 알고 출력도 아는데, 함수 자체는 (형태는 알아도) 쓸 수 없거나, 함수 자체가 엄청난 초월함수들의 합성으로 이루어져 있어서 함수 자체를 명시적으로 알 수 없는 것

### 이상적인 AI 모델

- 만약 AI 모델이 이 세상에 발생 가능한 **모든 데이터와, 각 데이터에 대한 설명을 전부 기억**하고 있다면?
  - 내가 얻고 싶은 답은 이미 DB에 있을 수도 있음 — **검색 엔진**과 유사한 개념 (검색 포탈, 최근접 이웃 탐색 알고리즘)
  - 그러나 **데이터 확보·저장·탐색은 비용이 매우 크고 현실적이지 않음**

**학습이란?**
- AI 모델에 데이터를 **"패턴화"하여 압축**하는 것
- 이 과정에서 비슷함과 다름을 파악하게 되고, 패턴을 익히면서 **새로운 데이터에 대한 일반화 능력**이 생김

### 파운데이션 모델의 정의

- **대규모 데이터로 사전학습**한 후, **다양한 문제(작업)에 범용적으로 빠르게 적용**할 수 있는 기반(foundation) AI 모델
- "파운데이션 모델"이라는 용어는 **마케팅/트렌드 용어**에 가까움 — 기술적으로 엄밀한 용어라고 보기는 어려움

**파운데이션 모델의 구성**: 거대 모델 + 대규모 데이터 학습 기반 (많은 지식과 경험)

**특징**

1. **대규모 사전학습 트랜스포머 모델 + 대규모 데이터 학습**
   - 태스크에 상관없이 비슷한 패턴들이 활용됨
   - 주로 **비지도학습**으로 훈련된 모델들도 많이 등장

2. **적응성 높은 미세조정 성능** (높은 태스크 적응 성능)
   - 하나의 믿고 쓸 수 있는 모델을, 다양한 목적에 적응시킬 수 있음

3. **범용성** — 다양한 작업, 한정되지 않는 출력을 지원
   - 예시: 물체 판별 — 기존 모델은 구조상 출력이 (예: 20여 개의) 정해진 물체 종류로 한정됨. 파운데이션 모델은 만 개 이상의 물체 종류를 구분하거나, **자연어 기반의 한정되지 않은 대상**에 대한 인식이 가능

### 파운데이션 모델에 의한 AI 모델 개발의 변화

- **과거**: 매번 모델을 태스크별로 새로 학습
- **지금**: 이미 잘 학습된 모델을 **얼마나 잘 활용하는가**가 핵심

**현실적 제약**
- 파운데이션 모델 하나를 확보하려면 **대규모 리소스**(데이터, 전력, 계산력)가 필요 — "턴키로 한 번에 수십억씩" 투입되기도 함

### 다운스트림 태스크 적응(Adaptation) 방법

- 프롬프트 엔지니어링, 튜닝, 전이학습, 적응학습(파인튜닝) 등

**전체 흐름**: 대규모 데이터 → **사전학습(Pre-training)**(다양한 데이터에서 폭넓은 기본 지식 습득) → **제로샷 / 퓨샷 / 파인튜닝** 등으로 적응

> "학습"이 붙었다고 다 같은 학습이 아님:
> - **제로샷(Zero-shot)**: 모델이 (사전학습을 통해) 이미 가진 배경지식을 그대로 활용
> - **퓨샷(Few-shot)**: 예시를 몇 개만 보여주고 그 자리에서 적용

## 2. AGI를 향해 — 시각 언어 모델의 등장

- AI는 **사람의 지능과의 유사점·차이점 분석**을 통해 발전해옴
- 지능에는 **지각(perception) 능력**과 **인지(cognition) 능력**이 모두 필요하다고 여겨짐

**타임라인**
- **2022년 11월 이전**: 각 분야별로, 지능의 매우 부분적인 능력만을 개별적으로 모델링하려는 시도
- **2022년 11월(ChatGPT 등장) 이후**: 대규모 언어모델(LLM)이 높은 사고·추론 성능을 보여주기 시작 — 다양한 인지 능력 벤치마크에서 **인간 수준에 근접**

**하지만 한계**: 사고와 언어 능력만으로는 **현실 세계를 이해하기 어려움**

> "LLM에게 눈을 달아볼까?" → **시각 언어 모델(Vision-Language Model, VLM)**의 등장

**GPT-4의 시각 언어 모델 활용 예시**
- 스케치를 그대로 HTML 코드로 변환 (Sketch-to-HTML)
- 클로드 기반 컴퓨터 사용(Computer Use) 기능 시연 — AI 에이전트가 스스로 수많은 컴퓨터 프로그램을 활용해 태스크를 해결

**에이전트가 화면과 상호작용하는 방식의 과제**
- 에이전트와 기존 응용 프로그램을 인터페이스하기 위한 **표준이 없음**
- MCP를 활용하고 싶어도, 레거시 프로그램들은 대응이 안 됨
- 그래서 **호환성 높고 손쉬운 인터페이스 방법**으로, **이미지 캡처(화면을 그냥 이미지로 찍어서 보는) 방식**이 선호되어 옴

## 3. CLIP (2021, OpenAI)

**"눈으로 뭘 쓸까?"** → CLIP

- **언어와 이미지의 유사도**를 학습하는 모델
- **이미지 인코더**와 **텍스트 인코더**로 구성됨
- **이미지 인코더만 떼어내서 LLM에 붙이는 방식**으로 활용됨
  - 이 이미지 인코더는, (LLM이 이해할 수 있는) **언어 공간에 대응되는 벡터**를 출력해줌
  - **비전 언어 모델의 "눈"**으로 사용됨

**CLIP의 강점**
- **학습되지 않은 입력 데이터에 대해서도 좋은 성능**을 발휘 (제로샷 전이)
- 자연어를 이용해서, **한 번도 본 적 없는 카테고리**도 텍스트 설명만으로 출력을 정의할 수 있음 (언어 인터페이스)

### 대조 학습 기반 언어-이미지 사전학습 (Contrastive Language-Image Pre-training)

- 인터넷 데이터를 통한 지도학습을 통해, **자연어 기반의 시각 개념을 학습**
  - (다만 "지도학습"이라는 표현이 조금 애매함 — 사람이 직접 라벨링한 것은 아님)
- **인터넷에서 수집된 약 4억 개의 이미지-텍스트 쌍**을 사용
  - HTML의 **alt 태그**를 기반으로 이미지 캡션을 수집
  - 당연히 **데이터 정제**도 진행함 — 중복 이미지, 낮은 해상도/품질의 이미지, 짧은 텍스트 등을 걸러냄

### CLIP의 구조

- **텍스트 인코더**: 트랜스포머
- **이미지 인코더**: ViT-B 또는 ResNet-50

**트랜스포머의 인코더-온리(Encoder-only) 사용**
- 원래 트랜스포머는 인코더-디코더 구조이지만, CLIP은 **벡터(피처)를 만드는 기능만 필요**했기 때문에 **인코더만 사용**함
- 토큰 단위 입력, 입력된 토큰 간의 관계성에 집중하는 어텐션
- 길이 L의 입력 토큰은, d차원 특징 벡터의 배열 형태로 입력됨

**이미지 인코더 — ViT (Vision Transformer)**
- **패치 단위의 임베딩** 사용
- ViT를 최소한의 수정만으로 적용한 모델
- 이미지를 16×16(×3채널) 크기로 나눠서, 각 패치를 1차원으로 **플래튼**
- 트랜스포머 인코더가 그 패치들을 처리
- **MLP 헤드**를 통해 분류 작업을 수행 (헤드를 수정하면 다른 작업으로도 전이학습 활용 가능)
- CLIP에서는, 이 ViT가 **CLIP만의 학습법(대조학습)**으로 학습됨

### 대조 학습 (Contrastive Learning)

**목표**
- 이미지(앵커)를, **대응하는(짝이 맞는) 텍스트와는 가깝게**
- **일치하지 않는 여러 텍스트와는 멀게**
- 즉, 의미에 따른 **거리 감각**을 학습하도록 유도

**이미지 인코더와 텍스트 인코더를 어떻게 정렬(align)하는가?**

두 인코더가 각각 이미지와 텍스트를 벡터로 변환하면, 그 벡터들을 **같은 벡터 공간(임베딩 공간)**에 놓고 비교한다. 학습 과정에서, 짝이 맞는 (이미지, 텍스트) 쌍의 벡터는 서로 **가까워지도록(코사인 유사도가 커지도록)**, 짝이 맞지 않는 쌍은 **멀어지도록(코사인 유사도가 작아지도록)** 두 인코더의 가중치를 동시에 역전파로 조금씩 업데이트해나간다. 이 과정을 수백만 개의 (이미지, 텍스트) 쌍에 대해 반복하면, 결국 "의미가 비슷한 이미지와 텍스트는 벡터 공간에서 가까운 위치에 놓이도록" 두 인코더가 서로 맞춰(정렬되어)간다 — 이게 "정렬(align)"의 의미다. 두 인코더 자체가 하나로 합쳐지는 게 아니라, **각자 다른 모달리티(이미지/텍스트)를 처리하면서도, 결과로 나오는 벡터의 "좌표계"를 공유하도록** 함께 학습되는 것이다.

### CLIP 손실함수 (수식)

- **sᵢⱼ**: i번째 이미지와 j번째 텍스트 임베딩 간의 **코사인 유사도**
- 핵심 직관: 두 벡터가 비슷한 방향을 보고 있을수록, 코사인 유사도 값이 큼

```
L_CLIP = (1/2) × [
   −(1/N) Σᵢ log( e^(sᵢᵢ/τ) / Σⱼ e^(sᵢⱼ/τ) )     ← Image→Text Loss
   −(1/N) Σᵢ log( e^(sᵢᵢ/τ) / Σⱼ e^(sⱼᵢ/τ) )     ← Text→Image Loss
]
```

- 각 항의 분자·분모에 **Softmax**가 적용됨 (τ는 temperature)
- 정답 쌍(i번째 이미지와 i번째 텍스트, 즉 sᵢᵢ)의 유사도가 상대적으로 높아지도록, 두 방향(이미지→텍스트, 텍스트→이미지) 모두에서 학습

**Softmax 복습**
- 숫자들이 들어오고 Softmax를 지나면, 모든 요소의 합이 1이 되는 확률 벡터가 나옴
- **temperature(τ)** 값에 따라, 가장 높은 값에 확률이 몰리는 정도(τ가 낮을 때)나, 넓게 퍼지는 정도(τ가 높을 때)를 조절할 수 있음

### 제로샷 이미지 인식기로서의 CLIP

**절차**
1. 텍스트로 원하는 **물체 카테고리 리스트**를 준비
2. 그 텍스트 카테고리 리스트를 **텍스트 임베딩으로 변환**해서 벡터 DB로 준비
3. **쿼리 이미지**와 비교해서, 가장 점수가 높은 카테고리를 반환

> **검색 시스템과의 유사성**: 실제로 검색 시스템과 매우 비슷하게 동작함 (쿼리를 벡터로 바꾸고, 가장 가까운 후보를 찾는 방식)

**카테고리 이외에도 어떤 것이 가능할까? / 카테고리가 정말 많을 때는?** → (다음 절의 SigLIP 등으로 이어짐)

## 4. SigLIP — Sigmoid 기반 손실함수

- SigLIP은 **Softmax 대신 Sigmoid 기반 손실함수**를 사용

**CLIP(Softmax 방식)의 문제**
- Softmax는, **이미 충분히 거리가 먼 음성(negative) 데이터 쌍**들에 대해서도, 계속 거리를 더 벌리기 위한 학습이 진행됨
- 그 결과, 가까운 거리의 **양성(positive) 페어에 집중하지 못하고**, 이미 먼 음성 페어를 더 벌리는 데 학습 에너지를 쓰게 됨

**SigLIP의 해결책**
- CLIP과 달리, **일치하지 않는 음성 데이터에는 제한된 영향만 받도록** 손실함수 디자인을 고침

**SigLIP 손실함수 (수식)**

```
L_SigLIP = −(1/N²) Σᵢ Σⱼ log( 1 / (1 + e^(−zᵢⱼ(sᵢⱼ·τ + b))) )
```

- sᵢⱼ: i번째 이미지와 j번째 텍스트 임베딩 간의 코사인 유사도 (CLIP과 동일)
- **Sigmoid 함수**를 사용 — 각 (이미지, 텍스트) 쌍을 **독립적인 이진 분류 문제**(맞는 쌍인가 아닌가)로 취급

**Sigmoid 함수의 역할**
- 음성 페어·양성 페어가 **어느 정도 멀거나 가까워지면**, 그 이상은 크게 벌점을 매기지 않음 (Softmax처럼 전체를 서로 비교하며 계속 밀어내지 않음)

### 멀티모달 정합(Alignment) 응용

- 서로 다른 두 가지(혹은 그 이상)의 **모달리티 간에 공통된 임베딩 벡터 공간을 구성**하는 것
- 예: "사자의 울음소리"(오디오), "사자"(텍스트), "사자 사진"(이미지)이 **같은 벡터 공간을 공유**하도록 학습
- 이미지, 비디오, 텍스트, 오디오, 뎁스(depth), 열화상, IMU 등 다양한 **모달리티 공간을 공유**하도록 학습하는 연구들이 있음

> 최근에는 VLM을 그냥 단독으로 쓰기보다, **여러 구조를 잘 조합해서 각각의 장점을 살리는** 방향으로 발전하고 있음

## 5. 멀티모달 정합의 두 가지 방법

크로스모달(cross-modal) 변환을 만드는 방법은 크게 두 가지:

| 방법 | 설명 |
|------|------|
| **① 변환(Translating)** | 모달리티 A → (신경망을 통과) → 모달리티 B 로 **직접 흘러가도록** 만드는 방식 |
| **② 정렬(Matching)** | 모달리티 A와 모달리티 B를 **각각 별도의 인코더**에 입력해서, 두 인코더의 출력이 **같은(정렬된) 피처 공간**에 놓이도록 학습하는 방식 |

- CLIP은 ②(정렬/Matching) 방식의 대표적인 예

---

## 6. [심화] CLIP 응용 — 멀티모달 정합을 손실함수로 활용

**질문**: 크로스모달이 피처 공간에서 정렬(align)된다면, 그 연관성을 **거꾸로 활용**할 수 있지 않을까?

### 정합(Matching)을 통한 크로스모달 변환

- **CLIP loss**를 (모델 학습이 아니라) **최적화 목적함수**로 직접 사용하는 예시
- 이 경우, "단일 데이터에 대해서만 학습하는 것 = 최적화"가 됨 (모델 전체를 학습시키는 게 아니라, 하나의 결과물 자체를 최적화)

### Text-to-X (예: Text-to-3D) 자세히 풀어서 설명

**등장하는 요소**
- **텍스트 인코더**: 문구(예: "정면을 향해 걷고 있는 앨런 튜링", "춤추고 있는 프레디 머큐리")를 넣으면, CLIP의 텍스트 인코더가 이를 벡터(T₁)로 변환
- **미분 가능한(differentiable) 이미지/3D 구성**: 학습 가능한 파라미터로 설정된 이미지(또는 3D 오브젝트) 표현
  - 예를 들어 3D라면, "미분 가능한 3D-to-2D 렌더링"을 사용 — 3D 모델을 2D 이미지로 투영(렌더링)하는 과정 자체를 미분 가능하게 설계해서, 역전파가 3D 파라미터까지 흘러갈 수 있게 만든 것

**전체 절차**
1. 원하는 결과물을 설명하는 **텍스트**를 CLIP의 텍스트 인코더에 통과시켜 텍스트 임베딩(T₁)을 얻음
2. **학습 가능한 파라미터**로 설정된 이미지(혹은 3D 오브젝트)를 준비 (처음엔 무작위 노이즈나 초기값)
3. 이 이미지(혹은 3D를 렌더링한 2D 이미지)를 CLIP의 이미지 인코더에 통과시켜 이미지 임베딩(I₁)을 얻음
4. **텍스트-이미지 간의 정렬 정도(코사인 유사도)를 측정** — 이게 손실함수(loss)로 사용됨
5. 이 유사도(정렬 점수)를 **최대화하는 방향으로**, 역전파(backpropagation)를 통해 **이미지/3D 파라미터 자체를 직접 업데이트**함
6. 이 과정을 반복하면, 결국 **텍스트 설명과 CLIP 임베딩 공간에서 가장 잘 정렬되는 이미지(또는 3D 오브젝트)가 점점 만들어짐**

**핵심 포인트**
- CLIP의 이미지·텍스트 인코더 자체는 **이미 학습이 끝난 상태로 고정(freeze)**되어 있음
- 역전파는 CLIP 모델의 가중치를 바꾸는 게 아니라, **이미지(또는 3D 오브젝트)를 나타내는 파라미터 자체**를 바꾸는 데 사용됨
- 즉 CLIP을 "감정사(평가자)"로 고정해두고, "이 그림/3D가 텍스트 설명과 얼마나 잘 맞는지 CLIP에게 점수를 매기게 한 뒤, 그 점수가 높아지도록 그림/3D 자체를 계속 고쳐나가는" 방식
- 이런 방식으로 텍스트만 주고 **3D 오브젝트를 뽑아내는 것(Text-to-3D)**도 가능해짐 (예: CLIP-Actor, StyleCLIP 등의 연구)

## 7. LLaVA (Large Language and Vision Assistant)

- **멀티모달 언어 모델** — 텍스트와 이미지를 결합한 대화형 AI
- **사전학습된 텍스트 디코더** + **사전학습된 이미지 인코더**를 사용

**구조**
- 이미지 인코더와 언어모델 사이에, **선형(Linear) 신경망 한 칸**만 두고, **그 부분만 학습**
- (이미지 인코더의) 각 피처맵을, (언어모델이 이해할 수 있는 공간으로) **정렬**

### 학습 절차

1. **사전학습(Pre-training)**: 잘 학습된 **언어모델**과 **비전 인코더**를 각각 가져와서, 그 사이에 **풀(Projection layer)을 붙여서 연결**
   - 입력 형태: **(이미지 / 언어 명령어 / 언어 응답)** 트리플렛(triplet) 쌍

2. **파인튜닝(Fine-tuning)**
   - 언어모델도 함께 파인튜닝
   - **FP16으로 양자화**해서, 메모리 사용량을 최적화해서 학습

**학습 데이터 — COCO 데이터셋**
- 이미지, 이미지 설명, 물체 좌표를 라벨 데이터로 제공
- COCO 데이터셋의 이미지·라벨 데이터를 가지고, **ChatGPT를 이용해 자동으로 역질의(질문)를 생성**
- 질의 타입: **대화(conversation), 자세한 설명(detailed description), 복잡한 추론(complex reasoning)**

> `[개인 메모 · 시험범위 아님]` 이 과정(ChatGPT로 COCO 라벨을 활용해 질의-응답 데이터를 자동 생성하는 것)은 어느 정도 **증류(distillation)**라고 볼 수도 있을 것 같음
>
> **참고**: 이 직관은 상당히 타당하다. 일반적인 지식 증류(knowledge distillation)는 "선생님 모델의 예측(로짓/확률)을 학생 모델이 모방하도록 학습"하는 것이었다면, 여기서는 조금 다른 형태다 — ChatGPT(선생님 역할)가 COCO의 (이미지 설명, 물체 좌표) 같은 **구조화된 정답 정보를 바탕으로, 사람처럼 자연스러운 질문·답변 데이터를 새로 "생성"**해내고, 그렇게 만들어진 데이터로 LLaVA(학생 모델)를 학습시키는 방식이다. 즉 "선생님의 확률 분포를 직접 모방"하는 고전적 증류와는 다르지만, **"더 크고 강력한 모델(ChatGPT)의 능력을 빌려서, 더 작은 모델을 학습시키기 위한 데이터를 만든다"**는 핵심 정신은 증류와 매우 닮아 있다 — 이런 방식은 최근 "데이터 증류" 혹은 "합성 데이터(synthetic data) 생성"이라고도 불린다.

### LLaVA 모델의 특징

- **효율적인 메모리 사용**: 적은 자원으로 큰 모델을 효과적으로 학습
- **다중 모달 학습**: 텍스트와 시각 데이터를 결합

## 8. Qwen-VL 시리즈

- **알리바바(Alibaba)에서 개발한 대형 모델**

### Qwen-VL

- 여러 개의 이미지 입력, 번역, 텍스트 읽기, 위치 찾기, 인식, 이해 능력을 갖춤
- 성능 지표가 매우 우수함

**학습 파이프라인 (3단계)**

| 단계 | 내용 | 데이터 |
|------|------|--------|
| **Stage 1: Pretraining** | QwenLM(언어모델)은 고정(freeze), ViT + CrossAttn 학습. **저화질**로 빠르게 학습 | Image-Text Pairs |
| **Stage 2: Multi-task Pretraining** | QwenLM도 학습에 참여, ViT + CrossAttn도 학습. **고화질**로 다시 학습 | Multi-task and Interleaved VL Data |
| **Stage 3: Supervised Finetuning** | QwenLM과 CrossAttn 학습, **ViT는 고정(freeze)** | Chat Interleaved VL Data |

> 즉 **저화질로 빠르게 기초를 다진 뒤, 고화질로 다시 정교하게 학습**하는 전략

### Qwen2-VL

- **다국어 텍스트**, **이미지 내 텍스트 이해** 지원
- **임의의 이미지 해상도**를 처리 가능
- 에이전트 응용 기능 강화: 코드/수식 추론, 비디오 분석, 라이브 챗 기능 등

**포지셔널 인코딩 — Rotary Position Embedding (RoPE)**
- 기존 포지셔널 인코딩(PE): 토큰 임베딩에 **+PE를 더하는** 방식
- **로터리 포지션 임베딩(RoPE)**: 액티베이션 피처의 Query/Key에다가, **위치 인덱스에 맞춰 회전(rotation)**을 적용하며 임베딩
- **멀티모달 RoPE**: 2D(이미지), 3D(비디오) 등의 **시간/높이/너비 인덱스 정보**까지 함께 인코딩할 수 있음 (기존 RoPE는 1D 전용)

**추가 강점**
- 강력한 문서 파싱(document parsing) 기능
- 정밀한 객체 그라운딩(object grounding, 이미지 내 위치 정확히 짚기)

### Qwen2.5-Omni

- **"옴니(Omni)"** = 모든/전부/전체 (라틴어 어원)
- **읽고, 보고, 쓰고, 듣고, 말하는** — 멀티모달 전 분야를 아우름
- 구조: **"띵커(Thinker)"**가 생각하고, **"토커(Talker)"**가 말할 것을 생각하는 방식으로 역할이 나뉨

### Qwen3

- 코딩을 해서 차트를 만들 수 있음
- **3D 물체 인식**도 가능

## 9. VLM(비전-언어 모델)의 성능을 높이는 트릭

- 최신 모델들도 여전히 (화면 속) **버튼을 잘 못 찾는** 등의 한계가 있음

### Set of Mark

- **세그멘테이션 파운데이션 모델**을 활용해서, VLM(멀티모달 언어모델)들의 **부족한 시각 능력을 보완**하여 성능을 비약적으로 향상시키는 기법
- **컴퓨터 조작(작동) 에이전트 모델**에서, 기본적인 **비주얼 프롬프팅(visual prompting)** 기법으로 매우 유용하게 활용됨

**예시 — 의료 파운데이션 모델**
- 비전-언어 모델에게 이미지 상의 특정 부위에 **어노테이션(주석)을 지시**할 때, "빨간색 화살표나 원으로 표시해라"라고 지시하는 방식

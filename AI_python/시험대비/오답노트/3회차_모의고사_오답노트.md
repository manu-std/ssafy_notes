## 2. 틀린 문제 심층 분석

### ❌ 18번 — 코사인 유사도 계산 (② → 정답 ①)

**문제**: A = [3, 4], B = [4, 3]의 코사인 유사도

```
A·B  = 3×4 + 4×3 = 12 + 12 = 24
|A|  = √(3² + 4²) = √25 = 5
|B|  = √(4² + 3²) = √25 = 5
cos  = 24 / (5 × 5) = 24 / 25 = 0.96      ← 정답 ①
```

**내가 고른 ② 0.80이 왜 오답인가**
분모를 한 번만 나눴을 때 나오는 값이다. `24 / 30` 같은 식으로 **크기 정규화를 한쪽만 적용**하면 0.8이 나온다.
코사인 유사도의 분모는 **두 벡터의 노름을 곱한 값(|A| × |B|)** 이지, 둘 중 하나거나 둘의 합이 아니다.

**틀린 원인 진단**
- 3-4-5 직각삼각형이 눈에 익어서 `|A| = 5`까지는 즉시 나왔는데, **분모를 5로만 나눴을 가능성**이 크다. (24/5 = 4.8 → 감각적으로 0.8로 착지)
- 계산 문항 8개 중 유일한 실점이 여기라는 건, 공식을 모르는 게 아니라 **손이 미끄러진 것**이다.

**절대 안 틀리는 루틴 — 3단 분해**
```
1) 내적       → 성분끼리 곱해서 더한다
2) 노름 두 개 → 각각 √(제곱합)
3) 나눗셈     → 내적 ÷ (노름1 × 노름2)      ← 곱하기, 반드시 두 개 다
```

**같이 챙길 것 — 코사인 유사도의 성질**

| 성질 | 내용 |
|---|---|
| 범위 | −1 ~ 1 (임베딩이 비음수면 0 ~ 1) |
| 무엇을 보나 | **크기가 아니라 방향** |
| 그래서 | [3,4] 와 [6,8] 의 유사도는 **정확히 1** (스칼라배는 방향이 같음) |
| = 1 인 경우 | 두 벡터가 **완전히 같은 방향**일 때만 |
| = 0 인 경우 | **직교(orthogonal)** — 원-핫 벡터들이 서로 이렇다 (14번과 연결) |

> 🔗 **14번(원-핫 한계)과 한 세트**: 원-핫 벡터끼리는 겹치는 성분이 없어 내적이 0 → 코사인 유사도가 **항상 0** → 그래서 의미적 유사도를 못 잰다. 18번은 그 반대쪽(밀집 임베딩이면 유사도가 잡힌다)을 묻는 문제였다.

### ❌ 30번 — RNN 기울기 소실 (② → 정답 ①)

**정답 ①**: 기울기 소실이 일어나면 **장기 의존성은 못 배우고 단기 문맥만 포착**하게 된다.
→ 이것이 기울기 소실의 **결과**이고, 바로 이 문제 때문에 1997년 LSTM이 등장했다.

**내가 고른 ② "그래디언트 클리핑을 적용하면 기울기 소실을 해결할 수 있다"가 왜 오답인가**

⭐ **여기가 이 문제의 핵심 함정이다. 폭발과 소실은 대칭이 아니다.**

| | 기울기 **폭발**(Exploding) | 기울기 **소실**(Vanishing) |
|---|---|---|
| 언제 | 반복 곱해지는 W의 **특이값 > 1** | 반복 곱해지는 W의 **특이값 < 1** |
| 증상 | 손실이 NaN, 학습 발산 | 손실은 줄지만 장기 문맥을 못 배움 |
| 해결책 | **그래디언트 클리핑** ✅ | **구조 변경(LSTM/GRU, 잔차 연결)** |
| 클리핑이 듣나 | 듣는다 | **전혀 안 듣는다** ❌ |

**왜 클리핑이 소실에 무력한가**
클리핑은 "기울기 노름이 임계값을 넘으면 **잘라서 줄이는**" 연산이다. 즉 **너무 큰 것을 눌러주는 장치**다.
기울기 소실은 값이 이미 0에 수렴한 상태인데, 클리핑은 **0을 키워주는 기능이 없다.** 방향이 반대다.

**같이 나온 나머지 오답도 정리**
- ③ "특이값이 1보다 크면 소실" → **반대다.** 1보다 크면 **폭발**, 작으면 **소실**.
  - 직관: 0.9를 100번 곱하면 0에 수렴(소실), 1.1을 100번 곱하면 발산(폭발).
- ④ "LSTM이 소실에 강한 이유는 게이트에 시그모이드를 쓰기 때문" → ⭐ **최고난도 함정.**
  - LSTM이 강한 **진짜 이유는 셀 스테이트 업데이트의 `+`(덧셈) 연산**이다.
  - `C_t = f_t ⊙ C_{t-1} + i_t ⊙ C̃_t` — 덧셈 경로가 있으면 역전파에서 기울기가 **곱셈으로 깎이지 않고 그대로 흘러간다.**
  - 이것은 **ResNet의 잔차 연결(skip connection)과 정확히 같은 원리**다.
  - 오히려 시그모이드는 그 자체로 **포화(saturation) 때문에 기울기 소실을 일으키는 쪽**이다. 게이트에 시그모이드를 쓰는 건 "0~1 비율로 얼마나 통과시킬지"를 표현하기 위함이지, 소실을 막으려는 게 아니다.

**LSTM 구조 — 표로 굳히기**

| 상태 | 기호 | 역할 |
|---|---|---|
| **셀 스테이트** | C_t | **장기(long-term)** 기억 — "컨베이어 벨트", 거의 그대로 다음 시점으로 흐름 |
| **히든 스테이트** | h_t | **단기(short-term)** 기억 — 그 시점의 출력이자 현재 상태 요약 |

> ⚠️ **31번에서 이걸 물었고 맞혔다** — "셀=단기, 히든=장기"는 뒤집힌 오답 선지다. **셀이 장기다.**

| 게이트 | 역할 | 활성화 |
|---|---|---|
| **포겟(Forget)** | 이전 셀 스테이트에서 **무엇을 버릴지** | 시그모이드 |
| **인풋(Input)** | 새 정보를 **얼마나 쓸지** | 시그모이드 |
| **아웃풋(Output)** | 셀 스테이트 중 **얼마나 내보낼지** | 시그모이드 |

세 게이트 **모두 시그모이드**(0~1 비율을 의미하므로). 게이트 값은 **입력에 따라 매 시점 새로 계산**되며, 학습이 끝나도 상수로 고정되지 않는다.

### ❌ 37번 — VLM 학습 절차 / LLaVA (① → 정답 ③)

**정답 ③**: LLaVA는 **사전학습 단계에서 이미지 인코더와 언어모델 사이의 선형층(Projection layer)만 학습**한다.

**내가 고른 ① "LLaVA는 학습 전 과정에서 언어모델을 끝까지 고정한다"가 왜 오답인가**

⚠️ **해설에 "실제로 틀렸던 지점"이라고 표시된 문항이다. 즉 반복해서 틀리는 지점이다.**

핵심은 **"단계에 따라 다르다"** 이다. **"끝까지"** 라는 단어가 오답 트리거였다.

**LLaVA 2단계 학습 절차**

| 단계 | 학습되는 것 | 고정되는 것 |
|---|---|---|
| **1. 사전학습(Pre-training)** | **선형층(Projection) 한 칸만** | 이미지 인코더, 언어모델 |
| **2. 파인튜닝(Fine-tuning)** | **언어모델도 함께 학습** (FP16 양자화로 메모리 최적화) | — |

- 구조: 사전학습된 **이미지 인코더** + **선형층 1칸** + 사전학습된 **텍스트 디코더**
- 선형층의 역할: 이미지 피처맵을 **언어모델이 이해하는 공간으로 정렬(align)**
- 학습 데이터: **COCO** (이미지 / 설명 / 물체 좌표) → **ChatGPT로 역질의를 자동 생성**
  - 질의 타입 3종: **대화(conversation) · 자세한 설명(detailed description) · 복잡한 추론(complex reasoning)**
  - 입력 형태: **(이미지 / 언어 명령어 / 언어 응답) 트리플렛**

**Qwen-VL 3-Stage — 순서를 반드시 외울 것 (선지 ②의 함정)**

| 단계 | 학습 | 고정 | 해상도 |
|---|---|---|---|
| **Stage 1: Pretraining** | ViT + CrossAttn | **QwenLM 고정** | **저화질** |
| **Stage 2: Multi-task** | QwenLM + ViT + CrossAttn | — | **고화질** |
| **Stage 3: SFT** | QwenLM + CrossAttn | **ViT 고정** | — |

> ⭐ **저화질 → 고화질** 순서다. 싸게 빠르게 정렬을 먼저 잡고, 그다음 비싼 고화질로 올린다.
> 선지 ②는 이 순서를 **뒤집어 놓은** 것이었다.

**CLIP — 선지 ④의 함정**
- CLIP은 **이미지 인코더와 텍스트 인코더가 따로** 존재한다. **하나로 합쳐지지 않는다.**
- 대조 학습으로 **출력 공간(임베딩 공간)만 공유**한다 — 짝이 맞는 쌍은 가깝게, 안 맞는 쌍은 멀게.
- 이것이 **정렬(Matching) 방식**의 핵심이며, "두 인코더가 따로"라는 점이 **바이 인코더 구조**와 그대로 연결된다. (→ 40번)
- 구성: 텍스트 인코더 = 트랜스포머(**인코더-온리**), 이미지 인코더 = **ViT-B 또는 ResNet-50**
- 데이터: 인터넷 **약 4억 개** 이미지-텍스트 쌍(HTML **alt 태그** 기반)
- 강점: **제로샷 전이** — 본 적 없는 카테고리도 텍스트 설명만으로 정의 가능

> 🔗 **"누가 학습되고 누가 얼어있나"가 VLM 파트의 단골 출제 포인트다.** 모델 이름 + 단계 + freeze 대상을 3종 세트로 묶어서 외울 것.

### ❌ 44번 — Tool Learning / 툴포머 (② → 정답 ①)

**정답 ①**: 툴포머는 API 호출 후보를 **실제로 실행해보고, 이후 토큰 예측 손실이 줄어든 호출만** 학습 데이터로 남긴다.

**내가 고른 ② "사람이 도구를 사용한 로그를 모아 그대로 모방"이 왜 오답인가**

그건 툴포머가 아니라 **모방 학습(Behavior Cloning)** 이다. 두 방식을 섞었다.

**툴 러닝 2가지 방식 — 반드시 구분**

| | ① 모방 학습 (Behavior Cloning) | ② 툴포머 (Toolformer, Meta, 2023) |
|---|---|---|
| 데이터 출처 | **사람의 도구 사용 로그** | **모델이 스스로 생성** (자기지도) |
| 학습 | 사람 행동을 흉내 (SFT와 유사) | 스스로 만든 데이터로 **지도학습** |
| 한 줄 | 사람을 따라한다 | **자기가 만들고 자기가 거른다** |

**툴포머 데이터 생성 파이프라인 — 3단계**

```
LM Dataset
   ↓
1. Sample API Calls   — 문장 중간중간에 "여기서 API 부르면 어떨까?" 후보를 여러 개 생성
   ↓
2. Execute API Calls  — 후보를 실제로 실행해서 결과를 받아옴        ← 진짜로 실행한다
   ↓
3. Filter API Calls   — 그 결과가 뒤 문장 예측 손실을 낮췄는지 확인해 도움 된 것만 남김
   ↓
LM Dataset with API Calls
```

**슬라이드 예시 (외워두면 그대로 나옴)**
- 원문: `"Pittsburgh is also known as the Steel City."`
- 후보 1: "What other name is Pittsburgh known by?" → **Steel City** → 손실 감소 → ✅ **채택**
- 후보 2: "Which country is Pittsburgh in?" → **United States** → 손실 안 줄어듦 → ❌ **탈락**
- 결과: `"Pittsburgh is also known as [QA(...)→Steel City] the Steel City."`

> 판단 기준 한 줄: **"이 API 호출이 실제로 다음 내용을 맞히는 데 도움이 되었는가"**

**툴포머가 다루는 API**: Question Answering, Wikipedia Search, **Calculator**, **Calendar**, Machine Translation

**ToolLLM — 선지 ③의 함정**
- 문제의식: 써야 할 도구가 너무 많아 **모델에 내재된 도구만으로는 부족**하다.
- 접근: ① API 대량 수집 → ② 명령문(instruction) 생성 → ③ 정답 어노테이션·필터링 → ④ 사용 시 **API 목록에서 검색해 탑-k를 가져옴** → ⑤ 인스트럭션 + **인자(argument) 설명**을 함께 전달
- 한 줄: **외워두는 게 아니라 필요할 때 검색해서 쓴다.** (선지 ③은 정반대로 서술)

**도구(Tool)의 정의 — 선지 ④의 함정**
- 도구 = **언어모델 외부에서 실행되는 프로그램, 혹은 연결되는 함수 인터페이스**
- 가장 야심찬 형태는 **현실 세계에 영향을 미치는 도구**
- ⭐ 극단적으로는 **사람에게 자연어로 지시하고, 사람이 시행해서 결과를 반환받는 것도 도구에 포함**된다.
  → "반드시 실행 가능한 프로그램이어야 한다"는 서술은 **틀렸다.**

> 🔗 **59번(맞힘)과 연결**: 도구 사용의 핵심은 **언제 자연어로 답하고 언제 도구를 호출할지 판단하는 감각**을 익히는 것. 24번의 에이전트 프레임워크(액추에이터 = **툴셋**, 도구 집행 담당)와도 이어진다.

### ❌ 47번 — RLHF 학습 파이프라인 (④ → 정답 ②)

**정답 ②**: **RLVR**은 정답 여부를 자동으로 검증할 수 있는 문제에서 **보상을 직접 주는** 방식이다.

**내가 고른 ④ "사전학습 → 강화학습 → 지시 학습"이 왜 오답인가**

**순서가 뒤집혔다. 지시 학습(SFT)이 강화학습보다 먼저다.**

```
Step 0  사전학습 (Pre-training)          — 언어와 지식
Step 1  지시 학습 (SFT, Instruction)     — 지시를 알아듣게 만들기      ← 강화학습보다 먼저!
Step 2  보상 모델(Reward Model) 학습     — 사람 선호 라벨을 모방하는 채점기
Step 3  강화학습 (PPO)                   — 보상 모델 점수가 높아지도록 정책 갱신
```

**왜 SFT가 먼저여야 하는가 (논리로 기억)**
사전학습 모델은 **질문에 대답을 하지 않는다.** 프롬프트를 "지시"로 인식하지 못하고 비슷한 문장을 이어 쓸 뿐이다.
→ 그런 모델에게 강화학습을 시키면 **채점할 만한 응답 자체가 안 나온다.**
→ 그래서 먼저 SFT로 "지시를 알아듣게" 만든 뒤, 그 위에서 선호를 학습시킨다.
→ 또한 **보상 모델의 학습 분포 = 지시학습 직후 모델의 출력 분포**이므로, SFT가 선행되지 않으면 보상 모델의 기준점 자체가 성립하지 않는다.

**RLVR (Reinforcement Learning with Verifiable Rewards)**
- 수학 문제처럼 **답이 분명한 문제는 정답 여부로 직접 보상**을 준다.
- 사람 선호를 물어볼 필요가 없어 **보상 신호가 훨씬 깨끗하다.**
- ⭐ **보상 해킹에서 자유롭다**: 보상 해킹은 보상 모델이 **사람 흉내를 낸 근사치**라서 생기는데, RLVR은 채점자가 **컴파일러·수식 검증기**라 속일 구멍이 없다.

**보상 신호의 출처로 4가지를 한 표에 (이 표를 통째로 외울 것)**

| 방식 | 채점자 | 신호의 성격 |
|---|---|---|
| **SFT** | 정답 문장 | "이걸 그대로 써라" |
| **RLHF/PPO** | 사람 라벨로 학습한 **보상 모델** | "이 답 몇 점" (근사치 → **해킹 가능**) |
| **DPO** | **정책 자신** (암묵적 보상) | "이게 저것보다 낫다" (**데이터에 갇힘**) |
| **RLVR** | **자동 검증기** | "맞다 / 틀리다" (깨끗하지만 **정답 있는 문제만**) |

**DPO — 선지 ①·③의 함정 (매우 중요)**
- ① "DPO는 보상 모델을 더 정교하게 학습시킨다" → **정반대다. DPO는 보상 모델을 아예 없앤다.**
  보상 모델도, 강화학습도 없이 **선호 데이터로 정책을 직접 학습**한다.
- ③ "DPO는 항상 PPO보다 우수하다" → **이론적으로 등가일 뿐, 실전은 다르다.**
  - 등가성은 **"보상 모델도 최적, RL도 최적으로 풀었을 때"만** 성립한다.
  - **목적함수가 같다는 뜻이지, 최적화 경로까지 같다는 뜻이 아니다.**

| | DPO | RLHF/PPO |
|---|---|---|
| 띄우는 모델 | **2개** (정책, ref) | **4개** (정책, ref, 보상, 가치) |
| 생성(rollout) | **없음** (오프라인, off-policy) | **매 스텝마다** |
| 학습 루프 | 지도학습과 동일한 모양 | RL 루프 |
| 신호의 최신성 | **옛날 데이터 고정** | 지금 모델 기준 |
| 성격 | 간단·싸다·안정적 | 복잡·비싸지만 **상한선 높음** |

> DPO가 새는 지점: DPO 손실은 **좋은 답과 나쁜 답의 "차이"만** 본다. 그래서 차이만 벌어지면 **좋은 답 확률까지 같이 떨어져도** 손실은 줄어든다. PPO는 매번 새 답을 생성해 채점받으므로 이렇게 새지 않는다.
> 절충안: **iterative DPO** (여러 라운드 반복하며 매번 최신 모델로 데이터를 새로 생성)

> 🔗 **11번·12번(맞힘)과 한 세트**: PPO는 보상에서 **레퍼런스 모델과의 KL × β를 뺀 값**을 최대화한다. KL 페널티의 목적은 정책이 SFT 모델에서 너무 멀어져 **보상 모델의 학습 분포 밖으로 나가는 것**을 막는 것.

### ✅ 26번 — 프롬프트 디자인 / 튜닝 / 모델 튜닝 (정답 ①)

**3가지 방식 비교 — 이 표 하나면 끝난다**

| 방식 | 파운데이션 모델 | 무엇을 학습하나 | 특징 |
|---|---|---|---|
| **프롬프트 디자인** | **고정** | **아무것도 안 함** (사람이 프롬프트 작성) | 높은 효율 / 성능은 **제한적** |
| **프롬프트 튜닝** (2021) | **고정** | **가상 토큰(virtual token) 임베딩만** | 효율·성능의 **중간** |
| **모델 튜닝(미세조정)** | **추가 학습** | 전체 또는 일부 파라미터 | **높은 성능** |

**프롬프트 튜닝 상세**
- **학습 가능한 프롬프트**로서 **가상 토큰**을 입력에 추가하고, 역전파로 **그 임베딩만** 학습. 본체는 freeze.
- 장점: 사람이 직접 디자인 안 해도 됨 / 본체 고정이라 **지식 손실 없음** / 적은 비용
- ⭐ 단점: 학습된 가상 토큰 임베딩은 **사람이 읽고 해석할 수 없다.** (선지 ②의 함정 — 정확히 반대로 서술)
- 응용: 학습된 토큰을 **형용사처럼** 사용 ("OO 스타일로 그려줘"의 OO 자리)

**⭐ 인컨텍스트 러닝(ICL) — 가장 잘 나오는 함정 (선지 ④)**
> **인컨텍스트 러닝은 가중치를 전혀 갱신하지 않는다.**
> 이름에 "러닝(Learning)"이 붙어 있지만 **트레이닝이 아니다.** 프롬프트 안의 예시만으로 추론 시점에 수행하는 것이다.

이 함정은 여러 문항에 반복 등장한다:
- 26번 ④ "ICL은 예시로 가중치를 미세하게 갱신하는 학습이다" → ❌
- 32번 ③ "ICL은 가중치를 갱신하므로 파인튜닝의 일종이다" → ❌
- 48번 ② "예시를 제공하므로 모델 가중치가 함께 갱신된다" → ❌

→ **"프롬프트에 무언가를 넣는다" = 가중치 갱신 없음.** 이 등식을 반사적으로 떠올릴 것.

**LoRA도 함께**
- 프롬프트 튜닝과 모델 튜닝 사이의 PEFT 기법 — 레이어마다 **작은 저랭크 행렬 모듈을 삽입**해 **일부만 학습**
- 32번 ④의 함정: "LoRA는 **원본 가중치와** 저랭크 행렬을 **함께** 학습한다" → ❌ **원본은 고정, 저랭크 행렬만 학습**한다.

### ✅ 40번 — RAG (정답 ③) · 요청하신 **덴스 vs 스파스 리트리버** 완전 정리

**RAG 한 줄 요약**: **파라메트릭 지식**(모델 가중치 내부) + **논파라메트릭 지식**(외부 데이터 스토어)의 **결합**

#### 🔥 스파스 vs 덴스 리트리버

| | **스파스 리트리버 (Sparse)** | **덴스 리트리버 (Dense)** |
|---|---|---|
| 기반 | **어휘적(lexical) 유사도** — 정확한 **용어 일치** | **의미적(semantic) 유사도** — **임베딩** |
| 대표 기법 | **TF-IDF**, **BM25** | 임베딩 + 코사인 유사도 |
| 작동 원리 | 흔한 단어("is", "a")엔 벌점, **희소한데 이 문서에 유독 많은 단어**에 고득점 | 고차원 공간에 의미를 표현, 쿼리를 같은 공간에 뿌려 **코사인 유사도 최대** 문장을 찾음 |
| **성능** | 상대적으로 낮음 | ⭐ **덴스가 더 좋다** |
| **투명성(설명가능성)** | ⭐ **높다** — 왜 이 문서가 나왔는지 설명 가능 | ⭐ **낮다** — 왜 나왔는지 설명 어려움 |
| 속도·비용 | **효율적**, 단순 | **높은 연산 비용, 느림** |
| 약점 | **제한된 의미 이해** — `"bad guy" ≠ "villain"` (같은 뜻인데 단어가 다르면 매칭 실패) | 비용, 낮은 투명성 |

> ⭐⭐ **가장 중요한 한 줄 — 여기서 반드시 뒤집혀 나온다**
> **성능은 덴스가 좋고, 투명성은 스파스가 좋다.**
> 40번 선지 ②는 "덴스가 스파스보다 투명성이 높다"로 **정확히 뒤집어** 놓았다.
>
> 직관으로 잡기: 스파스는 **"'villain'이라는 단어가 이 문서에 5번 나와서"** 라고 근거를 댈 수 있다.
> 덴스는 **"768차원 벡터의 코사인이 0.87이라서"** — 사람이 납득할 근거가 아니다. 그래서 투명성이 낮다.

#### 🔥 바이 인코더 vs 크로스 인코더 (= 덴스 리트리버의 두 구현 방식)

| | **바이 인코더 (Bi-Encoder)** | **크로스 인코더 (Cross-Encoder)** |
|---|---|---|
| 방식 | **두 문장을 따로 인코딩**한 뒤 유사도 계산 | 쿼리와 문서를 **구분자로 엮어 함께 인코딩** |
| 속도 | **매우 빠름** | **매우 느림** |
| 정확도 | 상대적으로 **낮음** | **세밀한 상호작용**을 포착해 **높음** |

> 📌 **바이 인코더가 빠른 진짜 이유 = 캐싱**
> 문서 쪽 임베딩을 **미리 계산해 저장**해둘 수 있다. 쿼리만 새로 연산하면 되고, **코사인 유사도 계산 자체는 매우 저렴**하다.
> 크로스 인코더는 **쿼리-문서 쌍마다 매번 통째로 인코딩**해야 해서 캐싱이 불가능하다.

> ⭐ **실무 패턴(넷플릭스 다단계 구조)**: 앞 단계는 **빠른 바이 인코더로 넓게 거르고**, 후보가 50개 정도로 줄면 **마지막 랭킹만 느리고 정밀한 크로스 인코더**로 처리한다.
> → 40번 선지 ④ "바이 인코더는 크로스 인코더보다 느리지만 더 정확하다"는 **완전히 뒤집힌 서술**이다.

#### RAG가 언제 효과적인가 — 선지 ①의 함정

> **RAG는 "항상" 성능을 올리지 않는다.**
> - ✅ **희소한 정보**(모델이 잘 모르는 것)에는 큰 효과
> - ❌ **모델이 이미 잘 아는 정보**에는 **오히려 부정적**일 수 있다
>
> **이유**: 탑-k로 가져올 때 정답 1개와 함께 **노이즈 9개도 전부 컨텍스트에 들어간다.** 어텐션 구조상 노이즈 토큰의 가중치가 **정확히 0이 되지 않으므로** 컨텍스트 오염이 발생한다.

## 4. 약점 패턴 진단

55/60이면 개념 자체는 대부분 잡혀 있다. 틀린 5개를 성격별로 묶으면 **약점은 3가지 패턴**뿐이다.

### 패턴 A — "대칭처럼 보이지만 대칭이 아닌 쌍"을 뒤집어 고름 (30번, 40번류)

가장 위험한 패턴이다. A와 B가 짝처럼 등장하면 **어느 쪽이 어느 속성인지**를 반드시 방향까지 저장할 것.

| 쌍 | 절대 뒤집히면 안 되는 방향 |
|---|---|
| 기울기 폭발 / 소실 | **클리핑은 폭발만** 해결. 소실엔 무력 |
| 특이값 > 1 / < 1 | **> 1 폭발**, **< 1 소실** |
| 셀 스테이트 / 히든 스테이트 | **셀 = 장기**, 히든 = 단기 |
| 스파스 / 덴스 리트리버 | **성능은 덴스**, **투명성은 스파스** |
| 바이 / 크로스 인코더 | **바이 = 빠름·부정확**, **크로스 = 느림·정확** |
| Precision / Recall | **Precision 분모 = 예측(P)**, **Recall 분모 = 실제(R)** |
| 회귀 / 분류 | 숫자 → 회귀 → **MSE(0~∞)**, 범주 → 분류 → **CE** |
| MSE / R² | **MSE = 원래 단위 오차 크기**, **R² = 0~1 무단위** |
| 학습률 스케줄링 | **크게 시작 → 작게** (반대 아님) |
| 파라미터 / 연산량 분포 | **파라미터는 FC**, **연산량(FLOPs)은 Conv**, **활성화 메모리는 초기 고해상도 레이어** |
| CBOW / Skip-gram | **CBOW = 주변→중심, 더 빠름** / Skip-gram = 중심→주변, 희귀어에 강함 |

**대응법**: 선지를 읽을 때 **두 항의 이름을 서로 바꿔 읽어보고**, 그래도 말이 되면 그게 함정 선지다.

### 패턴 B — 순서·단계를 뒤집거나 "끝까지 / 항상"에 걸림 (37번, 47번)

| 반드시 순서로 외울 것 | 순서 |
|---|---|
| **RLHF 파이프라인** | 사전학습 → **지시학습(SFT)** → 보상 모델 → 강화학습 |

| **LLaVA** | 사전학습(**선형층만**) → 파인튜닝(**LM도 함께**) |
| **툴포머** | Sample → **Execute** → Filter(**손실 감소분만**) |
| **ToolLLM** | 수집 → 명령문 생성 → 필터링 → **검색해서 탑-k** |

⚠️ **"끝까지 / 항상 / 반드시 / 전혀 / 유일하다"가 들어간 선지는 일단 의심하라.**

## 5. 시험 직전 30초 체크리스트

**틀린 5개의 정답만 다시**
1. **코사인 = 내적 ÷ (노름 × 노름)** — 노름은 **두 개 다** 곱한다
2. **클리핑은 폭발 전용.** 소실은 구조(LSTM의 **`+`** = ResNet 잔차와 같은 원리)로 푼다
3. **LLaVA 사전학습 = 선형층만.** 파인튜닝 단계에선 **LM도 학습**한다 ("끝까지 고정" ❌)
4. **툴포머 = 실행해보고 손실 줄어든 호출만 남긴다** (사람 로그 모방은 **Behavior Cloning**)
5. **RLHF 순서: 사전학습 → SFT → 보상 모델 → 강화학습.** **RLVR = 자동 검증기가 채점**

**요청 개념 3줄 요약**
6. **ICL·프롬프트 디자인은 가중치 갱신이 전혀 없다** (프롬프트 튜닝은 **가상 토큰만**, 해석 불가)
7. **Sora = 월드 모델 / Veo3 = 소리까지 동시 생성 / LDM = Stable Diffusion(2022), 효율·품질 동시 개선**
8. **성능은 덴스, 투명성은 스파스. 바이는 빠르고(캐싱), 크로스는 정확하다.**

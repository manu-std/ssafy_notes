## 1. GPT-3의 사전학습

GPT-3 175B는 굉장한 모델인데, 그럼 학습 방법이 크게 달라졌을까? **아니다.**

| 항목 | 내용 |
|---|---|
| **학습 방법** | 다음 토큰 예측 (Next Token Prediction) — 이전과 동일 |
| **학습 데이터** | 3,000억 토큰, 약 4TB 텍스트 데이터 — 인터넷 + 양질의 텍스트 북 |
| **학습 비용** | 약 150억 원으로 추산 |

### 모델 사이즈 계보 — 한 번에 만들지 않았다

GPT-3는 처음부터 175B로 만든 게 아니라, 작은 모델부터 순차적으로 키워가며 만들었다.

| 모델 이름 | n_params | n_layers | d_model | n_heads | d_head |
|---|---|---|---|---|---|
| GPT-3 Small | 125M | 12 | 768 | 12 | 64 |
| GPT-3 Medium | 350M | 24 | 1024 | 16 | 64 |
| GPT-3 Large | 760M | 24 | 1536 | 16 | 96 |
| GPT-3 XL | 1.3B | 24 | 2048 | 24 | 128 |
| GPT-3 2.7B | 2.7B | 32 | 2560 | 32 | 80 |
| GPT-3 6.7B | 6.7B | 32 | 4096 | 32 | 128 |
| GPT-3 13B | 13.0B | 40 | 5140 | 40 | 128 |
| **GPT-3 175B ("GPT-3")** | **175.0B** | **96** | **12288** | **96** | **128** |

- **n_params**: 전체 파라미터 수 / **n_layers**: 트랜스포머 층 수 / **d_model**: 임베딩(은닉 상태) 차원 / **n_heads**: 어텐션 헤드 개수 / **d_head**: 각 헤드가 담당하는 차원

### 데이터 구성 — 양과 질의 균형

- 인터넷 데이터는 **양을 채우기엔 좋지만 양질은 아님** → 그래서 양질의 텍스트 북(도서 데이터 등)도 함께 활용
- **커먼크롤(Common Crawl)**: 4,100억 토큰 규모로 전체 학습 데이터 구성의 약 60%를 차지
- 핵심 전략: **저품질 데이터는 학습 빈도수 자체를 적게 가져가고, 고품질 데이터는 양에 비해 더 많이 반복 학습**시킴

## 2. 다음 토큰 예측만으로는 부족했다

GPT-3의 학습 자체는 성공적이었지만, **"다음 토큰 예측만 잘하면 우리가 원하는 좋은 모델이 나오는가?"**에 대한 답은 아니었다. 다음 토큰 예측만으로는 그런 모델을 만들 수 없었고, GPT-3 연구자들 스스로 다음 문제들을 리포트했다.

- 사람의 지시에 대해 **올바르지 않은 응답**을 생성
- **유해한 응답**을 생성
- **사람의 말을 제대로 알아듣지 못하는** 문제

**예시**: "6살 아이에게 달 착륙에 대해 설명해줘"라는 프롬프트를 주면, GPT-3는 설명 대신 질문을 다시 읊는 식의 응답을 내놓곤 했다.

- 추가로 **제일브레이킹(jailbreaking, 탈옥)**에도 취약했음

> 왜 이런 일이 벌어질까? 사전학습 모델은 "인터넷에서 이 문장 다음에 나올 법한 말"을 이어 붙이도록 학습됐을 뿐, "사용자가 원하는 것을 해줘라"라고 배운 적이 없기 때문이다.

## 3. 정렬 학습(Alignment)과 사후 학습(Post-training)

**정렬 학습 / 사후 학습(Post-training)**: 사전 학습으로 거대 언어모델을 만들어둔 뒤, 그 **출력이 사용자의 의도와 가치를 반영하도록** 만드는 과정

| 종류 | 무엇을 가르치는가 |
|---|---|
| **지시 학습 (Instruction Tuning)** | 주어진 지시에 대해 **어떤 응답이 생성되어야 하는지** |
| **선호 학습 (Preference Learning)** | 상대적으로 **어떤 응답이 더 선호되어야 하는지** |

- 앞서 나온 달 착륙 문제도 정렬 학습을 거치면 "사람이 달에 가는 것은…" 식으로 아이 눈높이에 맞춰 실제로 설명하게 됨
- 유저가 탈옥을 시도하는 경우에도 적절히 대응할 수 있게 됨

> 📌 **사후 학습이 반드시 정렬 학습으로만 이루어지는 것은 아니다.** 강화학습 기반으로 **추론 능력을 특화**시키는 사후 학습도 많이 한다 — 모델에게 문제를 풀게 하고, 맞았는지 틀렸는지에 따라 계속 손실을 주는 방식.

## 4. 지시 학습 (Instruction Tuning)

### 기존 BERT 시대의 방식과 무엇이 같고 다른가

지시 학습은 **BERT 모델에서 봤던 지도 추가학습(supervised fine-tuning)과 방식 자체는 동일**하다.

**기존 방식의 문제**

- 감정 분석 모델이 필요하다 → 리뷰와 레이블을 모아서 학습 → 감정 분류 전용 모델 완성
- 번역 모델도 필요하다 → 원문-번역 쌍을 모아서 또 추가학습
- 결국 **n개의 태스크 = n종류의 데이터쌍 수집 + n번의 추가학습 + n개의 모델 저장**

**요즘 아이디어**: 추가학습을 한다는 건 동일하지만, **여러 태스크를 하나의 모델에 동시다발적으로 학습**시키자.

- 문제: **입출력 포맷이 태스크마다 다르다** — 감정 분류 모델은 출력이 이진값(긍정/부정), 번역은 입출력 모두 자연어

### 해결책 — 모든 태스크를 "지시"로 표현하겠다

모든 태스크를 자연어 지시(instruction) 형태로 통일하면, 출력도 모두 자연어로 나오게 된다.

**예시 (감정 분석을 지시로 바꾸기)**

```
지시: 주어진 리뷰 속 유저의 감정이 긍정적이야, 부정적이야?

리뷰: 전체적으로, 두 시간 동안 영화를 보는 것에서 얻은 가치는
      팝콘과 음료의 합계였습니다. 영화는 정말 끔찍했습니다.
```
→ 언어 모델 출력: `"부정적으로 보입니다."`

- **인스트럭션 튜닝의 핵심**: 자연어 태스크를 포맷 템플릿으로 정해서, **지시 + 입력**의 형태로 통일하는 것

### 기존 방식과의 근본적 차이 — 메타 지식 학습

| 구분 | 기존 프레임워크 | 지시 학습 |
|---|---|---|
| 목표 | 태스크 A 해결 | 지시 이해 능력 자체를 획득 |
| 방식 | 태스크 A 데이터를 많이 모아 파인튜닝해야 그제서야 해결 가능 | 수천~수만 개의 다양한 태스크를 지시 형태로 학습 |
| 새 태스크 대응 | 불가 — 또 데이터 모으고 학습해야 함 | 처음 보는 지시도 이해하고 수행 |

- 잘 생각해보면, 이런 방식으로 천 개, 만 개의 태스크를 배웠다고 할 때 **태스크 자체를 외우는 방식으로는 더 이상 감당할 수 없다**
- 그래서 모델은 **"지시를 이해하는 것"** 자체를 배우게 된다 — 즉 **메타 지식(meta knowledge)**을 배우도록 유도되는 것
- 예: 생전 처음 보는 "삼행시를 지어줘"라는 지시를 받아도, "아 삼행시라는 걸 해야 하는구나"를 이해하고, 사전학습 단계에서 봤던 삼행시의 형식에 대한 지식을 꺼내서 수행함

### 하나의 태스크를 지시 데이터로 바꾸는 방법은 무한하다

- 예: **NLI 태스크** — 두 문장을 비교해서 서로 유사한지(함의 관계인지) 판단하는 태스크
- 같은 태스크라도 이를 표현하는 **템플릿은 무한히 만들어질 수 있고, 그 모두가 맞는 데이터**다
- 실제 유저들도 물어보는 형태가 제각각이다
- 따라서 **여러 가지 템플릿을 함께 넣어주면 더 강력한 일반화**를 이룰 수 있다는 것이 핵심 중 하나

## 5. FLAN — 지시 일반화 실험

구글 팀의 **FLAN** 연구에서 다룬 지시 학습의 중요한 이슈: **"지시를 이해하면 풀 수 있을 것"**이라는 가설을 검증하는 것. 즉 **지시를 일반화하는 것**이 중요하다.

### 실험 설계의 고민

- 기존에 흩어져 있던 자연어 태스크 데이터를 모은 다음, **더 큰 분류(카테고리)**로 묶어봤다 — 서로 다른 태스크였던 것들이, 더 큰 분류에서는 같은 태스크로 묶임
- 문제: 어떤 태스크 데이터를 학습에 쓰고 **같은 카테고리의 데이터를 테스트에 쓰면**, 진짜로 "지시 일반화"가 이루어진 건지, 아니면 그냥 같은 카테고리 데이터를 봤기 때문에 잘하는 건지 구분할 수가 없다
- 그래서 FLAN 연구자들은 **카테고리 레벨에서 학습/테스트를 분리**했다

### 결과

실험 결과, **제로샷(예시 없이)으로도 새로운 지시에 대해 올바른 응답을 내놓는 성능이 크게 증가**했다.

---

## 6. 지시 학습에서 관측된 3가지

1. **태스크의 종류를 늘리면 늘릴수록 성능이 좋아진다**
2. **모델 사이즈가 클수록 좋다** — 8B 이전 규모에서는 지시 학습을 하면 오히려 성능이 떨어졌는데, 70B 이상에서는 확연히 좋아졌다
   - 즉 **지시를 이해하고 응답하는 능력 자체도 창발성(Emergence)의 한 사례**
3. **지시를 주는 방법**: 데이터셋 이름을 불러주는 것보다, **자연어 지시로 사람에게 대화하듯 지시하는 것**이 가장 효과적이었다

## 7. 선호 학습 (Preference Learning)

지시 학습을 마치면 지시를 알아듣고 척척 해내는 모델이 만들어진다 — 그럼 이걸로 충분한가? **아니다.** 모델은 **가치 판단**을 할 줄 알아야 한다.

### 지시 학습의 한계

- 지시 학습은 **주어진 입력에 대해 적절한 응답이 딱 하나 있다**고 가정한다
- 태스크의 정답이 하나뿐이라면 자연스럽지만, **개방형(open-ended) 태스크에서는 명백한 한계**가 있다

**예시 — 번역 태스크**

영어 시(詩) 가사 한 구절을 한국어로 번역하라고 하면, 문법적으로 맞고 의미도 통하는 번역이 여러 개 나온다. 강의 슬라이드에서는 같은 영어 원문에 대해 두 가지 한국어 번역 결과를 나란히 제시했는데, 둘 다 "틀린 번역"은 아니지만 어감·리듬·시적 표현의 완성도에서 차이가 나고, 사람은 그중 하나를 분명하게 **더 선호**한다.

> **목표**: 단순히 복수 정답을 허용하는 데 그치는 게 아니라, **더 좋은(선호되는) 응답을 생성하도록** 만들고 싶다.

### 선호 학습이란

- AI가 만든 다양한 응답 중, **사람이 더 선호하는 응답을 생성하도록** 추가 학습하는 것
- **다양한 응답은 모델이 생성**하고, **응답 간의 선호도는 사람이 제공**한다
- 결과적으로 거대 언어모델은 **사람이 좋아할 응답**을 만들게 된다

> 자연스럽게 나오는 질문: "응답 n개를 어떻게 만드나요?" → 이건 **디코딩(decoding)** 단계를 다룰 때(3차시) 자세히 볼 예정. 핵심은, 여러 개의 응답 중에서 **사람의 선호도와 가치관을 따라가는 모델이 된다**는 것.

## 8. RLHF — 챗GPT를 만든 핵심 알고리즘

- 챗GPT의 공식 문서는 공개되어 있지 않지만, 블로그에 힌트가 제공되어 있음
- **RLHF (사람 피드백 기반 강화학습)** — **InstructGPT**에서 사용한 방식
- 챗GPT는 InstructGPT에 새로운 **다이얼로그(대화) 데이터셋**을 추가로 넣은 것으로 간접적으로 추론 가능

### Step 0 — 사전학습

GPT-3를 먼저 만든다.

### Step 1 — 지시 학습

- FLAN과 다르게, **실제 유저로부터 다양한 지시 입력을 수집**
- 해당 입력에 대해 **훈련된 사람 주석자(annotator)**들이 직접 정답 데이터를 생성

### Step 2 — 보상 모델(Reward Model) 학습

"사람을 모방하는 모델"을 만들어서 사람의 선호 데이터를 대신 판단하게 만드는 단계.

1. 지시 학습된 모델이 하나의 입력에 대해 **여러 가지 응답 선택지**를 생성
2. 사람을 고용해서 **어떤 응답이 더 좋았는지 순위를 레이블링** — 예: `d > c > a = b`
3. 그 레이블링을 **모방해주는 모델(보상 모델)**을 학습
   - 학습 목표: "지시와 출력 응답이 주어졌을 때, 이게 얼마나 좋은지 **숫자로 표시하라**" — 예: `100 > 50 > -5 = -5`
   - **사람의 레이블과 모델의 점수가 같은 순서로 정렬(align)되도록** 손실 함수를 설계

### Step 3 — 강화학습 (사람 없이 돌리기)

이제 사람이 매번 개입할 필요가 없다.

1. 지시 학습된 모델이 여러 응답을 생성
2. 보상 모델이 각 응답의 선호도를 점수로 채점
3. 지시 학습된 모델은 **점수가 높은 응답(예: d)을 더 많이 생성하도록** 추가 학습 — 즉 보상 모델이 더 좋아하는 답변을 만드는 방향으로 스스로를 수정

> ⚠️ 사람이 중간에 없이 모델끼리만 자가발전하면 **발산할 수 있으므로**, 체크포인트를 보면서 사람이 중간중간 들여다본다.

> `[개인 메모 · 시험범위 아님]` 정보 이론적으로, 보상 모델(모방 모델)의 학습에 사용된 "사람이 진짜 레이블링한 데이터"를, 지시학습이 완료된 모델의 선호학습에도 사용하는 것이 모델 품질 측면에서 좋은지, 아니면 정보 교차 오염을 막기 위해 해당 데이터는 격리하는 것이 좋은지 답할 것. 개인적으로는 실제 데이터와 증강 데이터의 관점에서 봤을 때, 해당 데이터를 선호학습에도 사용하는 게 더 좋을 것 같긴 함

**답변** `[개인 메모 · 시험범위 아님]`

결론부터 말하면 **직관은 맞다** — 사람이 직접 레이블링한 진짜 선호 데이터는 정책 모델(지시학습된 모델)의 학습에 직접 쓰는 것이 품질 면에서 유리하다. 다만 "격리해야 한다"는 반대편 우려도 완전히 근거 없는 건 아니고, 실제로 InstructGPT는 데이터를 나눠서 쓴다. 두 이야기가 서로 충돌하는 것처럼 보이는데, 사실 **서로 다른 두 가지를 나눠서 말하고 있기 때문**이다. 하나씩 풀어보자.

**① 정보 이론적으로 보면, 보상 모델은 새 정보를 만들어내지 못한다**

사람이 레이블링한 선호 데이터가 가진 정보량을 H라고 하자. 보상 모델은 이 데이터로 학습된 함수이므로, 보상 모델이 담고 있는 "사람 선호에 대한 정보"는 **아무리 많아야 H를 넘을 수 없다**. 데이터 처리 부등식(Data Processing Inequality)이라고 부르는 원리인데, 쉽게 말하면 **원본 데이터를 가공해서 만든 결과물은 원본보다 더 많은 정보를 가질 수 없다**는 뜻이다. 보상 모델이 학습하면서 근사 오차·과적합이 끼기 때문에 실제로는 H보다 적은 정보를 담는다.

따라서 "사람 레이블 데이터를 보상 모델에만 쓰고 격리한다"는 선택은, 정보 관점에서 보면 **원본(H)을 놔두고 그 열화된 복사본만 쓰겠다는 것**에 가깝다. 원본 데이터를 정책에 직접 쓰면 손실 없이 신호를 전달할 수 있는데, 굳이 그럴 이유가 없다. 실제 데이터 vs 증강 데이터로 본 직관이 바로 이 지점을 정확히 짚은 것이다.

**② 그리고 실제로 그렇게 하는 방법이 이미 존재한다 — DPO**

이건 가설이 아니라 이미 표준이 된 방법이다. **DPO(Direct Preference Optimization)**는 보상 모델을 아예 만들지 않고, 사람이 레이블링한 선호쌍 데이터로 **정책 모델을 직접 학습**시킨다. 수학적으로 "보상 모델을 학습한 뒤 그것으로 강화학습하는 과정"이 "선호쌍으로 정책을 직접 최적화하는 것"과 등가임을 보인 것이 DPO의 핵심 기여다. 파이프라인이 단순해지고 학습이 안정적이라, 요즘 개방형 모델 학습에서는 RLHF보다 DPO를 쓰는 경우가 오히려 더 많다. 즉 "그 데이터를 정책 학습에 직접 쓰는 게 낫지 않나"는 질문은, 이미 학계가 그렇다고 답을 내놓은 질문이다.

**③ 그럼 보상 모델은 왜 존재하는가 — 격리해야 한다는 주장의 진짜 근거**

그렇다고 보상 모델이 무의미한 건 아니다. 보상 모델의 가치는 정보량이 아니라 **일반화**에 있다.

- 사람이 레이블링한 데이터는 **유한하고 고정**되어 있다. 반면 강화학습 단계에서 정책 모델은 **매 스텝마다 새로운 응답을 새로 생성**한다 — 사람이 한 번도 본 적 없는 응답들이다.
- 이 새 응답들을 채점하려면 **함수 형태의 채점기**가 필요하고, 그게 보상 모델이다. 고정된 데이터셋만으로는 "지금 막 생성된 이 응답"을 채점할 수 없다.
- 즉 보상 모델은 정보를 늘리려고 있는 게 아니라, **가진 정보를 새로운 입력에 적용할 수 있도록 함수로 바꿔주는 역할**이다.

여기서 **진짜 오염 문제**가 생긴다. 다만 그것은 "같은 데이터를 두 번 쓰는 것" 때문이 아니라, **같은 프롬프트를 두 단계에서 재사용할 때** 생기는 문제다.

- 보상 모델이 학습에 썼던 프롬프트로 강화학습을 돌리면, 정책은 보상 모델이 **잘 맞히는 영역이 아니라 점수를 잘 주는 영역**을 파고들게 된다. 보상 모델의 오차를 악용하는 방향으로 최적화되는 것이다.
- 이걸 **보상 해킹(reward hacking) / 과최적화(over-optimization)** 라고 부른다. 겉으로는 보상 점수가 계속 올라가는데, 실제 사람이 보기엔 응답 품질이 오히려 나빠지는 현상이다.
- 그래서 InstructGPT는 실제로 프롬프트 집합을 **지시학습용 / 보상모델용 / 강화학습용으로 분리**해서 쓴다. 또한 보상 모델의 정확도 자체를 평가하려면 **레이블 데이터 일부를 검증용으로 반드시 홀드아웃**해야 한다.

**④ 정리**

| 질문 | 답 |
|---|---|
| 사람 레이블 데이터를 정책 학습에 직접 써도 되나? | **써도 되고, 쓰는 게 낫다.** 그게 DPO다 |
| 그럼 격리해야 한다는 말은 틀린 건가? | **부분적으로 맞다.** 다만 격리해야 하는 건 "레이블 데이터"가 아니라 **프롬프트 집합**과 **검증용 홀드아웃**이다 |
| 왜 보상 모델을 여전히 만드나? | 사람이 본 적 없는 새 응답을 채점하려면 **함수 형태의 채점기**가 필요하기 때문 |

실무에서는 둘 다 하는 경우가 흔하다 — 사람 선호 데이터로 DPO를 돌려 기본기를 잡고, 별도로 보상 모델을 만들어 강화학습이나 응답 재순위화(rejection sampling)에 쓰는 식이다.

> `[개인 메모 · 시험범위 아님]` 보상 모델도 이 루프에서 자가발전하는지 답할 것

**답변** `[개인 메모 · 시험범위 아님]`

**① 표준 RLHF의 Step 3에서 보상 모델은 얼어 있다(frozen).**

InstructGPT 기준으로, 강화학습 단계에서 업데이트되는 것은 **정책 모델(지시학습된 모델)뿐**이고, 보상 모델의 가중치는 고정된 채로 채점기 역할만 한다. 그러니 "루프 안에서 보상 모델이 자가발전한다"는 그림은 표준 RLHF에는 해당하지 않는다.

**② 그리고 이게 바로 위에서 말한 과최적화가 일어나는 이유다.**

보상 모델은 자기가 학습했던 응답 분포(=지시학습 직후 모델의 출력)에 대해서만 잘 채점할 수 있다. 그런데 강화학습이 진행될수록 정책 모델의 출력 분포는 점점 달라진다. 결국 정책은 **보상 모델의 학습 분포 바깥**으로 나가버리고, 거기서는 보상 모델의 점수가 신뢰할 수 없게 된다.

- 흔한 실패 사례: 답변을 무의미하게 길게 늘이거나, 특정 정중한 표현을 반복하거나, 특정 서식을 남발하는 식으로 **점수만 높고 실질은 없는 응답**을 찾아내는 것
- 이걸 막는 표준적인 장치가 **KL 페널티**다. 정책이 지시학습 직후 모델에서 너무 멀리 벗어나면 벌점을 줘서, 보상 모델이 제대로 채점할 수 있는 범위 안에 머물게 붙잡아둔다. 강의에서 "체크포인트를 보면서 사람이 들여다본다"고 한 것도 같은 문제에 대한 대응이다.

**③ 그럼 보상 모델을 갱신하는 방법은 없나 — 있다. 다만 사람이 다시 들어와야 한다.**

이걸 **반복적(iterative) RLHF**라고 부르고, 아래 10장에서 다룰 **LLaMA 2가 정확히 이 방식**을 썼다.

1. 현재 정책 모델로 응답을 새로 생성한다
2. 그 **새로운 응답들에 대해 사람에게 다시 선호 레이블링**을 받는다
3. 새 데이터로 보상 모델을 다시 학습시킨다
4. 갱신된 보상 모델로 강화학습을 다시 돌린다

LLaMA 2는 이 사이클을 여러 라운드 반복했다. 핵심은, 보상 모델이 최신 정책의 출력 분포를 따라잡게 만들어서 ②의 분포 이탈 문제를 완화하는 것이다. 다만 이건 **자가발전이 아니라 사람이 매 라운드 다시 개입하는 구조**다.

**④ 사람 없이 갱신하는 방식도 있긴 하다 — RLAIF / Constitutional AI**

사람 레이블러 대신 **다른 AI 모델이 선호를 판정**하게 만드는 접근이다. 명시된 원칙(헌법, constitution)을 기준으로 AI가 두 응답 중 어느 쪽이 나은지 판단하고, 그 판단으로 보상 모델을 학습시킨다. 사람 레이블링 비용을 크게 줄일 수 있어서 실제로 쓰이는 방법이다.

다만 이것도 "보상 모델이 루프 안에서 스스로 성장한다"기보다는 **사람의 자리에 다른 모델을 앉힌 것**에 가깝다. 그리고 판정하는 모델 자체의 편향과 한계가 그대로 보상 모델에 전이된다는 위험이 있어서, 완전한 무인 자가발전 루프는 여전히 열린 연구 문제로 남아 있다.

> **한 줄 정리**: 표준 RLHF에서 보상 모델은 고정되어 있고, 그래서 정책이 보상 모델을 속이는 과최적화가 생긴다. 갱신하려면 사람(반복적 RLHF)이나 다른 AI(RLAIF)가 새 레이블을 공급해줘야 한다 — 루프 자체가 저절로 보상 모델을 키워주지는 않는다.

## 9. RLHF의 실제 효과

실제로 효과가 있었을까?

- 단순 프롬프팅이나 지시 학습만 한 경우에 비해, **선호 학습까지 마치면 성능이 확실히 좋아졌다**
- **안전한 응답** 측면에서도, 기존 대비 **유해(toxic) 답변과 할루시네이션이 더 적어졌다**

> `[개인 메모 · 시험범위 아님]` 개인적 의견으로는, 사람이 모델의 가치관만 보는 게 아니라 출력 자체의 질도 함께 평가하기 때문에 이런 결과가 나오는 듯함

**RLHF 프레임워크가 사실상 업계 표준**이 되었음을 보여준 사례.

| 구분 | 공개 범위 |
|---|---|
| **LLaMA 1** | 사전학습된 모델만 공개 |
| **LLaMA 2** | 사전학습 → 이니셜 모델 → 피드백 수집 → 보상 모델 → 파인튜닝까지, **RLHF와 동일한 구조를 거친 LLaMA 2-Chat 모델**을 공개 |

- LLaMA 2는 당시 **대화형 개방형 모델 중 가장 우수한 성능**을 보여줬음

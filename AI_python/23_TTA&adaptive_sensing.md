## 1. 분포 이동(Distribution Shift)이란

### 문제 상황

학습을 시켰는데, **현장 데이터가 학습 데이터와 달라서 잘 안 된다.** 이런 경우가 매우 빈번하다.

- 학습 데이터에서 봤던 세상과 실제 세상이 다르면 **성능 하락**이 일어난다
- 이 다름에 적응하게 만드는 기법이 필요하다 → **TTA (Test-Time Adaptation)**

> 📌 **비유**: 교수님이 말해준 시험 범위를 잘못 알아들은 것. 1~200쪽을 열심히 공부했는데, 실제 시험 범위는 100~300쪽이었던 상황.

### 과적합 vs 분포 이동 — 구분할 것

| 구분 | 무엇이 문제인가 |
|---|---|
| **과적합(Overfitting)** | **같은 도메인** 안에서 학습 데이터를 외워버린 것 |
| **분포 이동(Distribution Shift)** | **도메인 자체의 분포**가 흔들린 것 |

### 예시

- 깔끔한 이미지에서는 새를 다 맞추는데, 현장에 갔더니 새 사진이 흐리다
- 다양한 종류의 노이즈가 있고, 그만큼 정확도가 떨어질 수 있다

### 핵심 질문

> **레이블이 없는 상황에서, 어떤 손실 함수로 도메인 적응을 할 수 있을까?**
>
> 현장에는 레이블이 없으니 비지도(unsupervised)로 배워야 한다. 손실 없이도 데이터 분포에 적응할 수 있을까?

## 2. TTA란 무엇인가

**AI가 실제로 쓰이는 순간, 테스트 데이터의 분포를 파악해 모델을 유연하게 적응시키는 것.**

- 테스트 데이터를 입력받을 때, **모델의 일부를 새 데이터의 통계에 맞게 재조정**해 성능을 유지
- 구체적으로는 **배치 정규화(BN) 계층만 실제 데이터 기반으로 슬쩍 바꿔준다**

> ⚠️ **TTA는 파인튜닝이 아니다.** 모델 전체를 다시 학습시키는 것이 아니라, 최소한의 부분만 건드린다.

## 3. TENT — TTA의 클래식

### 동작 방식

1. 현장 데이터를 조금씩 모은다 — **통계치를 뽑을 수 있을 정도만**
2. **배치 정규화 계층을 타겟팅**해서 모델을 정상 궤도에 올린다

### 왜 BN 계층만 건드리나

- 현장 데이터가 사실 몇 개 없다. 이 상태에서 파라미터 전체를 업데이트하면 **이거야말로 과적합**이 일어난다
- 현장 데이터는 치우쳐 있고 편향되어 있다
- 학습 데이터로 넣어둔 **파라메트릭 지식을 까먹을 위험**이 있다

> **모델을 고정한 상태에서, 최소한의 변화로 적응하겠다는 것.**

### 무엇을 어떻게 업데이트하나

| 대상 | 업데이트 방법 |
|---|---|
| **μ (평균), σ (분산)** | **단순 계산으로 업데이트** — 테스트 데이터 기준으로 재계산 |
| **γ (스케일), β (이동)** — 어파인 파라미터 | **역전파로 미세 조정** |

- μ, σ를 테스트 데이터 기준으로 재계산하면 → **모델이 새로운 데이터 분포에 즉각 적응**

### 손실 함수 — 엔트로피

⚠️ 손실 함수를 계산하고 싶은데 **테스트 데이터에 레이블이 없다.**

> **해결책: 엔트로피 자체를 손실 함수로 설정하자.**
>
> "확신이 있냐 없냐"만 가지고 손실 함수를 만들 수 있다. (다만 **확신이 맞았는지 틀렸는지는 알 수 없으므로** 아주 제한적이다.)

**결과**: 학습을 다시 진행하지 않고도, 테스트 데이터 분포에 맞게 모델을 즉시 최적화

> 📌 **온디바이스 환경에서는 역전파 자체가 안 될 수 있다.** 그럴 때는 아쉬운 대로 **μ와 σ만 업데이트**해서 쓰기도 한다.

- TENT가 클래식이라, 이후 모든 기법들이 **"TENT보다 얼마나 좋은가"**로 평가된다

## 4. SAR — 이상치를 걸러내자

### 무엇을 문제 삼았나

> **테스트 데이터는 정제되어 들어가지 않는다.**

- 학습 데이터셋은 데이터를 다 모아서 눈여겨보며 정제하고, 쳐낼 건 쳐내는 등 궁리할 여지가 있다
- 반면 **테스트 데이터는 전부 현장 데이터**라, 현장에서 무슨 일이 일어날지 알 수 없다

**예시**: 비디오를 찍고 있는데 누군가 장난으로 렌즈를 손으로 막았다 → 사진이 새까맣다. 이런 사진으로 μ를 업데이트하면 안 된다.

> **→ 이상치(outlier)를 필터링하는 기법이 필요하다.**

### SAR의 접근

**최적화를 안정적으로 하고 싶다.** 현장 데이터가 마구 들어오는데, 어떤 걸 배우고 어떤 걸 버릴지 판단해야 한다.

- 데이터에 이상치·노이즈가 많으면 → **그래디언트가 아주 커진다** → 모델을 불안정하게 만든다
- 이상한 데이터를 보고 "못 보던 거네" 하며 배우면 안 된다

**핵심 기법**

| 기법 | 내용 |
|---|---|
| **엔트로피 기반 샘플 선택** | 엔트로피가 **낮은** 샘플만 선택해서 업데이트 — "내가 이렇게까지 모르는 데이터는 노이즈일 거야" |
| **로스 스무딩(평탄화)** | 엔트로피 손실이 너무 요동치지 않도록 평탄화 |

**결과**: TENT보다 안정적이고, 험한 테스트 환경에서도 성능을 유지한다

### 여기까지의 정리

```
γ, β    → 역전파로 업데이트
μ, σ    → 통계 계산으로 업데이트
엔트로피가 너무 크면 → 쳐낸다 (SAR)
```

## 5. 비전언어모델 기반 TTA — TPT

> 💡 재미있는 점: VLM의 철학은 **"다양한 테스트 환경에서 버티도록 데이터를 대량으로 때려넣는다"**인데, **그럼에도 불구하고 VLM에도 TTA가 필요하다.**

### TPT (Test-Time Prompt Tuning) — 일관성 있는 예측을 돕자

VLM은 이미지 인코더와 텍스트 인코더를 정렬시켜, 컨피던스를 바탕으로 "개다, 책이다, 고양이다, 새다"를 판단하는 구조다.

**TPT의 핵심**: **모델은 고정하고, 프롬프트만 테스트 타임 전용으로 바꿔 끼운다.**

**동작 절차**

1. 하나의 테스트 이미지에 대해 **여러 증강(회전, 밝기 변화 등)을 생성**
2. **엔트로피가 가장 낮은 증강 이미지 6개를 선택** (accept / reject)
3. 6개의 **평균 엔트로피를 손실로 설정**
4. 이를 최소화하도록 **텍스트 프롬프트를 업데이트**

```
prompt p ─────────────→ text encoder ──┐
   ↑                                    ├→ 각 증강별 확률분포 p(y|A(X))
   │  (역전파)         image encoder ───┘         ↓
   │                                        confidence selection (✓/✗)
   │                                              ↓
   └──────────── min H(p̃) ←──── average ────── p̃(y|X)
```

> → 이 지점에 대한 필기자 개인 소견은 별도 파일 **`26_appendix_personal_notes.md`**의 **A1** 항목에 있다. (개인 메모이므로 시험 대비 학습 내용에서 제외)

> 📌 **왜 6개인가?** 특별한 이유는 없고, **해보니까 6개가 좋더라**는 것. 하이퍼파라미터를 선택하는 건 과학적이라기보다 **경험적인 부분이 크다.**

## 6. PromptAlign — 통계량 기반 정렬

**학습 데이터와 테스트 데이터를 직접 정렬시키자.**

- 학습 데이터 도메인에서 어떤 **통계량**을 얻을 수 있다면, 이걸로 더 잘할 수 있지 않을까?
- **학습 데이터 통계량**은 내가 이미 가지고 있는 것이고, **테스트 데이터 통계량**은 현장에서 체험하며 계산하는 것
- → **통계적 차이(평균·분산)를 최소화하도록 프롬프트를 업데이트**한다

즉 **통계량이 다른 정도를 손실로 만들고**, 그 손실로 앞에 붙은 프롬프트를 업데이트하는 것.

> `[개인 메모 · 시험범위 아님]` 프롬프트를 업데이트한다는 게 이해가 안 되는데 무슨 의미인지 소상히 설명할 것

> → 이 질문에 대한 상세 답변은 별도 파일 **`26_appendix_personal_notes.md`**의 **A2** 항목에 정리해두었다. (개인 메모이므로 시험 대비 학습 내용에서 제외)

## 7. 적응적 센싱 — 왜 센싱을 이야기하는가

> **AI 모델을 포함한 "시스템"이 성능을 내는 것이지, 모델만 가지고 일하는 게 아니다.**

- 시스템에 모델이 설치되어 돌아갈 것이기 때문에 → **AI 가속기와 양자화** 이야기를 하는 것
- 훈련 데이터가 아니라 현장에서 돌아갈 것이기 때문에 → **TTA** 이야기를 하는 것
- 그런데 **누군가는 입력을 줘야 하지 않나** → 그래서 **센싱** 이야기를 하는 것

> **사실상 종합예술이다.** 다 잘해야 어떤 에러가 어디서 기인한 것인지 진단할 수 있다.

### 학습 목표

- 초거대 AI 패러다임의 한계점과 **인간 인지 체계와의 괴리**를 이해한다
- **적응적 센싱을 통한 분포 이동의 억제** 개념을 이해한다
- 적응적 센싱의 성능 효과와 특징을 이해한다

> 📌 **TTA와 적응적 센싱의 차이 — 중요**
>
> | 접근 | 무엇을 하는가 |
> |---|---|
> | **TTA** | 분포 이동이 **이미 일어난 상태**에서, 거기에 **적응**하는 것 |
> | **적응적 센싱** | 테스트 타임에 도메인이 **이동하지 않도록 억제**하는 것 |

## 8. 초거대 AI의 한계

### 지금까지의 해법 — 규모로 보험 들기

- 스케일링 법칙에 의거해, 파라미터가 무지하게 많은 모델을 만든다
- 시간에 따라 파라미터 수가 엄청나게 올라간다
- **분포 이동의 리스크를 줄이기 위해 규모로 보험을 드는 것** — "뭐가 나올지 모르니까 다 공부하자!"
- 웹에서 방대한 데이터 + 증강으로 드문 경우까지 흉내 낸다
- 파라미터가 엄청난 초거대 모델을 설계해 고성능 컴퓨터로 학습 → **반년도 걸린다**

> **가장 무식하지만 가장 효과적인 해법**: "니가 뭘 좋아할지 몰라서 다 가져왔어"

### 스케일링 법칙의 한계 — 피지컬 AI 시대

**우리는 언어모델의 시대에서 피지컬 AI로 넘어가는 시대에 있다. 지금 프론티어는 로보틱스다.**

- 물리 환경에서는 **다양한 센서를 통해 세상을 인지하고, 계획하고, 행동**한다
- **챗봇 시대, 키보드·마우스로 입력하는 시대는 끝났다**

**피지컬 AI에서 분포 이동은 심화된다**

| 변수 종류 | 예시 |
|---|---|
| 환경 변수 | 조도, 날씨, 재질 |
| 로봇 행동 변수 | 시점, 거리, 모션 블러 |

> ⚠️ **이게 짬뽕되면 경우의 수가 폭발해버린다.**

### 보완책의 필요성

"초거대? 초초거대? 초초초초거대?? 데이터 없어? 데이터 더 모아!" — 300명 인부를 고용해서 손으로 조립하는 걸 모아 데이터로 활용하자는 식으로, **스케일링 법칙을 계속 가져가고자 하는 노력들**이 있다.

> ⚠️ 하지만 **기술적으로 가능하더라도 자본, 개인정보 보호, 환경, 현실 등 다양한 부가적 문제**가 발생한다.

## 9. 발상의 전환 — AI를 위한 안경

### 초거대 AI의 철학과 그 이상함

**초거대 AI의 발상**: "모든 것은 노오력의 문제야. AI는 머리가 좋으니 공부를 많이 시키자."

> 이걸 사람에 비유하면 이렇게 된다:
> **"안경을 못 가져와서 시험을 망쳤어. 다음엔 흐릿한 문제를 더 여러 장 풀자. 그러면 실수로 안경을 두고 와도 잘 볼 거야."**
>
> ← 이게 스케일링 법칙의 발상이다.

**문제 제기: 이게 상식적인가?**

- 사람은 피지컬 영역에서 AI보다 잘하고 있으므로, **인간을 모방하는 것이 합리적인 판단**이다
- 인간의 사고방식은 이렇다: **흐리면 안경을 쓰고, 눈이 부시면 선글라스를 쓴다**

### 적응적 센싱 = AI를 위한 안경

> **모델의 뛰어난 "뇌"에만 의존하지 말고, 안경을 씌워보는 건 어떨까?**

**개념 대응**

| 인간 | AI 시스템 |
|---|---|
| 뇌 | 모델 |
| 감각기관 | 센서 |

- 모델의 입력 데이터는 **모두 센서가 물리 환경을 해석한 결과물**이다
- **공부는 공부대로 열심히 시키고, 안경도 같이 씌워주자** — 모델이 설령 좀 부족하더라도, 좋은 안경을 씌워주면 세상의 어려운 것을 잘 풀 수 있지 않을까?

> 💡 **흥미로운 관점**: 인간의 눈은 **소뇌**로 컨트롤되는데, 우리는 AI 설계를 **대뇌에만** 박고 있는 꼴이다. 뉴런의 70%는 소뇌에 있다.

## 10. ImageNet-ES 데이터셋

적응적 센싱을 연구하려면 **데이터셋이 있어야 한다.**

### 구축 방법 (이미지 분류 태스크)

1. **암실**에 ImageNet 이미지를 스크린에 띄운다
2. **캐논 카메라로 사진을 대량으로 촬영**한다
3. **ISO, 셔터스피드, 조리개** 등 파라미터를 바꿔가며, 조명의 조도도 조절하며 촬영

> 같은 꽃 데이터인데도 이렇게 다양하게 찍힌다 — **이게 분포 이동의 가짓수다.**
>
> **"이걸 다 학습시키라고?"**라는 질문을 하게 되는 지점.

### ImageNet-ES → ImageNet-ES Diverse

- 첫 번째 데이터셋(**ImageNet-ES**)을 찍고 보니 문제가 있었다 — **스크린은 그 자체가 광원**이다. 현실에서는 피사체가 광원인 경우가 잘 없다
- 그래서 두 번째 데이터셋(**ImageNet-ES Diverse**)은 **이미지를 종이에 인쇄해서 촬영**했다

**기존 강건성 데이터셋과의 차이**: 기존 데이터셋은 **디지털 변환**(소프트웨어로 노이즈·블러를 입힌 것)인 반면, 이건 **물리 카메라로 실제 촬영**한 것이다.

> 📌 논문 기준 규모: ImageNet-ES는 64,000장, ImageNet-ES Diverse는 192,000장. Diverse 쪽은 조명 조건이 6가지로 늘었고, 센서 파라미터 27가지 수동 설정 + 오토 익스포저 5장 구성.

### SenseShift6D — 6D 포즈 추정 태스크

- **3차원 위치 + 3차원 각도 = 6차원 포즈**를 추정하는 태스크
- 조명을 바꿔보고, 카메라 파라미터도 바꿔서 촬영했으며, **깊이(depth)도 컨트롤**했다

**결과**: 기존에 잘 된다던 모델들이 **이 데이터셋에서는 망했다.** 이걸 먼저 보여주는 것이 연구의 출발점.

## 11. Lens

**카메라 센서를 잘 조절해서 해결하자는 기법.**

### 동작 절차

```
Scene ─→ Camera Control ─→ p'₁ ─→ 캡처 ─→ VisiT ─→ Q₁ ─┐
                          p'₂ ─→ 캡처 ─→ VisiT ─→ Q₂ ─┤
   Target Neural Network   ...                          ├→ Best image
   M, # of Options K       p'_K ─→ 캡처 ─→ VisiT ─→ Q_K ─┘   for model
        ↓                                              
   CSA (Candidate Selection)                      p̂ = argmax Q(x_s,p)
        ↑
   Available Sensor Options {p₁, ..., p_N}
```

**단계별 정리**

| 단계 | 내용 |
|---|---|
| **① 센서 파라미터 후보 선택 (CSA)** | 옵션이 많아서 현실적으로 모든 파라미터를 테스트할 수 없음 → **무작위 선택, 등간격 선택, 최단시간 선택** 등의 알고리즘 사용 |
| **② 이미지 캡처** | 후보로 선택된 파라미터들로 **이미지를 여러 장 캡처** |
| **③ 비전 테스트 (VisiT)** | 캡처한 이미지들을 모델에 입력하여 추론 → 점수는 모델이 도출한 **컨피던스 스코어** |
| **④ 최적의 파라미터 선택** | **점수가 가장 높은 이미지를 선택**하여 최종 추론 수행 |

> 📌 이 구조를 **아날로그 증강**이라고 부를 수 있다 — 소프트웨어로 이미지를 변형하는 게 아니라, **카메라 파라미터를 바꿔가며 물리적으로 다시 찍는 것**이기 때문이다.

> `[개인 메모 · 시험범위 아님]` 이게 무슨 뜻이지? 현실에서는 하나의 씬에 대해 여러 아날로그 증강을 볼 일이 없잖아 — 논문을 직접 찾아서 확인하고 정리할 것

> → 이 질문에 대한 상세 답변(논문 확인 결과 및 후속 논의)은 별도 파일 **`26_appendix_personal_notes.md`**의 **A3** 항목에 정리해두었다. (개인 메모이므로 시험 대비 학습 내용에서 제외)

## 12. 성능 효과

### 센서 조절만으로 성능 향상

| 비교 | 결과 |
|---|---|
| ResNet-50 (ImageNet-ES) | 오토 익스포저 32.1% → **Lens 78.6%** |
| DINOv2-b (ImageNet-ES) | 오토 익스포저 74.5% → **Lens 90.6%** |
| 전체 모델 평균 | 오토 익스포저 대비 **8.71% ~ 47.58%** 향상 |

> 📌 강의에서 "ResNet-50에서 오토 익스포저 대비 50% 향상"이라고 한 것은 위 ResNet-50 수치(+46.5%p)를 어림한 것이고, 논문이 보고하는 최대 향상폭은 **47.58%**다.

### Lens vs 도메인 일반화 — EfficientNet-B3(Lens) vs OpenCLIP-h(AE)

- OpenCLIP-h는 **초거대 모델**의 일종으로, EfficientNet-B3보다 **50배 많은 모델 파라미터**와 **2,000,000배 많은 학습 데이터**를 가진다
- 그럼에도 **50배 작은 모델 + 적응적 센싱**이 **초거대 모델 + 일반 제어**보다 **4~10% 더 높은 정확도**를 냈다

> **→ 모델만 키우는 게 다가 아니라, 센서도 중요하다. 센서도 1등 시민으로 대우해달라.**

### AI가 더 잘 맞추는 사진은?

| 방식 | 어떤 이미지를 만드나 |
|---|---|
| **오토 익스포저(AE)** | **사람이 좋아하는** 이미지 |
| **Lens** | **AI가 좋아하는** 이미지 |

> **사람과 AI가 좋아하는 이미지가 다른가? → 다르다.**
>
> 기존 오토 익스포저는 애초에 **인간의 지각을 위해 설계**된 것이므로, 모델에게 최적이라는 보장이 전혀 없다. 논문의 네 가지 핵심 발견 중 하나가 바로 "모델 인지에 좋은 이미지는 인간 시각에 최적화된 이미지와 다르다"는 것이다.
